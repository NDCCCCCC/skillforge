# eval/ — SkillForge Go-native trust evaluator

This directory is the home of SkillForge's **Go-native trust evaluator**
(Plan 03-06, D6 reversed). It holds:

- `golden/compliance.jsonl` — the 50-case synthetic golden set (GEVL-05).
- `golden/README.md` — golden set construction methodology.
- `report.json` — the per-run metric report (overwritten each run).
- `calibration.json` — the per-run threshold recommendation (D2-15).
- `NOTICE` — Apache-2.0 attribution for the ported Ragas faithfulness
  prompt.

The Go code lives in `internal/eval/` (the library) and `cmd/eval/`
(the CLI binary). This directory holds ONLY data + docs.

## D6 reversal note (2026-08-12)

The original Plan 03-06 draft imported Python + Ragas as a CLI
sidecar. Scope review reversed that decision: the evaluator is now
**single-language Go**. Only the faithfulness prompt is ported from
Ragas (Apache-2.0, attributed in `NOTICE`); the other 3 metrics use
simple Go-authored yes/no judge prompts. See `.planning/STATE.md` D6
row for the full rationale. The original Python draft is preserved in
git history.

## The Go-only end-to-end run

### Prerequisites

The evaluator reuses the same env vars as `cmd/server` (it constructs
the same embedder + retriever + agent + store):

| Env var | Required | Notes |
|---------|----------|-------|
| `GLM_API_KEY` | yes | Zhipu Coding Plan key (judge + agent). |
| `GLM_BASE_URL` | no | default `https://open.bigmodel.cn/api/coding/paas/v4`. |
| `JUDGE_MODEL` | no | default `glm-5.2` (D3-07 slot — override for Phase 6 cross-eval). |
| `BGE_M3_URL` | yes | BGE-M3 HTTP endpoint (same as cmd/server). |
| `MILVUS_ADDRESS` or `MONGO_URI` | yes | retriever backend (same switch as cmd/server). |
| `SQLITE_DSN` | no | default `skillforge.db` (audit backfill target). |

### Running the evaluator

```bash
# 1. Start SkillForge and exercise it (so audit rows exist to backfill):
go run ./cmd/server

# (In a separate terminal — drive a few queries via POST /api/chat so
# audit rows land in skillforge.db. Optional: the eval CLI runs fine
# without pre-existing audit rows; it just won't backfill anything.)

# 2. Run the evaluator over the 50-case golden set:
go run ./cmd/eval --golden=eval/golden/compliance.jsonl

# 3. Read the outputs:
#    eval/report.json       — per-category metric averages + per-case detail
#    eval/calibration.json  — recommended retrievalScoreThreshold
```

### Reading `report.json`

```json
{
  "overall": {
    "faithfulness": 0.92,
    "context_precision": 0.85,
    "answer_relevance": 0.88,
    "context_recall": 0.79
  },
  "per_category": {
    "adversarial":      { "faithfulness": 0.88, "context_precision": 0.82, ... },
    "refusal-required": { "faithfulness": 1.00, "context_precision": 0.00, ... },
    "multi-hop":        { "faithfulness": 0.91, "context_recall": 0.65, ... }
  },
  "cases": [ {"id": "adv-001", "category": "adversarial", ...}, ... ]
}
```

- `refusal-required` faithfulness should be ~1.0 (refusals have no
  claims → 1.0 by convention). If it's < 0.95, the agent is answering
  when it should refuse.
- `adversarial` faithfulness is where Ragas self-eval bias shows most
  (the judge is scoring GLM answers, generated by GLM). Use the human
  spot-check (below) here first.
- `multi-hop` context_recall stresses retrieval coverage. Low scores
  here mean the retriever is missing one of the needed clauses.

### Reading `calibration.json`

```json
{
  "recommended_threshold": 0.34,
  "rationale": "midpoint of refusal boundary (0.21, 5th percentile of ...)",
  "score_distribution": { "median": 0.42, "p25": 0.31, "p75": 0.55, ... },
  "refusal_boundary_score": 0.21
}
```

The `recommended_threshold` is the **D2-15 retirement vehicle**. It
replaces the magic `0.3` literal at `internal/server/pipeline.go:43`.
The swap is a **manual ops decision** — the eval CLI emits the data;
the operator reviews the rationale and edits the literal:

```go
// internal/server/pipeline.go:43 (BEFORE)
const retrievalScoreThreshold = 0.3

// (AFTER operator reviews eval/calibration.json and decides)
const retrievalScoreThreshold = 0.34
```

This is intentional: the threshold governs the refusal floor (a trust
boundary), so a human signs off before it goes live.

## Pitfall 8 counter-measures (judge self-eval bias, D3-07)

The judge is **GLM scoring GLM-generated answers** — a known optimism
risk. Three counter-measures (all in place, none blocking Phase 3 exit):

1. **Deterministic Go grounding floor** (D3-01). The trust floor
   catches worst-case hallucinations REGARDLESS of what the judge
   says — if the agent answered but the retrieve tool returned 0
   chunks, the agent's output is discarded and a structured Refusal
   is returned. The judge never sees the hallucinated answer.

2. **Human spot-check (non-blocking Phase 3 exit criterion).** After
   each eval run, manually review ~5 cases where faithfulness > 0.9
   to confirm the judge is not optimism-skewed. Look for cases where
   the answer asserts a specific number/threshold that the chunk text
   does not actually contain — the judge should mark these as
   unfaithful, but if it marks them faithful, that's the self-eval
   bias signal. Log findings; if systematic, switch `JUDGE_MODEL` to
   a different model for cross-evaluation.

3. **`JUDGE_MODEL` config slot.** Setting `JUDGE_MODEL=deepseek-chat`
   (or any OpenAI-compatible model) switches ONLY the judge — the
   production agent keeps using `GLM_API_KEY`/`glm-5.2`. This is the
   Phase 6 cross-evaluation vehicle: run the eval once with GLM
   judging, once with DeepSeek judging, diff the scores. A score
   delta > 5% on faithfulness flags the self-eval bias.

## What this evaluator does NOT do

- **It is NOT a CI promotion gate.** Phase 3 emits the data; Phase 6
  wires `eval/report.json` into the CI gate (faithfulness < 0.9 blocks
  Skill promotion — GEVL-07).
- **It is NOT an always-on HTTP service.** It's a batch CLI. Running
  it against the 50-case golden set takes ~5-10 minutes (50 agent
  Runs × ~6 LLM calls each at temp=0).
- **It does NOT train or fine-tune.** Pure prompt-based eval. The
  agent and judge are both stateless API callers.
- **It does NOT touch `web/`.** The frontend has its own TS wire-
  contract tests; this evaluator is Go-only.

## Re-producibility (SC-6)

`internal/eval/eval_test.go::TestRunnerReproducibility` is the SC-6
gate. It runs all 4 metrics on the 5-case frozen fixture
(`internal/eval/testdata/frozen_5.jsonl`) TWICE with a `StubJudge` +
deterministic SHA-derived embedder, and asserts `abs(run1 - run2) < 1e-9`
for every (case, metric) cell. If this test fails, the eval pipeline
has a hidden source of non-determinism (a map iteration order, a
`time.Now`, etc.) — fix it before shipping.
