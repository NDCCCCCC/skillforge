## Goal

Touch `skills/<name>/SKILL.md` on disk → `ReloadToast` within ~1s (status ok). Append broken
YAML → failure toast (`status:failed`, old version kept). Drop the dead SSE EventSource that
404-hammers `/api/skills/events`.

## Root cause (confirmed)

1. `GET /api/skills/events` is NOT registered → SSE EventSource 404 reconnect storm.
2. `GET /api/skills` returns `[]*skill.Manifest` — NO `version` field. `registry.Entry.Version`
   exists but (a) is never serialized, (b) `cmd/server/main.go` never constructs `Deps.Registry`,
   so the fsnotify watchLoop is fictional in production.

## Design (de-risked against existing tests)

### Sub-choice resolved (the locked decision was ambiguous here — documented for audit)
The decision text names BOTH `registry.Entry.Version` AND "Loader.Scan() path." Engineering
verdict: **wire `skill.Registry`** as the listing/reload signal source.
- Registry already has correct, TESTED fsnotify + per-skill `Entry.Version` + graceful per-file
  failure (D5-08 keep-old + loadError hook).
- Re-implementing fsnotify+version+graceful-failure on the Loader would duplicate the Registry
  AND break `Loader.Scan`'s fail-fast startup contract.
- `Loader` stays for wizard-commit registration confirmation + chat findSkill + agent construction.
  Registry is ADDITIVE for the listing/reload path. Dual startup scan (~1 skill) is negligible.

### JS Number safety (load-bearing)
`Entry.Version` uses `time.Now().UnixNano()` (~1.7e18 > 2^53) and reloadOne bumps `prev.Version+1`.
At 1.7e18 the JS double ULP is ~512, so a `+1` reload bump is **invisible to JS** — polling could
not detect reloads. **Change to a per-process monotonic counter** (`atomic.Int64` from 1).
- All existing `registry_test.go` assertions are RELATIVE (`>0`, `>pinned`, `==goodVersion`,
  unchanged-on-failure) → a counter satisfies every one. No test asserts UnixNano shape.

### Failure contract (must not break T4/T6)
`TestRegistry_Reload_ValidationFailure_KeepsOld` + `_SymlinkEscape_Rejected` pin: on failure,
version UNCHANGED + manifest UNCHANGED + loadError hook fired. So failures MUST NOT bump version.
- Surface failures via a NEW copy-on-write `Registry.failed map[string]string` (name→err.Error()).
- `reloadOne` on error → `setFailed(name, err)` (version unchanged). On success → `clearFailed(name)`.
- `listSkillsHandler` overlays `status:"failed"` + `error` from the failed map.
- FE poll emits the failure toast on a **status flip** (ok→failed), not a version bump.

### Response shape (breaking — verified safe)
`GET /api/skills` → `[]{id,name,version,status,error?,manifest}`. **Only FE consumer of the live
list endpoint is `useSkillReload.ts`** (grep-verified). All other Skill components
(SkillManagerMenu, ChatInput, SkillPicker, SkillMdPreview) read the STATIC fixture
`__fixtures__/skills.json` — that is §4's problem, untouched here.
