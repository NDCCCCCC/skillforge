# Summary 260813-1y0: UAT #7 hot-reload toast bridge (polling-B)

## Outcome
DONE. The Skill hot-reload notification bridge is rebuilt **polling-only
(decision B)**, end-to-end. Touching `skills/<name>/SKILL.md` now bumps a
JS-safe per-process version counter that `GET /api/skills` serializes; the FE
polls it and fires `ReloadToast` on a version increase (success) or a status
flip (ok→failed on broken YAML, prior version KEPT). The dead SSE `EventSource`
on the never-registered `/api/skills/events` — the source of the 404 reconnect
storm — is deleted. Completes the hot-reload subsystem alongside #9 (wizard
NEW-skill registration).

## Changes
**BE (commit `3d77870` — core):** `internal/skill/registry.go` — replaced
`time.Now().UnixNano()` `Entry.Version` with a per-process `atomic.Int64`
counter (`nextVersion()`, from 1) so every reload bump is visible to JS
(UnixNano ~1.7e18 > 2^53 made a +1 bump invisible, ULP≈512). Added copy-on-write
`failed atomic.Pointer[map[string]string]` + `setFailed`/`clearFailed`/`Failed()`.
`reloadOne` error path calls `setFailed` then the existing loadError hook
(version + manifest UNCHANGED — keep-old contract, T4/T6); success path
`clearFailed`.

**BE (commit `3265178` — wiring + tests):** `internal/server/skills.go` —
`listSkillsHandler` rewritten to `skillItem{ID,Name,Version,Status,Error?,
Manifest}`; Registry path iterates sorted `Snapshot()` overlaying `Failed()`
(status:"failed" + error, NO version bump); Loader fallback version:0 /
status:"ok"; empty → `[]`. `cmd/server/main.go` constructs
`skill.New("skills/", nil)` + `reg.Watch(ctx)` and sets `Deps.Registry` (so the
fsnotify watcher is REAL in production, not fictional). Tests: exported
`Registry.Reload(path)`; `skills_test.go` nested-shape updates +
`TestListSkillsHandler_RegistryVersionAndFailedStatus`; `skills_wizard_test.go`
#9 regression → nested; `registry_test.go` `TestRegistry_FailedMap_SurfacesValidationError`.

**FE (commit `09ae711`):** `useSkillReload.ts` — polling-only rewrite: dropped
the `constructSSE` import + SSE conn block + `ssePath`; `SkillListItem` gains
`status?`/`error?`; the poll tick tracks `Map<id,{version,status}>` and emits on
version-increase OR status-flip (failed → {status:'failed', version:'old-kept',
error}; else {status:'ok', version:'new'}); first tick seeds a baseline without
emitting. `web/src/lib/sse-client.ts` + its test DELETED (sole consumer was
useSkillReload). `App.tsx` stale SSE comments fixed. `useSkillReload.test.tsx`
adds the status-flip case.
