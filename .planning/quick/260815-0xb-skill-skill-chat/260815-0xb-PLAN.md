<objective>
两项 chat 交互改进：

1. **斜杠命令 Skill 菜单**（借鉴 Claude Code）：在输入框键入 `/` 触发 Skill 菜单（带过滤 + 键盘导航），替换当前不符合最佳实践的点击式 popover 下拉框（`web/src/components/chat/ChatInput.tsx` Plan 05-07 D5-IA-01 遗留交互）。
2. **chat 流式输出**：当前 VerdictPipeline 在 embed→retrieve→LLM→grounding 的整个等待期（数秒到数十秒）不发射任何 SSE chunk，结论又以单个 `text-delta` 一次性发出 —— 用户感知为"一次性返回"。本计划让 pipeline 各阶段流式发射 `data-subprogress` 进度 chunk。FE 的 `DataSubprogressPart`（FEUI-06）**已经存在并在渲染**该 wire 类型（mock fixture `sub-progress.json` 在用），但后端 `wire.ValidTypes` 白名单没有 `data-subprogress`、pipeline 从未发射 —— 打通这条现成通道即可。

Purpose: 输入区交互对齐成熟 harness 心智模型；流式进度消除"长时间空白"的坏体验，展示 agent 工程透明度（SkillForge 开源卖点）。
Output: 上述 must_haves artifacts；全量回归绿。

**范围说明（非削减）**：结论文本无法做 token 级流式 —— 结论句是 LLM 输出结构化 Verdict JSON 并通过 grounding 校验后、由 `conclusionText()` 确定性推导的模板（信任架构要求：readable surface 是 trust-checked structure 的纯函数）。在 grounding 完成前向用户流式发文本会破坏"绝不确定性地输出未验证结论"的设计底线。因此流式输出的正确实现 = 阶段进度流（data-subprogress），这正是本计划所做的。
</objective>
