**A. 新建 `web/src/transport/RealChatTransport.ts`** — 实现 ChatTransport<UIMessage> 接口，复用 MockChatTransport 的 DraftUpdate 类型（从 './MockChatTransport' re-export `DraftStatus` / `DraftUpdate` / `DraftUpdateHandler` / `MockChatTransportDraftOptions`，避免类型重复）。

构造签名：`constructor(opts: RealChatTransportOptions, draftOpts: MockChatTransportDraftOptions = {})`，其中 `RealChatTransportOptions = { api: string; fetch?: typeof globalThis.fetch; headers?: Record<string,string> }`。

`sendMessages(options)` 实现：
1. 调用 `fetch(opts.api, { method:'POST', headers:{'content-type':'application/json', ...opts.headers}, body: JSON.stringify({ messages: options.messages, id: options.chatId }), signal: options.abortSignal })`（fetch 可由 opts.fetch 覆盖，便于测试）。
2. 断言 `response.ok` && `response.body` 存在；否则 controller.error。
3. 用 `getReader()` 读 `response.body`，按行切分 SSE（每个 frame = `data: <json>\n\n`，可能前置 `event:` 行被忽略；多行 data 用 `\n` 拼接）。
4. 对每个 data JSON: `JSON.parse(line)` → 按 type 分类：
   - `text-delta-draft` → 累积 `draftBuffer += chunk.delta`，emit `onDraftUpdate({status:'pending', draftText: draftBuffer})`，**不 enqueue**
   - `text-delta-draft-end` → emit `onDraftUpdate({status:'pending', draftText: draftBuffer})`（保持 pending 等 data-policy），**不 enqueue**
   - `data-policy` 且 `data.status` 存在 → emit `onDraftUpdate({status:'verified', draftText: draftBuffer})` + enqueue chunk
   - `data-policy` 且 `data.reason` 存在 → emit `onDraftUpdate({status:'refused', draftText: ''})` + enqueue chunk
   - 其他 type → 直接 `controller.enqueue(chunk as UIMessageChunk)`
5. 流结束时 `controller.close()`；fetch 抛错时 `controller.error(err)`。
6. 在 start 闭包内维护本地 `draftBuffer = ''`（每次 sendMessages 重置 — 与 MockChatTransport 一致，状态机 LOCAL to stream）。

`reconnectToStream` 返回 `null`（与 MockChatTransport 对齐 — 当前实现没有持久 server-side stream handle）。
