    - reconcileOne 末尾追加 O(n) 存在性扫描（checker concurrency_correctness 修复，必做）：遍历当前 snapshot 的每个 entry，lstat filepath.Join(rootAbs, name, "SKILL.md")，不存在即 removeFromSnapshot(name)（含 clearFailed）。动机：单 timer 单 pending path 的 debounce 在"删 A + 增 B"同窗突发下，B 的 schedule 覆盖 pending path，静默丢失 A 的移除事件 —— 恰为本计划 objective 的 motivating 场景（git rm -r skills/compliance + 新增 skills/simple-qa）；全量扫描天然兜底该场景、cp -r 竞态及任何"移除事件未被送达/被覆盖"路径。成本：snapshot 规模 = 已注册 skill 数（v1 量级几十），每个 debounce 窗口至多触发一次，可忽略。扫描中同样不得调用 setFailed/loadError（不存在 = 移除，不是加载失败）
    - removeFromSnapshot(name)：copy-on-write 克隆 snapshot、delete(next, name)、仅当 name 原本存在才 Store；slog.Info 记录移除

      2. event.Op 含 Remove|Rename：event.Name 以 SKILL.md 结尾 → scheduleReconcile(event.Name)；event.Name 是 rootAbs 直属子目录 → scheduleReconcile(filepath.Join(event.Name, "SKILL.md"))（Windows 下 ReadDirectoryChangesW 对 remove 可能只报目录名）
      3. 其余事件维持现状：resolveSkillPath 命中 → scheduleReload 改为统一 scheduleReconcile（同一 debounce timer，重命名为 scheduleReconcile 或保留名字但回调改 reconcileOne）；未命中 → continue
    - New() 启动时在 watcher.Add(root) 之后（顺序不可颠倒，见 L126-131 Windows 约束）、startupScan 之前，os.ReadDir(root) 对每个直属子目录 watcher.Add —— 修复 Linux 下从未建立的子目录 watch（现状单文件编辑重载在 Linux 实际收不到事件，仅 Windows 递归特性掩盖）；Add 失败仅 slog.Warn 不 fatal
    - 保持不回退：ReloadDebounce=1s 语义、单 timer 单 pending path 结构（配合上述存在性扫描后单 pending path 不再丢失移除语义）、failed keep-old 契约、symlink guard（经 parseAndValidate 复用）、nextVersion JS-safe 上限、watchLoop 的 recover/ctx.Done/errors 分支
