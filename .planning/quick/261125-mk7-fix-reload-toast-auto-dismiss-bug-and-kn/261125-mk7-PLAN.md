# Quick Plan 261125-mk7 — ReloadToast 自动消失失效 + graph-browser 片段 403

**日期:** 2026-11-25 · **分支:** main · **模式:** quick（1-3 个原子任务）

## 背景与根因（编排方已诊断，已对代码核实）

**Bug 1 — ReloadToast 成功 toast 永不自动消失**
`web/src/components/layout/ReloadToast.tsx:85-103`：父级 effect 把所有 setTimeout 句柄存进局部数组 `timers`，cleanup 时全部 clearTimeout。当 4 秒窗口内 `skillReloadStatus` 再次变化（如第二个 skill 先后重载，两条 toast 叠放）时，effect 重跑，但旧条目被 `if (entry.ts <= lastSeen) continue;` 跳过 —— timer 永不再创建，toast 永驻。

**Bug 2 — knowledge-graph 浏览器取片段 403**
BE `internal/server/knowledge.go` chunkHandler（~270 行）在写出前调 `s.knowledgeReadAllowed(c, payload.Tier)`（2026-11-09 引入，见 `internal/server/identity.go:149-180`）。该闸门只放行：有效 X-Admin-Token，或 X-Skill-Name 的 manifest reads 覆盖目标 tier。而 graph 端点（/api/knowledge/graph、/graph/neighbors）按 D-28-02-AUTH 是公开读。FE `web/src/lib/chunk-lookup.ts` 的 `fetchChunkContent` 是**裸 fetch，绕过了两个身份注入点**：既不走 `apiFetch`（`web/src/lib/api.ts`，会注入 X-Owner-Token），也不读 admin token（localStorage key `sf_admin_token`）。因此**即使是已认证的浏览器**，这一条请求也不带任何身份头 → BE 拒绝 → 403 → `web/src/components/center/ChunkSourceView.tsx` 渲染 加载片段失败（用户实测已登录仍复现）。这是 2026-11-09 闸门锁死了自家产品 UI（260813 feature / UAT #4）的回归。

**修复方向（已定，含用户修正）**：BE 复用浏览器身份层 —— `knowledgeReadAllowed`（`internal/server/identity.go:149-180`）增加第三条放行分支：非空 X-Owner-Token 视为已声明的浏览器身份，放行（与现有 X-Skill-Name 注释同理：拦的是"完全匿名的批量枚举"，不是"可自述的身份"；graph 元数据本就公开读，此举修复 UI 断裂而不削弱匿名枚举防线），同步更新 fail-closed 注释块。FE 是关键修复点：`fetchChunkContent` 必须同时携带 (a) `X-Admin-Token`（localStorage `sf_admin_token`，存在时才发，姿势参照 `web/src/components/admin/platform/platformApi.ts:20/25`）和 (b) `ownerTokenHeaders()`（`web/src/lib/owner-token.ts:82`）—— 无 admin token 的浏览器靠 BE 新放行分支兜底。ChunkSourceView 对 403 渲染更具体的错误文案。

**约束**：失败 toast 保持常驻（UI-SPEC §SC-2）+ 手动 X 关闭不变；chunkHandler 既有测试（`internal/server/knowledge_test.go` ~163-400）必须继续通过。

**动作**
1. `knowledgeReadAllowed`（identity.go:149-180）：在 X-Skill-Name 分支**之前**加：
   ```go

   }
   ```
   同步改写函数 godoc 的放行条件注释块（admin / owner-token / X-Skill-Name / 拒绝），并说明：owner token 与 X-Skill-Name 同为自述身份，拦的是完全匿名批量枚举；graph 元数据已公开读（D-28-02-AUTH），此举修复图浏览器 UI 而不削弱匿名枚举防线。
2. BE 测试（沿用 `invokeChunkHandler` + `ut.Header` 既有姿势，参考 ~175-266 行）：
   - `TestChunkHandler_OwnerTokenAllowed`：无 X-Skill-Name、仅 `X-Owner-Token: some-owner` → 200。
   - `TestChunkHandler_NoHeadersStill403`：无任何身份头 → 403 且 body error 为 "knowledge chunk not readable by this caller"（fail-closed 不变）。
   - 既有测试（Found 用 X-Skill-Name、NilBuilder/BadID/NotFound/BuildError、RouteRegistered）保持通过 —— 注意 NotFound/BuildError 在闸门之前返回，不受影响。
3. FE `fetchChunkContent`（关键）：headers 同时合入 admin token 与 owner token —— 存在时带 `X-Admin-Token: localStorage.getItem('sf_admin_token') ?? ''`，并展开 `...ownerTokenHeaders()`（`web/src/lib/owner-token.ts:82`）；与 `platformApi.ts:24-26` 的 `adminHeaders()` 同款姿势（不 import 那个私有助手，本文件内联同样两行，保持 chunk-lookup 无跨模块耦合）。
4. BE 测试补充对应用例：`TestChunkHandler_AdminTokenAllowed`（有效 X-Admin-Token → 200，锁住 admin 分支不被新分支破坏）；admin token 姿势参照 knowledge_test.go 既有 admin 相关用例。
5. `ChunkSourceView`：错误态检测 `err.message` 含 403 / "not readable" 时渲染更具体文案（如「片段访问被拒绝（403）：缺少浏览器身份，请刷新页面重试」），其余仍显示 加载片段失败；保持既有 data-testid 结构。
