  <name>Task 1: Write scripts/merge_parts_pipeline.py (stdlib-only, dry-run, --only, conservation-gated)</name>
  <files>scripts/merge_parts_pipeline.py</files>
  <action>
Create `scripts/merge_parts_pipeline.py` — Python 3 standard library ONLY (argparse, pathlib, re, sys, shutil, tempfile as needed), in the style of the repo's existing pipeline scripts (scripts/compress_pipeline.py precedent: single-purpose, utf-8 explicit). Zero third-party imports.

CLI: `--corpus` (default `knowledge/sql-guides`), `--dry-run` (print the plan, write/delete nothing, exit 0), `--only IDX[,IDX...]` (process only these source_idx values — pilot mode), `--max-bytes` (default 4000, mirroring internal/knowledge/indexer.go:67 maxDocBytes), `--verbose`. Exit codes: 0 success or nothing-to-do, 1 usage error, 2 validation/conservation failure.

PHASE 1 — Discover + group. Recursively glob `*.md` under corpus; a file is a part iff its name matches `^(?P<stem>.+)__part(?P<num>\d{1,})\.md$`. For each part read the file, strip frontmatter exactly like splitFrontmatter does (leading `---` line, next `---` line; permissive when absent), and parse the simple `key: value` frontmatter lines for title / source_idx / split_part / source_split. Fallback when frontmatter lacks a field: parse the stem as `^(?P<idx>\d+)_(?P<title>.+)$`. Group key = (subdirectory, source_idx, title). Order parts within a group by split_part's N (fallback: filename part number). If the parts found for a group != M from `split_part: N/M`, that group FAILS closed (report which parts are missing; counted in exit-2 gate). Files not matching the part pattern are never touched — the 17 whole notes stay byte-identical.

PHASE 2 — Merge. Concatenate part bodies in order, joined by a blank line. Keep only the FIRST `# {title}` H1; any later line exactly equal to it is dropped as a sanctioned duplicate (count and report drops in stats — this is the only permitted deletion).

PHASE 3 — Normalize. Two sub-stages, both designed so running them twice changes nothing (idempotent by construction: every split inserts a newline, so a glue pattern can never re-match).
  3a. Glue splitting — apply ONLY this closed rule list (no free-form rewriting):
    - `;` immediately followed by a CJK char, or by a SQL keyword (select|insert|update|delete|drop|create|alter|truncate|merge|with|from|where|and), case-insensitive -> insert newline after the `;` (evidence: `...('OVD','CCI');注：1、...`).
    - a CJK char immediately followed by one of those SQL keywords -> newline between them (evidence: `--入账保费收入+跟单手续费业务费绩效drop table tmp_ycb_002;`).
    - `[A-Za-z0-9_.)]` immediately followed by `set ` where the next token is `ident=` -> newline before `set ` (evidence: `etl_NONAUTO_POLICY_Tset department_group_code='420100'`).
    - `[A-Za-z0-9_.]` immediately followed by `left join` / `right join` / `inner join` -> newline before the join keyword (evidence: `t.policy_noleft join etl_policy h`).
    CJK detection = chars in the 一-鿿 range. Log each applied rule with counts (--verbose prints file:line).
  3b. Fence re-derivation — existing fences are NEVER trusted; they are always re-derived, which is what makes pairs guaranteed:
    - First protect non-SQL fenced blocks: any block whose opening fence carries a non-sql info string (```bash, ```json, ```python, ```yaml, ...) is lifted out verbatim and re-inserted untouched at the end.
    - Strip all remaining bare ``` and ```sql fence lines.
    - Classify the remaining lines into SQL regions vs prose. Strong SQL start: optional `-- comment` lines then `^\s*(select|insert|update|delete|drop|create|alter|truncate|merge|with|grant|revoke|exec|execute|call|begin|declare)\b` case-insensitive. Continuation (keeps the region open): line starts with and/or/where/from/join/left/right/inner/on/set/group/order/union/having/values/by/as/,/)/(/;/`ident=` or ends with `,`/`;`/`(`/`=`/`--`, AND the line is not a `#` heading AND does not start with CJK prose. A region ends at a heading, at a CJK-prose-start line, at a protected-block marker, or EOF.
    - Wrap each SQL region as ```sql ... ``` (open+close emitted as a pair, always).

PHASE 4 — Split into sections. Split the normalized body on `^## ` headings. Content before the first h2 (the H1 + 涉及表/视图 preamble) becomes its own section — it is NEVER dropped. A body with no h2 at all yields a single section. Section heading = the h2 text (preamble section uses the note title).

PHASE 5 — Byte budget. Encode each section body (post-frontmatter, exactly what the indexer measures) in UTF-8; if > --max-bytes, secondary-split at SQL statement boundaries (`;` + newline), greedily accumulating statements until adding the next would exceed the budget. Each secondary chunk body is PREFIXED with its section's original `## {heading}` line (a sanctioned addition — frontmatter is stripped before embedding, so this is the only way the chunk carries section context in the vector). Record every prefixed heading for gate G4.

PHASE 6 — Conservation gates. Define norm(text) = remove ALL whitespace AND drop every line whose stripped form starts with ``` . Gates run for ALL groups BEFORE any write; any failure -> print the failing group, per-gate character counts, and exit 2 with nothing written:
  - G1: norm(sum of part bodies) == norm(merged body)
  - G2: norm(merged body) == norm(normalized body)  (proves phase 3 only inserted whitespace + fence lines)
  - G3: norm(normalized body) == norm(concat of section bodies BEFORE heading prefixing)
  - G4: every prefixed heading line's text is a heading that exists in the normalized body
  - G5: every section body <= --max-bytes

PHASE 7 — Write (skipped entirely under --dry-run). Output name: `{stem}__sec{NN:02d}_{slug}.md` in the SAME directory as the parts, where stem is the part stem minus `__partNN`, NN = 1-based document-order index, slug = section heading sanitized (remove `\/:*?"<>|#`, collapse whitespace runs to `_`, strip edge `_`, truncate to 24 runes). Frontmatter emitted: `title` (original), `source_idx`, `section` (the section heading) — split_part and source_split are dropped. Before writing a group, delete that group's existing `__sec*.md` files (convergence on re-run — names are deterministic because NN follows document order and slug follows the heading). Only after EVERY group is written, delete all consumed part files (collect-then-delete; --dry-run prints the would-delete list instead). Never touch the 17 whole notes.

Finish by printing stats: parts consumed, groups, sections written, sections needing secondary split, max section body bytes, sanctioned H1 drops, part files deleted, whole notes untouched (expect 17). On a corpus with zero part files, print "nothing to do" and exit 0 — this is the idempotency contract.
