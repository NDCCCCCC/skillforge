<objective>
Make the BGE-M3 HTTP embedder connectable to internal HTTPS endpoints that use self-signed certificates, while keeping the default behavior (verify-on) safe for production. The current code shares http.DefaultClient.Do(req) which rejects self-signed certs — there is no knob. We add a configurable InsecureSkipVerify flag (off by default), construct a dedicated http.Client with a custom http.Transport, and wire an env var to the existing bge.New call site in cmd/server/main.go so operators can opt in for internal-network deployments.

Purpose: Unblock internal-network deployments where BGE-M3 is exposed behind a self-signed HTTPS reverse proxy (for example https://10.62.10.33:63803). The constraint says we MUST NOT silently weaken production TLS posture — InsecureSkipVerify is opt-in via env var, default false, and emits a startup WARN log so the operator sees the insecure mode is active.

Output: A TDD-driven fix (RED then GREEN) that adds 1 Config field, 1 BGE struct field, swaps http.DefaultClient for a constructed client, and threads BGE_M3_TLS_SKIP_VERIFY through cmd/server/main.go. About 30% context budget.
</objective>
