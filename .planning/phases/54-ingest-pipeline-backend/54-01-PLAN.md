<objective>

Phase 54-01: 摄取异步化——upload 从同步 HTTP 内联转为 job，八步状态机 `parse → chunk → embed → vector_insert → ecl_merge → ecl_extract → ecl_kg_load → ecl_milvus_load` 每步落库（SC 5 的 step 元组），`GET /api/admin/ingest/jobs/:id` 暴露 step 级状态，`POST upload` 返回 job_id。

**表结构定夺（两表，否决 RAGFlow 单表宽行）**：`ingest_jobs`（run 态）+ `ingest_steps`（步态）+ `ingest_items`（item 态，本 plan 建 schema、54-03 消费）。理由：RAGFlow 把 chunk_ids/retry_count/progress_msg 揉在 Task 单行上，是因为它的步骤不是一等实体（进度靠追加字符串，不可查询）；SC 5 明确每步独立 status/attempt/started_at/completed_at/error/artifact_ref——8 步 × 8 字段的宽行会随步骤集演化反复改 job 表 DDL，且步级重试（54-03）需要 (job_id, step) 行粒度的 CAS 与级联更新。Dify 的 8 态 indexing_status + 4 个 `*_completed_at` 时间戳同样是列式宽行，但 Dify 步骤集固定且不可重试单步；我们要重试，就选行式。

**UploadIndex 分解纪律**：摄取管线从此以步骤函数为唯一实现，UploadIndex 改为对步骤函数的组合封装（不得出现两套实现——53-02 修的正是"两套分块器"这一 bug 类）。

**wave 分工边界**：本 plan 与 54-02 同 wave，合入顺序 01 → 02。本 plan 拥有 steps.go 的 parse/vector_insert/ecl 段与 schema.go 的 jobs/steps/items 三张 DDL；54-02 拥有 chunk/embed 段与 embed_cache DDL，均为追加编辑。

Output: 可跑通的异步摄取链（fake seams 全链 done）+ 状态端点 + 上传返回 job_id（FE 契约破坏：旧响应 {chunks, id_range} 移除——chunk 数与 ID 区间在异步世界里完成前不可知，Phase 55 承接前端迁移）。

</objective>

```sql
    job_id      TEXT PRIMARY KEY,              -- "ing-" + crypto/rand 12字节 hex（24字符）

    status      TEXT NOT NULL DEFAULT 'queued',-- queued|running|partial|done|failed
    error       TEXT NOT NULL DEFAULT '',
    created_at  TEXT NOT NULL DEFAULT '',
    updated_at  TEXT NOT NULL DEFAULT ''
);
CREATE TABLE IF NOT EXISTS ingest_steps (
    job_id       TEXT NOT NULL,
    step         TEXT NOT NULL,                -- 八步枚举，见 ingest.StepSequence
    status       TEXT NOT NULL DEFAULT 'pending', -- pending|running|done|failed|skipped|stale
    attempt      INTEGER NOT NULL DEFAULT 0,   -- 每次执行 start 时 +1，累计不清零
    started_at   TEXT NOT NULL DEFAULT '',
    completed_at TEXT NOT NULL DEFAULT '',
    error        TEXT NOT NULL DEFAULT '',     -- 一等字段：失败原因必须可查询（Dify 教训）
    artifact_ref TEXT NOT NULL DEFAULT '',     -- 54-02 定语义，本 plan 先落列
    PRIMARY KEY (job_id, step)
);
CREATE TABLE IF NOT EXISTS ingest_items (
    job_id     TEXT NOT NULL,
    step       TEXT NOT NULL,                  -- v1 仅 embed 写入（vector_insert 是批原子语义不拆 item；ecl 的 item 账本是既有 ecl_failures，不重复建）
    item_key   TEXT NOT NULL,                  -- embed = chunk content_hash
    status     TEXT NOT NULL DEFAULT 'pending',-- pending|done|failed
    error      TEXT NOT NULL DEFAULT '',
    updated_at TEXT NOT NULL DEFAULT '',
    PRIMARY KEY (job_id, step, item_key)
);
```
