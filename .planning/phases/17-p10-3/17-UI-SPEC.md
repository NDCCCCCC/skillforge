## Spacing Scale

Reuse the locked Phase 4 scale (`theme.css` §Spacing). No new tokens. All Phase 17 surfaces use the canonical 8-step scale.

| Token | CSS var | Value | Phase 17 usage |
|-------|---------|-------|----------------|
| xs | `--space-1` | 4px | Sparkline point gap from inline text; hover popup inner padding; chip-to-chip gap |
| sm | `--space-2` | 8px | Sparkline wrapper padding-y; hover popup padding; chip internal padding |
| md | `--space-3` | 12px | Message bubble padding (inherited); data-reference part outer margin |
| lg | `--space-4` | 16px | Sparkline SVG container padding; popup max-width |
| xl | `--space-5` | 20px | (reserved — not used in Phase 17) |
| 2xl | `--space-6` | 24px | Multi-KPI answer block vertical gap between numbers |

**Exceptions (declared, not violations):**
- Sparkline SVG `viewBox` intrinsic sizing: `width="100%" height="32"` (32px is a multiple of 4). The 32px height is the sparkline's intrinsic height — it fits inside the message bubble line-height (14px × 1.5 = 21px) + 4px top/bottom padding + 4px text clearance = 29px → rounded to 32 for clean 4-grid.
- Sparkline `<circle>` r=2.5 (idle) / r=4 (hover) — these are SVG coordinate units, NOT CSS spacing tokens. Exempt from the "multiples of 4" rule.
- Hover popup: `max-width: 280px` (not a multiple of 4 — 280 IS a multiple of 4). Padding is `--space-2` (8px) on all sides.

## Layout Contract

Phase 17 ships **zero new layout** — all surfaces embed inside the existing chat message body. The chat column, left sidebar, and right detail panel are LOCKED (Phase 4 baseline).

### Position 1 — Sparkline inside message bubble

The `<Sparkline>` component renders as an inline block **below** the answer text, within the same `<MessageBubble>`:

```
┌─────────────────────────────────────────────────┐
│ 贷款余额 4,231.5 亿元，按 KPI_LOAN_BALANCE 计算  │ ← text body (Body 14px)
│ （as_of 2026-08-01）                             │
│                                                 │
│ ┌─ Sparkline (viewBox 0 0 300 32) ────────────┐ │
│ │  6000│     ·──·                           │ │ │ ← SVG <polyline> + <circle>
│ │  4000│    ·    ·──·──·──·──·──·           │ │ │   height=32px, width=100%
│ │  2000│   ·                              ·  │ │ │   stroke: --color-sparkline
│ │      └──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┬──┘ │ │   points: <circle r=2.5 idle>
│ │        01月 02月 03月 ... 12月             │ │ │   hover: <circle r=4 active>
│ └───────────────────────────────────────────┘ │
│                                                 │
│ [看月度趋势]                           ← chip  │
└─────────────────────────────────────────────────┘
```

**Layout semantics:**
- Sparkline wrapper: `display: inline-block; width: 100%; margin-top: var(--space-2); margin-bottom: var(--space-1);`
- SVG: `width: 100%; height: 32px; overflow: visible;` — intrinsic 32px height.
- Sparkline is **always** below text, never interleaved with text (preserves reading flow).
- When multiple numbers appear in one answer, the sparkline appears **after** all text and all inline numbers (not between them).

### Position 2 — Hover popup (shared component)

The hover popup is the **same component** for both single-value data-reference and sparkline-point data-reference (D17-B4).

```
┌──────────────────────────────────┐
│ 4,231.5 亿元                     │ ← value (--color-text)
│ 周期：2026-07                    │ ← period (--color-text-muted)
│ 数据截至：2026-08-01             │ ← as_of (--color-text-muted)
│ 来源：data:aggregated_only        │ ← channel (--color-text-dim)
│ 函数：KPI_LOAN_BALANCE           │ ← KPI name (mono, --color-text-muted)
└──────────────────────────────────┘
```

**Layout semantics:**
- Tooltip trigger: `<Tooltip>` from shadcn (already present from Phase 4 citation chip).
- Popup max-width: `280px` (fits single-line KPI name + metadata).
- Padding: `--space-2` (8px) all sides.
- Border: `1px solid --color-border`, `--radius-md`.
- For sparkline points: popup appears on hover; tooltip placement = `top` (above the point).

### Position 3 — Drill-down chip

Embedded **below** the sparkline (or below the answer text if no sparkline), as a badge-like chip:

```
[看月度趋势]    ← chip (bg: --color-kpi-chip-bg, border: --color-kpi-chip-border)
```

**Layout semantics:**
- Component: `<Badge>` from shadcn (already present) styled as a clickable chip.
- `onClick` → navigates back to chat input, pre-fills `请调 {kpi_name} periods=[最近12个月]` (user can review before sending).
- Chip renders inline with text flow (NOT a block-level element).
- Only renders when the KPI function supports multi-period calls (declared in `drill_chips` field of KPI definition file; default = "看月度趋势" if field absent).

### Position 4 — Multi-KPI inline layout

Multiple KPI values inline within the same text body, each number hoverable independently:

```
贷款余额 4,231.5 亿元 [hover popup #1]，
不良率 2.3% [hover popup #2]，
利息收入 186.2 亿元 [hover popup #3]
```

**Layout semantics:**
- Numbers render as inline `<span>` with hover handler.
- No grid, no card, no separate layout block (D17-C2).
- Hover popups for each number appear independently (no z-index conflict — shadcn Tooltip handles stacking).
- Vertical spacing between multi-KPI answers: `--space-2` (8px) if a sparkline follows; otherwise `--space-1` (4px).

## Component Contracts (DASH-01..05 + supporting)

### DASH-01 — KPI numeric answer with full provenance

- **Component:** `MessageBubble` extension — `data-reference` part renders as inline text with hover popup.
- **Visual:** Each number in the answer text is wrapped in a `<span data-kpi-value>` that triggers the Tooltip on hover. The tooltip displays: value + period + as_of + channel name + KPI function name.
- **Multi-part SSE:** Each number gets its own `data-reference` part (D17-A4). UI renders them inline as text, each independently hoverable.
- **Chat input / answer output:** The answer text renders at the top of the assistant message bubble (existing `TextBody` behavior). Hover popups do NOT block the text — they appear above the hovered span.

### DASH-02 — Data reference popup (multi-point array)

- **Component:** `<DataReferencePopup>` (same as Phase 4 `Citation` tooltip, extended for KPI).
- **Single-value mode:** Displays the fields listed in §Copywriting Contract (value, period, as_of, channel, KPI name).
- **Sparkline-point mode:** Same component, displays the same fields + `point_index` (which point in the sparkline, 0-based). The popup header shows `{value}（点 {point_index + 1} / {N}）` to indicate position.
- **Implementation:** `data-reference part.references[]` array maps to N popups — each point's hover triggers a popup for that specific index. No wire union expansion (D16-B3 invariant).

### DASH-03 — Sparkline mini-trend

- **Component:** `<Sparkline points={[{x, y, value, period}]} onPointHover={(index) => showPopup(index)} />`
- **SVG structure:** `<svg viewBox="0 0 {width} 32">` containing:
  - `<polyline>` for the trend line (stroke: `--color-sparkline`, stroke-width: 1.5, fill: none)
  - N × `<circle>` for data points (r=2.5 idle, r=4 hover, fill: `--color-sparkline-point-active`, stroke: `--color-surface-2` for contrast)
  - Optional: `<text>` for x-axis period labels (Label 12px, `--color-text-muted`, positioned below the SVG)
- **No deps:** Hand-coded SVG. Zero shadcn blocks, zero third-party libraries. (D17-B1)
- **Auto-scale:** Y-axis auto-scales to [min, max] of the N points with 10% padding on each side. No fixed axis.
- **X-axis:** Period labels rendered below the SVG (Label 12px). Only shows labels for first, middle, and last points if N > 6 (avoids crowding).
- **Hover:** Point circle grows (r=2.5 → r=4) + Tooltip appears (same component as single-value popup).

### DASH-04 — Drill-down chip (multi-period re-invocation)

- **Component:** `<DrillChip label="看月度趋势" onClick={() => prefillChat(`请调 ${kpi_name} periods=[最近12个月]`)} />`
- **Visual:** `<Badge variant="secondary">` styled with KPI chip tokens (bg: `--color-kpi-chip-bg`, border: `--color-kpi-chip-border`). Text: Label 12px semibold.
- **Interaction:** Click → navigates to chat input, pre-fills the query. User must press Send (no auto-send). The pre-filled text includes the KPI function name for transparency.
- **Rendering rule:** Chip only appears when the KPI definition file declares `drill_chips` for this KPI. If absent, no chip renders. Default = "看月度趋势" if `drill_chips` is present but `label` is empty.

### DASH-05 — Multi-KPI combination

- **Layout:** Text inline (see §Position 4 above). No card, no grid, no separate layout region.
- **Hover:** Each number independently hoverable. Tooltips do NOT overlap — only one popup visible at a time (standard shadcn Tooltip behavior).
- **Spacing:** Comma-separated in natural language text. 8px gap (`--space-2`) between adjacent numbers if they need visual separation (e.g. when both are wrapped in data-reference parts).
