<objective>
Seed 12 documents across 4 knowledge tiers (权威/历史/个人/草稿) into a Milvus v2.5+ collection, run tier-filtered vector search with BGE-M3 dim=1024 embeddings, and prove that the tier filter returns ONLY the requested tier (zero cross-tier bleed).

Purpose: SC-2 of Phase 1. The tier filter is SkillForge's structural security boundary (no other vector DB has this ability). Without this plan, Phase 2-5's compliance refusal + authority-only retrieval cannot be built safely. Per D-06 / D-07: this must be the real tier-filter E2E, not just syntax validation.

Output: 12 markdown fixtures + a Milvus+TEI docker-compose file (or Milvus Lite / remote-Milvus instructions per docker-mode) + an `internal/spike/milvus_client.go` wrapper + a `spike milvus` subcommand that asserts bleed prevention across all 4 tier queries.

User Story:
**As a** Phase 2 developer (and the project's "trust contract" custodian for future work),
**I want to** validate that Milvus tier-filter blocks cross-tier retrieval at the database level,
**so that** Phase 2-5's compliance Skills can refuse out-of-tier retrieval as a structural guarantee, not a policy.
</objective>
