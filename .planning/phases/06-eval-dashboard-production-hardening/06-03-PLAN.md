<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → GLM API | The secret crosses from GitHub to the LLM provider; must not leak in logs or artifacts |
| Fork contributor PR → workflow | Untrusted code changes trigger the workflow; secrets are not available to forked PRs by GitHub default |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-6-SECRET | Information disclosure | GLM_API_KEY in CI | mitigate | Secret referenced via `${{ secrets.GLM_API_KEY }}`; never echoed in workflow steps; report.json/calibration.json do not contain the key (verified internal/eval/chatmodel.go:121-131 has no env-write path). `pull_request` trigger only — secrets are unavailable on default-branch push runs. |
| T-6-SECRET-FORK | Information disclosure | Forked PRs | accept / transfer | GitHub's default behavior withholds secrets from forked-PR workflows; this is the platform's security model, not ours. Cost control (all PRs run) is D6-12; [skip-eval] override is deferred to Phase 7. |
| T-6-SC | Tampering | GitHub Actions supply chain | mitigate | Uses only first-party actions: actions/checkout@v4, actions/setup-go@v5, actions/upload-artifact@v4. No third-party actions or marketplace downloads. |
| T-6-WORKFLOW | Tampering | Maliciously modified workflow in a PR | mitigate | The workflow file itself is under version control and reviewable in every PR diff. Path-filter ensures it runs on eval-relevant changes. |
</threat_model>
