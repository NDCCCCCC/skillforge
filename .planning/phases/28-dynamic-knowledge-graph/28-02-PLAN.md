  <action>
Extend internal/server/knowledge.go with three additions:

1. **neighborsHandler** (GET /api/knowledge/graph/neighbors?chunk_id=X&depth=N):
- Parse chunk_id via parseLenientChunkID — return 400 on failure.
- Parse depth=N query param (int, default SKILLFORGE_GRAPH_NEIGHBOR_DEPTH_LIMIT=2, max capped at config). Return 400 if depth <= 0.
- Build EdgeGraph from ListMetadata (call knowledge.ComputeEdges — imported from internal/knowledge).
- Call EdgeGraph.Neighbors(chunkID, depth, maxNodes) — returns NeighborResult.
- On chunk not found in metadata: return 404 with graphResponseError envelope.
- On success: return 200 with NeighborResult JSON (mirrors research §3 shape exactly).
- Degraded: when EdgeGraph.Neighbors returns degraded=true, include degraded=true + degraded_reason in response.
- Follow the same nil-check (s.Knowledge == nil → 503), W-3 masking (log full error at WARN, return generic to FE), and 503 pattern as graphHandler.

2. **pathHandler** (GET /api/knowledge/graph/path?from=X&to=Y&max_hops=N):
- Parse from and to via parseLenientChunkID — return 400 on failure.
- Parse max_hops (int, default SKILLFORGE_GRAPH_PATH_HOPS_LIMIT=4, capped at config). Return 400 if max_hops <= 0.
- Build EdgeGraph (same as neighbors).
- Call EdgeGraph.ShortestPath(from, to, max_hops) — returns PathResult.
- Return 200 with PathResult JSON (mirrors research §3 shape exactly).
- On chunk not found: return 404.
- On no path found within max_hops: return 200 with hops=-1, path=[], edges=[], degraded=true, degraded_reason="no path found within N hops".
- Follow same nil-check + W-3 + 503 pattern as graphHandler.

3. **Extend graphHandler**: After building the Graph, if len(all_chunk_ids) > SKILLFORGE_GRAPH_MAX_NODES (config-driven, default 50), set Graph.Degraded=true and Graph.DegradedReason with Chinese explanation naming the limit. The existing tiers/chunks are still returned (skeleton). No edges embedded in the main graph response — edges come from /neighbors and /path.

The edge graph is derived from ListMetadata. In Plan 28-03 a cache layer is added; for this plan, compute on every call (acceptable for small corpora; cache TTL is Phase 28-03's job).

Note: The Deps struct carries Knowledge *knowledge.GraphBuilder. Plan 28-01 creates ComputeEdges as a standalone function in the knowledge package. The handlers should call it via a knowledge.EdgeGraphFor(ctx) function (stub for now — it calls ListMetadata + ComputeEdges). The real TTL cache wiring happens in Plan 28-03.

For Plan 28-02 scope: handlers call knowledge.EdgeGraphFromMetadata(ctx, retriever) which is defined as:
```go
func EdgeGraphFromMetadata(ctx context.Context, r retriever.Retriever) (*EdgeGraph, error) {
    metas, err := r.ListMetadata(ctx)
    if err != nil { return nil, err }
    eg := ComputeEdges(metas)
    eg.buildAdjacency() // builds the adj map for fast lookup
    return eg, nil
}
```
This function goes in internal/knowledge/graph_edges.go alongside the existing types.

3. **Route registration** in internal/server/server.go New() — add three new routes:
```go
h.GET("/api/knowledge/graph/neighbors", deps.neighborsHandler)
h.GET("/api/knowledge/graph/path", deps.pathHandler)
```
These go after the existing graphHandler line. No new middleware needed.
