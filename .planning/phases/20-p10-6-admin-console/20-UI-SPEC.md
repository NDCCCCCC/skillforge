# Phase 20 — UI Design Contract

> Visual and interaction contract for Phase 20 Admin Console (P10.6). Four-tab read-only dashboard reusing the EvalDashboard shell pattern. Generated by gsd-ui-researcher.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | Tailwind CSS v4 (CSS-first, no tailwind.config.js) |
| Preset | not applicable |
| Component library | none (custom components, no shadcn) |
| Icon library | lucide-react (already in use) |
| Font | Plus Jakarta Sans Variable (from theme.css --font-sans) |

**Design system foundation:** All tokens are inherited from `web/src/styles/theme.css`. No new tokens are defined for this phase. The EvalDashboard.tsx and its SubrouteTab pattern are the canonical shell reference.

## Color

Inherited from theme.css `--color-*` tokens.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #0c0e12 (--color-bg) | App background |
| Secondary (30%) | #14171e (--color-surface) | Cards, list rows |
| Accent (10%) | #6366f1 (--color-primary) | Tab active state, focus rings, capacity bar fill |
| Destructive | #ef4444 (--color-danger) | Red badge on capacity breach only |

**Accent reserved for:** Tab active indicator (pill bg-primary-dim), capacity bar fill (normal state), focus rings on interactive elements. NOT used for status.

**Status semantic colors (from --color-status-*):**

| Status | Color | Usage |
|--------|-------|-------|
| completed / ok | #34d399 (--color-status-compliant) | Batch success, skill ok, schedule idle |
| pending / running | #fbbf24 (--color-status-needs-info) | Batch running, schedule running |
| failed / error | #f87171 (--color-status-non-compliant) | Batch failed, skill failed, schedule failed |
| unknown / never-run | #8b95a3 (--color-status-unanswered) | Null timestamps, unregistered skills |

### Shell Reference

The `AdminDashboard` component reuses the EvalDashboard.tsx shell pattern:

```typescript
// App.tsx — mirrors route === 'eval'
if (route === 'admin') {
  return <AdminDashboard />;
}

// AdminDashboard.tsx — mirrors EvalDashboard.tsx structure
<div className="flex h-full flex-col bg-bg text-text">
  <header className="flex h-11 items-center justify-between border-b border-border bg-surface px-4">
    {/* Back to Chat + title + /admin badge + Refresh */}
  </header>
  <nav className="flex items-center gap-1 border-b border-border bg-surface px-4 py-2">
    {/* SubrouteTab × 4 */}
  </nav>
  <div className="border-b border-border px-4 py-3">
    {/* CapacityMonitor */}
  </div>
  <main className="flex-1 overflow-y-auto p-4">
    {/* Active view panel */}
  </main>

```

### Route Branch

From App.tsx: `route === 'admin'` renders `<AdminDashboard />` (no `ReloadToast` needed since there is no live SSE transport for admin views). The store manages `adminSubroute` state (`'batches' | 'kpis' | 'skills' | 'schedules'`).

## Component Inventory

### 1. SubrouteTab (imported from EvalDashboard.tsx inline)

**Visual:** Rounded-md pill button. Active: `bg-primary-dim text-text`. Inactive: `text-text-muted hover:bg-surface-2 hover:text-text`. Font: `text-xs font-semibold`. Gap: `gap-1`. Icon: `lucide-react` 3.5px.

**States:**
- Default (inactive): text-muted, no background
- Hover: bg-surface-2, text-text
- Active: bg-primary-dim, text-text, no border
- Focus: focus-visible ring primary

### 2. CapacityBar

**Purpose:** Per-table row count/threshold progress bar. Shows audit growth health.

**Props:** `tableName: string`, `currentCount: number`, `threshold: number`

**Visual:**
- Label: `text-xs text-text-muted` (table name)
- Track: `flex-1 h-2 bg-surface-2 rounded`
- Fill: `h-full rounded` — normal: `bg-primary`; breach: `bg-danger`
- Counter: `text-xs font-mono` — normal: `text-text-muted`; breach: `text-danger font-bold`
- Breach badge: `bg-danger text-white text-[10px] px-1 rounded font-bold` (red `!` indicator)

**Thresholds (from RESEARCH.md open questions — planner to confirm in PLAN):**
- audit: 10,000 rows (default, env-override: SKILLFORGE_AUDIT_CAPACITY)
- kpi_calls: 50,000 rows (SKILLFORGE_KPI_CALLS_CAPACITY)
- report_runs: 5,000 rows (SKILLFORGE_REPORT_RUNS_CAPACITY)

**States:**
- Normal: primary fill, muted counter
- Warning (>= 80% of threshold): counter turns --color-status-needs-info (amber)
- Breach (>= threshold): danger fill, danger counter + red badge `!`

### 3. ImportBatchList (View 1)

**Data:** `GET /api/admin/batches` → `ImportBatchRow[]`

**Fields per row:** `batch_id`, `dataset`, `status` (pending/running/completed/failed), `desensitized_row_count`, `raw_size_bytes`, `discard_ts`

**Layout:** Table with columns: Dataset | Status badge | Row Count | Raw Size | Discarded At | (no actions — read-only)

**Status badges:**
- pending: amber (#fbbf24)
- running: amber with subtle pulse animation
- completed: green (#34d399)
- failed: red (#f87171)

**Row hover:** `hover:bg-surface-2` transition

**Empty state:** "暂无导入批次" heading + "数据导入后将显示在此处" body

### 4. KPIDefinitionList (View 2)

**Data:** `GET /api/admin/kpis` → `KPIRow[]` (signature + latest_calls map)

**Fields per row:** `func_name`, `signature` (monospace), `last_call_at` (relative time), `call_count`

**Layout:** Table with columns: Function Name | Signature | Last Called | Call Count

**Read-only enforcement:** No edit button, no kebab menu. Files are sole source of truth.

**Empty state:** "暂无 KPI 定义" heading + "在 kpis/ 目录添加 YAML 文件注册新 KPI" body

### 5. SkillManagementList (View 3)

**Data:** `GET /api/admin/skills` → `SkillRow[]` combining `GET /api/skills` + `eval/frozen/*.lock.json` overlay

**Fields per row:** `name`, `version`, `status` (ok/failed/pending), `last_eval_summary` (hover only — no inline badge), `last_change_at`

**Eval result interaction:** Hover over `last_eval_summary` cell → tooltip showing:
- faithfulness score (e.g., "faithfulness: 0.94")
- context_precision (e.g., "context_precision: 0.91")
- eval timestamp

**Tooltip visual:** `bg-surface border-border rounded-md shadow-lg p-3 text-xs`. Not a badge. Not inline text.

**Hot-reload status icon:** `Circle` dot — green (ok), red (failed), amber (pending)

**Empty state:** "暂无注册 Skill" heading + "创建 skills/*.d/SKILL.md 注册新 Skill" body

### 6. ScheduledTaskList (View 4)

**Data:** `GET /api/admin/schedules` → `ReportRunRow[]` from `store.ListReportRuns`

**Fields per row:** `skill_id`, `cron_expr` (monospace), `last_run_status`, `last_fired_at`, `next_fire_at`, `drift_status`

**Layout:** Table with columns: Skill | Cron 表达式 | 上次运行 | 状态 | Drift | 下次执行

**Drift badge:** If `drift_status === 'drifted'` → amber `drift` badge. Otherwise no badge.

**Read-only enforcement:** No edit/create/delete buttons.

**Empty state:** "暂无定时任务" heading + "在 Skill 的 report_schedule 字段配置调度" body

## Interaction Behaviors

### Tab Switching

- State: `adminSubroute` in Zustand store (`'batches' | 'kpis' | 'skills' | 'schedules'`)
- URL sync: On tab click, `window.history.pushState({}, '', '/admin')` with subroute in store only (no sub-path segment, unlike `/eval/audit`)
- Mount sync: `useEffect` reads `window.location.pathname` on mount and sets `adminSubroute`
- Tab bar uses `SubrouteTab` component (copied from EvalDashboard inline function, NOT a separate file)

### Hover Tooltips (SkillManagementList eval results)

- Trigger: `mouseenter` on the `last_eval_summary` cell
- Dismiss: `mouseleave` from the cell or tooltip itself
- Positioning: tooltip appears above the cell (placement: top), constrained within viewport
- Delay: 200ms hover delay before showing (avoids flash on mouse pass-through)
- No keyboard equivalent (eval results are supplementary, not required for accessibility)

### Capacity Bars

- Refresh: Fetched on mount of AdminDashboard (no polling — admin console is for manual monitoring)
- Breach badge: Red `!` badge appears to the right of the count when `currentCount >= threshold`
- No click/hover interaction on the bar itself (monitoring indicator only)

### Read-Only Enforcement

- No POST/PUT/DELETE buttons anywhere in the four views
- No inline edit icons (pencil) on KPI or schedule rows
- Source-grep lock in plan: `grep -cE "POST|PUT|DELETE|PATCH" admin_*.go` must return zero for all four admin BE handlers

## Accessibility

### Tab Accessibility (ARIA)

- `role="tablist"` on the nav container
- Each tab: `role="tab"`, `aria-selected={active}`, `data-state="active|inactive"`
- Keyboard: Tab key moves focus to tab list; Arrow keys navigate between tabs (native button behavior)
- Focus ring: `focus-visible:ring-2 focus-visible:ring-primary focus-visible:ring-offset-2 focus-visible:ring-offset-bg`

### Semantic HTML

- Tables use `<table>`, `<thead>`, `<tbody>` with `scope="col"` headers
- Status badges use `<span>` with `aria-label` (e.g., `aria-label="状态: 已完成"`)

### Capacity Bars

- Each bar: `role="meter"` with `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax={threshold}`, `aria-label="{tableName} capacity: {currentCount} of {threshold}"`
- Breach state: `aria-label` includes "BREACH" warning

### Keyboard Navigation

- All interactive elements (tabs, buttons) are keyboard accessible via native focus
- No custom keyboard shortcuts for this phase (avoids conflicting with browser/OS)
