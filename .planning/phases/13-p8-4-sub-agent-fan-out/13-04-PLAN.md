## Design Rationale

**Why a 9-stage hermetic gate (not a simpler "run all tests" check)?** Phase 11's 11-stage gate + Phase 12's 11-stage gate are the proven templates — the granular stages localize failures. If a regression appears ("D15 wire-type drift detected"), the gate Stage 6 prints the precise stage label + last 20 lines of context. A single `go test ./...` would dump thousands of test lines without pinpointing the regression category. The 9 stages mirror Phase 12's gate (12-08) with adjustments for Phase 13's specific concerns (sub-agent budget half-cap + accumulator LRU + NewParallel ban).

**Why separate Stage 4 for `NewParallelAgent` source-grep?** P13-L1 sealed sentinel + source-grep is a fast O(N) check that catches the architectural violation before any test runs. If a future executor copy-pastes from `prebuilt/supervisor` and uses `NewParallelAgent`, Stage 4 fails in <1 second with the file:line of the violation — the test runner never gets a chance to run.

**Why keep `eval/frozen/compliance.lock.json` UNCHANGED?** T-8-12 (re-generating lock = tampering baseline) — Phase 8's compliance lock is the v0.8 frozen baseline; Phase 13 ADDS fanout.lock.json as a NEW v0.8 milestone re-baseline. Two locks coexist: compliance.lock.json (Phase 8 pin) + fanout.lock.json (Phase 13 v0.8 milestone). Cross-phase verification proves neither has been tampered with.

**Why STRIDE-13 mirrors STRIDE-12's structure (8 threats)?** Phase 11/12 threat models follow the same template — TRUST BOUNDARIES table + STRIDE register + reference patterns. The 8 threats in STRIDE-13 map directly to P13-L1..L9 architectural decisions + RESEARCH §Pitfall 1..8. Future maintainers can compare STRIDE-11/12/13 side-by-side to understand how the threat surface evolved across phases.

**Why `WalkDir` 8 roots (not 6 from Phase 12)?** Phase 12 scanned: `internal/agent/callbacks/`, `internal/agent/tools/`, `internal/agent/hitl/`, `internal/server/`, `web/src/**` (5) + `internal/runtime/` (1 — Phase 12 added for deep_agent.go).
