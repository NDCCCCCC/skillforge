## Design Rationale

**Why manual `errgroup` instead of eino's `adk.NewParallelAgent` (P13-L1)?** `NewParallelAgent` shares parent's `runSession.Values` via `forkRunCtx` at `adk/runctx.go:478-508` — a prompt-injection attack on a sub-agent could expose parent's session values. Manual `errgroup` + per-Run agent construction (via `BuildSubAgent` from 13-01) bakes tier-closure into Tool closures at construction time, making it structurally impossible for sub-agents to read parent's session state. This is the load-bearing FAN-02 invariant.

**Why per-goroutine `defer recover()` + never propagate to errgroup?** FAN-01 SC-1 explicitly requires "fault isolation": a panic in one sub-agent must not kill the parent Run. The `defer recover()` converts the panic into a `Status: faulted` SubAgentResult with `FaultedReason`. The goroutine returns `nil` to errgroup (NOT the panic error) so the parent Run sees completion + the conservative merge treats `faulted` as refusal-equivalent (FAN-03 SC-4). This is the canonical Pitfall 4 mitigation.

**Why per-sub-agent `ApplyTrustStage` (FAN-04 SC-4)?** The Phase 12 unified exit (`ApplyTrustStage` in `internal/runtime/trust_stage.go`) is the single funnel for citation entailment verification — REUSED UNCHANGED. Each sub-agent's output runs through ApplyTrustStage independently before merge; the shared `*ChunkAccumulator` (P13-L9) provides the citation whitelist (parent seed retrieval + union of sub-agent retrievals, LRU-capped at 20). Per-sub-agent grounding catches ungrounded citations at the sub-agent level — before they can pollute the merged verdict.

**Why D16 overload on `data-decision` instead of new `data-fanout-trace` SSE chunk?** RESEARCH §Alternatives Considered + P13-L7 decision. The `data-decision` discriminator is the existing AI SDK v5 native routing path for orchestrator events (Phase 12 P12-L3 added `forced_stop` to the same discriminator; Phase 12 12-03 added `plan_approved`/`plan_denied`). New chunk types = D15 alarm reset cost (paired Go + TS commits + new union members); overload = 3 enum additions on the existing path. The FE agent state inspector (Phase 5 SC-4) already routes `data-decision` events into the timeline; the 3 new values render inline without new components.

**Why `run_path` as TEXT slash-separated (not JSON array)?** RESEARCH §Open Question 4 + RESEARCH recommendation. TEXT simpler for SQL queries: `SELECT * FROM audit WHERE run_path LIKE 'parent_run/%' ORDER BY ts` returns the full fan-out trace without parsing JSON. The index `idx_audit_run_path` keeps the query O(log N). JSON would require a parse + array_to_string round-trip per row.

**Why ADD COLUMN migration (not new `fanout_events` table)?** RESEARCH §Alternatives Considered + P13-L6 decision. Same audit query path + retention redaction applies uniformly (Phase 6 SC-5). New table = cleaner SELECT but needs JOIN for `AuditTimelineTab`. ADD COLUMN = same SELECT, one extra index. The trade-off favors ADD COLUMN for v0.8 (simpler for the milestone and matches existing patterns).
