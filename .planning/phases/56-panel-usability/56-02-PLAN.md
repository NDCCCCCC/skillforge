<objective>

Phase 56-02: 匹配引擎 + 审批决策路径接线——把 56-01 的 policy 表接进真实的规则生命周期：审批时创建规则（修复「CreateRule 零调用点」）、Pass-1 三级匹配（exact/prefix/template × session>skill>global）、命中递增 + approval_rule_hits 审计行、对话流 rule-matched 系统事件（D-56-02：命中必须可见）。

语义（锁定，UI 文案与测试都以这为准）：
- **exact**：`sha256(args 逐字节)` 相等（现状语义保留，args_hash 只作索引，D-56-01）。
- **prefix**：`args_pattern`（JSON object，锁定字段→期望值）——传入 args 解析为 object 后每个锁定字段存在且值深相等，未锁定字段自由（「锁定字段+自由字段」；命名承 Claude Code `Bash(cmd:*)` 直觉）。
- **template**：仅 target 层匹配（同 tool 一律放行），参数全自由。
- 优先级：scope session > skill > global；同层 specificity exact > prefix > template；同 specificity 的 prefix 取锁定字段数多者；再平取 created_at 早者、id 小者。**同层 deny 语义保持：deny/request_change 永远一次性，不存在 deny 规则，规则只自动放行。**

</objective>

2. `MatchRuleForArgs(ctx, req MatchRequest) (*ApprovalRule, MatchStats, error)` 实现：
   - 候选集：ListActiveRulesForTarget(target, skillID, sessionID)。
   - 逐条求值（in-Go，不进 SQL）：exact → `rule.ArgsHash == req.ArgsHash`；prefix → `json.Unmarshal(req.ArgsJSON)` 成 object 且 `prefixMatch(parsed, rule.ArgsPattern)`（pattern Unmarshal 失败或非 object → 该规则按不匹配跳过并计数，不报错）；template → 无条件匹配。
   - prefixMatch：pattern 的每个 key 在 parsed 中存在且值 `reflect.DeepEqual`（标量/同型才可能相等；嵌套 object 值做 DeepEqual）；parsed 顶层非 object（数组/标量）→ 不匹配。
   - 全部候选不匹配或 ArgsJSON 非 JSON → `(nil, stats, nil)`——**no-match 是正常返回不是错误**（引擎层错误只会来自 store I/O）。
   - 优先级评分：scope(0/1/2) ASC → specificity(exact 0/prefix 1/template 2) ASC → 锁定字段数 DESC → created_at ASC → id ASC，取第一条；MatchStats{Candidates, Matched, ChosenRuleID, ChosenScope, ChosenMatchType} 供测试与日志。
3. deny 语义注释钉在函数头：规则表只表达「放行策略」，deny 永远走 operator 一次性决策（D-56-01）。
</action>
