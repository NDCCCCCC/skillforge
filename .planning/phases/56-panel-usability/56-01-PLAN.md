<objective>

Phase 56-01: `approval_rules` 表升级——把「args_hash 精确哈希 + 二元 scope」的死规则表升级为 D-56-01 的 policy 条目表（match_type 三级 + scope 三层 + TTL/开关/命中统计/来源）。

根因（已实证，本 plan 只修 schema 层）：
1. `CreateRule` 在生产代码**零调用点**（`internal/server/approval_api.go::executeApprovalResume` 只写 audit resolution 行，`decision.Scope` 从不落地成规则）——规则绝育第一层（创建接线在 56-02）。
2. `matchRuleSQL` 是 `args_hash = ?` 精确相等——LLM 每次参数不同，规则永不复命中——绝育第二层（匹配引擎在 56-02）。
3. D11-D3 二元 scope（session/skill）无 global、无 TTL、无开关、无命中统计——面板无法运营——绝育第三层（**本 plan 修这层**）。

Output: 重建后的 `approval_rules` 表 + 新 `approval_rule_hits` 命中审计表 + store 层新 surface + `GET/DELETE /api/session/:id/approval-rules*` wire 升级（56-02/56-03 在此之上接引擎与面板）。

</objective>

```sql
CREATE TABLE IF NOT EXISTS approval_rules (
    id               INTEGER PRIMARY KEY AUTOINCREMENT,
    target           TEXT NOT NULL,
    match_type       TEXT NOT NULL DEFAULT 'exact'
                     CHECK (match_type IN ('exact','prefix','template')),
    args_hash        TEXT NOT NULL DEFAULT '',  -- D-56-01：exact 的索引列，不再是唯一键
    args_pattern     TEXT NOT NULL DEFAULT '',  -- prefix：锁定字段 JSON object；template：''
    skill_id         TEXT NOT NULL DEFAULT '',  -- global scope 允许 ''（跨 Skill）
    scope            TEXT NOT NULL DEFAULT 'session'
                     CHECK (scope IN ('session','skill','global')),
    scope_session_id TEXT NOT NULL DEFAULT '',  -- 仅 scope='session' 非空
    enabled          INTEGER NOT NULL DEFAULT 1,
    expires_at       INTEGER,                   -- NULL = 永久；epoch 秒
    origin           TEXT NOT NULL DEFAULT 'approve_remember'
                     CHECK (origin IN ('approve_remember','manual','seed')),
    hit_count        INTEGER NOT NULL DEFAULT 0,
    last_hit_at      INTEGER,                   -- NULL = 从未命中
    created_at       INTEGER NOT NULL DEFAULT (strftime('%s','now')),
    last_used_at     INTEGER NOT NULL DEFAULT (strftime('%s','now'))  -- 兼容列：与 last_hit_at 同步写，56-03 FE 切换后下个里程碑退役
);
CREATE UNIQUE INDEX IF NOT EXISTS idx_approval_rules_natural
    ON approval_rules(target, match_type, args_hash, args_pattern, skill_id, scope, scope_session_id);
CREATE INDEX IF NOT EXISTS idx_approval_rules_args_hash ON approval_rules(args_hash);
CREATE INDEX IF NOT EXISTS idx_approval_rules_scope     ON approval_rules(scope, scope_session_id);
CREATE INDEX IF NOT EXISTS idx_approval_rules_skill     ON approval_rules(skill_id);
```

2. 同一 schemaSQL 追加 `approval_rule_hits`（INSERT-only 命中审计账本，56-02 引擎写入）：

```sql
CREATE TABLE IF NOT EXISTS approval_rule_hits (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    rule_id           INTEGER NOT NULL,
    ts                INTEGER NOT NULL,
    session_id        TEXT NOT NULL,
    target            TEXT NOT NULL,
    tool_call_id      TEXT NOT NULL DEFAULT '',
    match_type        TEXT NOT NULL,
    matched_args_hash TEXT NOT NULL DEFAULT ''
);
CREATE INDEX IF NOT EXISTS idx_rule_hits_rule ON approval_rule_hits(rule_id, ts);
```

3. migrate() 内追加 legacy rebuild 步骤（**置于上述索引创建之前或之后均可，但索引语句必须在 rebuild 之后仍能幂等命中**——migrate_legacy_test.go 的地雷是「索引引用了只有迁移才加的列」，本例列全部在新 CREATE TABLE 里，rebuild 完成后索引语句才第一次执行；旧库路径：rebuild 先行 → 索引 IF NOT EXISTS 落地）：
   - 探测门：PRAGMA table_info(approval_rules) 不含 `match_type` 列 → 判定为旧四元组 PK 表。
   - 重建（SQLite 标准 ALTER 流程，事务内）：CREATE TABLE approval_rules_v2（新 DDL 去 IF NOT EXISTS 语义）→ `INSERT INTO approval_rules_v2 (target, match_type, args_hash, skill_id, scope, scope_session_id, created_at, last_used_at, last_hit_at) SELECT target, 'exact', args_hash, skill_id, CASE WHEN scope_session_id = '' THEN 'skill' ELSE 'session' END, scope_session_id, created_at, last_used_at, last_used_at FROM approval_rules`（旧行 origin 一律 'approve_remember'、hit_count=0、last_used_at 语义即"上次自动放行"→ 映射为 last_hit_at）→ DROP TABLE approval_rules → ALTER TABLE approval_rules_v2 RENAME TO approval_rules。
   - 旧行映射是旧 PK 上的单射，无重复合并风险；audit 表无对 approval_rules 的 FK，drop 安全。
4. 语义注释写进 schema.go：exact=参数逐字节一致；prefix=args_pattern 锁定字段+自由字段（命名承 Claude Code `Bash(cmd:*)` 直觉，落地为字段级模板）；template=仅 target 层匹配；deny 语义保持——**deny/request_change 永远一次性 operator 决策，不存在 deny 规则，规则只自动放行**（D-56-01 同层 deny 语义保持的落地解释）。
