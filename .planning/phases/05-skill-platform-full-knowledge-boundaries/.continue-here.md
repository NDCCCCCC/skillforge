# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **JS Number safety on Entry.Version** — `Entry.Version` MUST stay well under 2^53. The original `time.Now().UnixNano()` (~1.7e18) + the `reloadOne` `prev.Version+1` bump were INVISIBLE to the JS polling client (double ULP ≈ 512 at 1.7e18), so reloads could never be detected. Fixed with a per-process `atomic.Int64` counter from 1. **Do not re-introduce UnixNano.** The counter is load-bearing for the whole feature.
- [ ] CONSTRAINT: **Keep-old failure contract** — on a validation/symlink failure, `Entry.Version` AND the manifest MUST stay unchanged, and the `loadError` hook MUST fire. Pinned by `TestRegistry_Reload_ValidationFailure_KeepsOld` (T4) + `_SymlinkEscape_Rejected` (T6). Failures surface ONLY via the new `failed` map → `status:"failed"` overlay; they must NEVER bump the version. Bumping version on failure breaks both tests and the semantic.

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| UnixNano Version base | Version base > 2^53 makes `+1` reload bumps invisible to JS polling → feature silently dead | blocking | Per-process `atomic.Int64` counter (`nextVersion()` from 1). Re-introducing `time.Now().UnixNano()` anywhere on the Version path re-breaks the feature — grep for it before committing. |
| Version bump on failure | Bumping `Entry.Version` in the `reloadOne` error path violates the keep-old contract (T4/T6) | blocking | Error path calls `r.setFailed(name, err)` then the existing `loadError` hook and returns WITHOUT touching the snapshot or Version. Success path (after `snapshot.Store`) calls `r.clearFailed(name)`. |
| gopls "file not in workspace" diagnostics | LSP emits these from stale worktree/module detection; they are NOT real compile errors | advisory | The real gate is `go build ./... && go vet ./... && go test`. Ignore LSP workspace-noise diagnostics; do not chase them. |
| Bundling unrelated drift into the §2 code commit | STATE.md + config.json have pre-existing unrelated drift (CRLF + continuity tweak) | advisory | Stage explicit files only for the §2 atomic commit (`registry.go` + the new files). Never `git add -A`. |
