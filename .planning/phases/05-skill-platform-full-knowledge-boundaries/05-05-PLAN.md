<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| useChat.messages -> AgentInspector | The inspector is a derived view of the chat stream. A malicious FE modification could inject bogus parts; the wire chunks themselves are the BE-trust surface (Phase 4). |
| /api/knowledge/graph -> FE | The graph data source is retriever metadata. effective_to values come from operator-indexed frontmatter; KNOW-02 indexer validation is the trust gate (05-02). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-21 | Spoofing | Inspector renders tool-call args via dangerouslySetInnerHTML | mitigate | InspectorToolCall renders args as text via React's default text-node rendering. JSON args are stringified with indentation. NEVER inject HTML. |
| T-5-22 | Tampering | Graph browser loads full chunk text into the browser via the metadata endpoint | mitigate | Graph endpoint returns metadata only (id, filename, effective_*, version). Chunk verbatim opens in ChunkSourceView via a separate, auth-gated chunk endpoint. The graph does NOT contain chunk content. |
| T-5-23 | Information Disclosure | Version badge reveals the effective_to date (could leak internal policy timing) | accept | The effective_to date is operator-authored metadata per KNOW-02 + indexer validation. Surfacing it is the explicit SC-8 requirement. No additional sensitivity gating needed (the policy itself is already public to the FE via ChunkSourceView). |
| T-5-24 | Spoofing | Inspector hop border could be applied to ANY hop (visual lie) | mitigate | The active hop detection uses the actual in-flight state (useChat.status==='streaming' and the hop is the last one). The border is a UI hint, not a security boundary. |
</threat_model>
