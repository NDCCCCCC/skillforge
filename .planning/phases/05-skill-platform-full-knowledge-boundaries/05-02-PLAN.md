<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Skill selection -> routed Skill's authority tier | Router picks a Skill; the routed Skill's reads[] drives the retriever's tier filter. A mis-routed Skill should NOT widen the tier surface; per-Skill isolation is preserved. |
| Document frontmatter -> retriever.Document fields | Operator-authored frontmatter (effective_from/to) becomes retriever state. The indexer is the trust boundary for these values — validate BEFORE write. |
| Retriever PRE-filter -> Verdict grounding | The effective_to filter must NOT widen what the verdict can ground on. Tier filter still wins; effective is co-layered, not a substitute. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-5-06 | Elevation of Privilege | Router picks wrong Skill -> cross-tier leakage | mitigate | Router selects the Skill, but VerdictPipeline still runs the routed Skill's `reads[]` through the existing D-09 tier filter. The routing decision cannot bypass tier enforcement. Per-Skill isolation is preserved structurally. |
| T-5-07 | Tampering | Indexer accepts a forged effective_to that suppresses current policy | mitigate | Indexer validateEffective rejects `effective_to < 0` and `effective_to < effective_from` (when both nonzero). Authority tier remains append-only per architecture §3.4. Audit row records the effective window of every retrieved chunk. |
| T-5-08 | Information Disclosure | Milvus NULL-evaluates-FALSE bug erases perpetual chunks | mitigate | Sentinel 0 design (NOT nullable). No NULL semantics in the filter. Milvus field has `Nullable:false`. Backward-compat: existing chunks (no effective_*) get 0 default and pass. |
