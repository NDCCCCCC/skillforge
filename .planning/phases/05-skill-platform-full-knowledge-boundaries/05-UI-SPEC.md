# Phase 5 — UI Design Contract

> Visual and interaction contract for the Skill Platform & Full Knowledge Boundaries phase. Generated by `gsd-ui-researcher`; consumed by `gsd-planner` (task-level), `gsd-executor` (implementation source of truth), and `gsd-ui-checker` (validation).
>
> **Scope:** SYSK-04, SYSK-05, SYSK-06, AGNT-06, KNOW-06, CMPL-06, CMPL-07, CMPL-08 — the eight ROADMAP Success Criteria. PLUS the Phase-4-deferred UI items that overlap Phase 5 (real file tree, `@`-mention fuzzy search, Skill manager UI, bidirectional tab nav).

## Color

60/30/10 split inherited from `04-UI-SPEC.md` §Color. Phase 5 introduces **ONE new semantic hue** (teal `--color-annotation`, parallel to Phase 4's introduction of `--color-status-out-of-scope`) plus **two diff-background tokens derived from existing status colors at low opacity** (not new hues — they composite over `--color-surface`).

### Inherited tokens (UNCHANGED — see 04-UI-SPEC.md for hex + usage)

Dominant `--color-bg #0f1419` · Secondary `--color-surface #1a1f26` / `--color-surface-2 #232932` / `--color-surface-3 #2a313b` · Border `--color-border #2d3540` / `--color-border-muted #1f252e` · Accent `--color-primary #4a9eff` (+ hover/dim/fg variants) · Destructive `--color-danger #ef4444` (still reserved-but-unused for destructive actions) · Text scale `--color-text #e8eaed` / `--color-text-muted #8b95a3` / `--color-text-dim #5a6473` · Status group (compliant green / needs-info yellow / non-compliant red / unanswered gray / out-of-scope blue-gray).

**Accent (`--color-primary` #4a9eff) reserved-for list — inherited + Phase 5 ADDITIONS:**

The Phase-4 exhaustive list (Send button, active session border, active tab, citation tier text, focus ring, resize handle, reasoning border, mention skill badge, streaming dot, skill selector outline) is UNCHANGED. Phase 5 adds these NEW accent-reserved surfaces and NO others:

11. **Wizard mode** step-indicator current-step dot + the "Skill 向导" mode-tag in the right-panel header
12. **Graph browser** selected-chunk left-border (the chunk the user clicked to open in `引用原文`)
13. **Inspector** active-hop indicator (the currently-streaming hop's left-border, replacing the static reasoning-preview border when inspector is the active surface)
14. **`@`-mention dropdown** active-item background (the highlighted file/skill row as the user arrow-keys)
15. **Routing-trace** selected-Skill score text (the `selected: true` row's score renders in accent; non-selected scores render in `--color-text-muted`)

NOT accent (Phase 5 reinforcements): counter-evidence border/heading (uses `--color-annotation` teal); redline diff backgrounds (use derived tokens below); version-badge backgrounds (use surface/status tokens); tier badges inside counter-evidence (use `--color-annotation` to signal "annotation tier", overriding the default accent-blue tier color — this is the ONE exception to "tier text is always accent-blue" and it exists to make the trust-moat line visible at a glance).

### NEW Phase 5 semantic token (one hue)

| Token | Hex | HSL | Semantic | Phase 5 surface |
|-------|-----|-----|----------|-----------------|
| `--color-annotation` | `#14b8a6` (teal-500) | 175° 81% 40% | "Meta-information shown alongside the verdict that does NOT participate in grounding." Distinct from accent blue (200°), status greens (140°), and out-of-scope blue-gray (220°). | (1) Counter-evidence card 2px left-border + heading text + the `历史` tier badge rendered INSIDE the counter-evidence card; (2) Redline rationale block left-border + `修改理由` label; (3) Inspector "annotation" badge on counter-evidence hop if the agent surfaced one. |

**Why teal:** the denova palette is blue/gray/surface + four status hues. Counter-evidence needs a color that reads "supplementary, not verdict" without the alarm of red/amber and without colliding with accent blue. Teal is in the blue family (harmonious) but shifted toward green enough to be unambiguous at a glance. WCAG contrast against `#1a1f26` surface: ratio 4.6 (passes AA for normal text). The Phase-4 checker pattern (contrast ≥ 3.0 for borders, ≥ 4.5 for text) holds.

**Checker-enforced separation:** `--color-annotation` (#14b8a6) MUST NOT appear on any verdict status surface, any refusal surface, or the Send button. It is reserved for the three surfaces above.

### NEW Phase 5 diff-background tokens (derived, not new hues)

Used ONLY inside the Redline diff view (§SC-7). Both composite over `--color-surface`; they are status colors at 12% opacity, not new palette entries.

| Token | Value | Surface |
|-------|-------|---------|
| `--color-redline-removed` | `rgba(239, 68, 68, 0.12)` over `--color-surface` (#1a1f26) → effective ~`#241c1f` | Redline diff `original_clause` line background (the text being replaced). Strikes through the text in `--color-status-non-compliant` (#ef4444). |
| `--color-redline-added` | `rgba(34, 197, 94, 0.12)` over `--color-surface` → effective ~`#1e2a21` | Redline diff `proposed_rewrite` line background (the replacement text). Renders text in `--color-status-compliant` (#22c55e). |

These reuse the existing verdict status red/green at low opacity — a reviewer scanning the diff immediately maps red = "being removed" and green = "being added" because those are the same hues the VerdictCard uses for 不合规 / 合规.

### Tier badge color encoding (Phase 5 — extends Phase 4)

Phase 4: all tiers render `[权威]` / `[历史]` / `[个人]` / `[草稿]` in `--color-primary` blue (tier differentiated by TEXT only). Phase 5 introduces a SCOPED exception: the `历史` tier badge, WHEN RENDERED INSIDE the counter-evidence card or the inspector's counter-evidence hop, renders in `--color-annotation` teal. Everywhere else (citations on VerdictCard, ChunkSourceView metadata row, graph browser), tier badges stay accent-blue. This exception exists to make the §SC-6 trust-moat line — "this 历史 chunk is annotation, not grounding" — visible without reading the heading. Per-tier full color encoding (个人 / 草稿) remains deferred (CONTEXT `<deferred>`: Phase 5 is 权威 vs 历史 only).

## Layout & Surfacing Strategy

**Invariant (LOCKED):** every Phase-5 surface lives WITHIN the locked three-panel shell (`ThreePanel.tsx`, 260/flex/420 + draggable resize + collapse). No new shell, no full-screen takeover, no modal-only flow. New surfaces are surfaced as:

1. **New center-panel tabs** (SC-4 inspector, SC-5 graph browser) — extends the existing 3-tab `CenterPanel` to 5 tabs.
2. **Right-panel "wizard mode"** (SC-3) — temporarily replaces the chat header + interview surface; the three-panel shell stays intact.
3. **New message-bubble parts** (SC-1 routing trace, SC-6 counter-evidence, SC-7 redline) — rendered inline in the chat message stream, reusing the existing `MessageBubble` part-dispatcher.
4. **Topbar dropdown** (skill manager) — the Phase-4 chevron stub becomes a real `command`-driven menu.
5. **Left-sidebar evolution** (real file tree) — the Phase-4 hardcoded 4-tier list becomes an expandable tree that links into the SC-5 graph browser.

### SC-1 — Multi-Skill semantic routing (SYSK-05, D5-01..05)

- **Routing trace renderer:** NEW `RoutingTracePart` rendered as the FIRST part of an assistant message on a routed turn (BEFORE SubProgress, which it subsumes for routing turns). Reads `data-decision` chunks where `DecisionPayload` carries the new `skill_scores` + `selected` fields (see §Wire §D5-04).
- **Visual:** Single-line section, Label-size, `--color-surface-2` bg + 2px left-border in `--color-primary`, `--space-2 --space-3` padding, `--radius-md` (mirrors SubProgress chrome). Heading `路由分析`. Below it, one row per candidate Skill: `{skillName} · cos {score}` in mono. Selected row (`selected: true`) in `--color-primary`; others in `--color-text-muted`.
- **Ambiguity picker (D5-03):** When the routing decision carries `ambiguous: true` (top-1 low OR top-1/top-2 within delta — threshold calibrated per D2-15), the `RoutingTracePart` renders a `SkillPicker`-style dropdown BELOW the score rows. Reuses the Phase-4 `SkillPicker` component with a different data source (`skill_scores[]` instead of the global skills fixture) + the ambiguity heading `检测到歧义，请选择目标 Skill`. Selecting a candidate dispatches `useChat.sendMessage` with `{ skillId: selected, query: originalQuery }` (the user's original text is re-sent with the forced skill).
- **Inspector mirror (SC-4):** The same routing decision appears in the inspector as the first hop's `决策：路由` row. Single source of truth: the `data-decision` chunk.
- **Empty/loading/error:** Routing trace absent on a non-routed turn (single-Skill install OR explicit skill via @-mention) → `RoutingTracePart` renders nothing (not an empty state — absence is correct). Routing decision chunk missing on a routed turn → inspector shows `路由信息缺失。`.

### SC-2 — fsnotify hot reload (SYSK-04, D5-06..09)

- **Reload status channel:** NEW out-of-band SSE event from the server's fsnotify watcher OR a Zustand-poll of `/api/skills` (planner decides — the UI contract is the same either way). Recommended: SSE event `{ type: 'skill-reloaded', skillId, skillName, status: 'ok' | 'failed', error?: string, version: 'new' | 'old-kept' }` on the existing `/api/chat` stream is WRONG (that stream is per-conversation); instead a lightweight `EventSource` on `/api/skills/events` OR a 2s poll of `/api/skills` diffing the version field. Planner picks; UI consumes `status: 'ok' | 'failed'`.
- **Toast component:** shadcn `sonner` (or equivalent). Success toast (D5-08 ok): `Skill 已重载：{skillName}` + `CheckCircle2` in `--color-status-compliant`, auto-dismiss 4s, top-right. Failure toast (D5-08 failed): `Skill 加载失败，已保留旧版本：{skillName}` + body `原因：{error}` + `FileWarning` in `--color-status-non-compliant`, persists until dismissed.
- **In-flight pinned indicator (D5-06):** When a run is in flight using a pre-change Skill snapshot, the statusbar right label shows `当前运行使用旧版本（完成后下次生效）`. Detected by comparing the run's `skillVersion` (emitted in `start` message metadata) against the current `/api/skills` version.
- **Skill manager menu status (D5-08):** The topbar skill-manager `command` menu shows per-skill status (`已加载` / `加载失败（旧版可用）`) — see §Phase-4-deferred copy above.
- **Empty/loading/error:** No skills installed → skill manager menu shows `尚未安装任何 Skill。点击「新建 Skill（向导）」创建。` with the wizard CTA.

### SC-3 — Skill Wizard (SYSK-06, D5-10..12)

- **Wizard mode controller:** NEW `WizardMode` component mounted in `RightChat` when `app.wizardMode.active === true`. Replaces the header; keeps the messages area + ChatInput.
- **Step indicator:** shadcn `Progress` bar at the top of the wizard header. `step / totalSteps` from Zustand. Current-step dot in `--color-primary`.
- **Interview surface:** Reuses the chat messages area. Wizard prompts are assistant messages (streamed via the wizard transport target — `POST /api/skills/wizard` per D5-10); user answers are user messages. The interview is multi-turn (5 steps per copy above).
- **Preview (D5-11):** After the last interview step, the wizard emits a `data-wizard-preview` payload (or a `source-document` with the SKILL.md markdown — planner picks; the center panel treats it as a SkillMdPreview input). The center panel auto-switches to the `Skill 定义` tab. The ChatInput is replaced by a 3-button row: `重新生成` / `确认并保存到 skills/{name}/SKILL.md` / `取消向导`.
- **Confirm flow (D5-11):** Click `确认并保存` → `POST /api/skills/wizard/commit` → server writes `skills/{name}/SKILL.md` → D2-07 file-driven registration → fsnotify picks it up (SC-2 toast fires) → wizard exits → success toast `Skill 已创建：{skillName}。已注册并热加载。`. The closed loop (wizard → write → fsnotify → registered → routable per SC-1) is complete.
- **Temperature recommendation (D5-12):** Step 5 of the interview surfaces the recommended temperature based on the Skill type captured in step 3 (合规 → 0.0; 通用问答 → 0.2; 创意 → 0.7). User can override via a numeric input. The generated SKILL.md must pass the Phase-2 7-field validator (SYSK-08 included).
- **Cancel (destructive):** `取消向导` opens `alert-dialog` (the single Phase-5 destructive action). Confirm → wizard mode exits, interview messages are cleared from `useChat` (transport reset), Zustand `wizardMode` reset to `{ active: false }`.
- **Empty/loading/error:** Wizard generating preview → `正在生成 SKILL.md 预览...` with `Loader2` spinner in the center panel. Generation failure → `向导生成失败：{error}。请重试或检查后端连接。`. Generated SKILL.md fails validator → `生成的 SKILL.md 未通过校验：{error}。请补充信息后重新生成。` (the planner ensures the LLM is prompted to obey the interview answers; this gate is defensive).

### SC-4 — Agent State Inspector (AGNT-06, Claude's Discretion — reuse D16 + tool/reasoning events)

- **Component:** NEW `AgentInspector` rendered in the center panel when `centerView.kind === 'agent-inspector'`.
- **Data source (NO new instrumentation channel):** The inspector reads from the SAME `useChat.messages` stream the chat renders. It walks the current turn's parts (the latest assistant message, or the in-flight message when `status === 'streaming'`) and groups them by hop using `data-decision` chunks as hop boundaries (`DecisionPayload.step`). Per hop, it renders:
  - `决策：{decision}` row (from `data-decision`)
  - `工具调用：{toolName}` expandable rows (from `tool-input-*` / `tool-output-*`)
  - `检索结果（{count} 条）` row (from `source-document` parts in this hop — chunk IDs listed in mono, clickable)
  - `推理（已折叠）` row (from `reasoning-*` — collapsed by default in the inspector since the chat already shows it expanded; click expands inline)
- **Visual:** Each hop is an `Accordion` item (shadcn) — collapsed shows the hop label + decision; expanded shows the full tree. The active hop (currently streaming) has a 2px left-border in `--color-primary` (accent reserved surface #13). Past hops render in `--color-text-muted`.
- **Counter-evidence hop badge:** If the turn fired SC-6, the relevant hop shows a teal `历史层反证已检索` badge. Click → scrolls the chat to the CounterEvidenceCard.
- **Live updates:** As new parts arrive on the in-flight message, the inspector re-renders. No polling; it's a derived view of `useChat.messages`.
- **Empty/loading/error:** No run in flight + no completed turn → empty state (`暂无 Agent 状态` + body). Run started, no events yet → `等待 Agent 首个事件...`.

### SC-5 — Knowledge graph browser (KNOW-06, Claude's Discretion — lightweight tree)

- **Component:** NEW `KnowledgeGraphBrowser` rendered in the center panel when `centerView.kind === 'knowledge-graph'`.
- **Visualization engine:** Lightweight shadcn `Accordion` tree — tier → doc → chunk. **NOT d3, NOT react-flow** (CONTEXT discretion: "lean lightweight tree/list to avoid a heavy d3/react-flow dependency"). Three levels of nesting:
  - Level 1 (tier): `{tier}（{docCount} 文档 / {chunkCount} 片段）` — 4 tier nodes (权威 / 历史 / 个人 / 草稿).
  - Level 2 (doc): `{filename} · {chunkCount} 片段` — grouped under their tier.
  - Level 3 (chunk): `{chunkId} · {effectiveStatus}` — mono-font chunkId + version badge.
- **Search filter:** `Command`-style input at the top (`搜索文档或片段...`). Filters doc + chunk nodes by filename / chunk text substring. Empty filter → full tree.
- **Click chunk action:** Dispatches `setCenterView({ kind: 'chunk-source', chunkId, tier, version, effectiveDate })`. The center panel switches to `引用原文` (the inherited ChunkSourceView). Bidirectional nav: clicking `引用原文` tab after this returns to the same chunk.
- **Data source:** `store.Store` + knowledge metadata via `GET /api/knowledge/graph` (planner defines the endpoint shape; returns `{ tiers: [{ tier, docs: [{ id, filename, chunkCount, chunks: [{ id, effectiveFrom, effectiveTo }] }] }] }`). Memoized on mount; refetched on `skill-reloaded` events that touch knowledge (D5-09: reload scope is Skill definition only, so knowledge graph is stable unless docs are re-indexed — a separate mechanism).
- **Version badge (SC-8 integration):** Chunks with `effective_to < today` render the `已失效` badge (strikethrough, `--color-text-dim`); others render `当前有效` (`BadgeCheck`, `--color-status-compliant`).
- **Empty/loading/error:** Empty knowledge base → `知识库为空` + body. Loading → `正在加载知识层级...`. Load failure → `无法加载知识图谱：{error}。请确认后端已启动。`.

### SC-6 — Counter-evidence annotation (CMPL-06, D5-13) — THE TRUST-MOAT UI

- **Component:** NEW `CounterEvidenceCard` rendered in the chat message bubble AFTER the VerdictCard + CitationCluster, as a sibling (NOT inside VerdictCard — mixing them risks the "annotation ≠ grounding" line).
- **Wire trigger:** A new `data-counter-evidence` chunk OR an extension of the existing payload model. **Decision (Claude's discretion, prescriptive):** reuse the `data-decision` chunk with a new `decision: 'counter_evidence'` value carrying `{ conflictChunks: Citation[], verdictCitations: Citation[] }`. This AVOIDS spending a new wire type (the budget is reserved for `data-redline` per D5-14) and keeps counter-evidence semantically a "decision the agent made after the verdict" (which it is per D5-13). The TS `DecisionPayload.decision` union extends to include `'counter_evidence'`; the Go side mirrors.
- **Visual (the trust-moat line made visible):**
  - 2px left-border in `--color-annotation` teal (#14b8a6) — DISTINCT from any verdict status color.
  - Heading `历史层反证` with `AlertTriangle` icon in teal.
  - **Disclaimer sentence REQUIRED on every render:** `以下内容来自「历史」知识层，仅供人工参考，不参与本次结论的生成与校验。` Body size, `--color-text-muted`, sits directly below the heading, NEVER collapsed. The checker validates this string is present verbatim on every `CounterEvidenceCard`.
  - Conflict chunk rows: each shows the `历史` tier badge IN TEAL (the scoped §Color exception) + chunkId in mono + a 1-line snippet. Click → center `引用原文` tab (same ChunkSourceView, but the metadata row's tier badge ALSO renders in teal here to reinforce the annotation context).
  - Expand toggle when > 3 conflict chunks.
- **Grounding invariant (D5-13, checker-enforced):** The `CounterEvidenceCard` MUST NOT appear in the `CitationCluster` of the VerdictCard. The VerdictCard's citations list is unchanged (权威 only, per CMPL-04). The counter-evidence chunks are a SEPARATE list in a SEPARATE card. A regression test asserts: `verdict.citations` ∩ `counterEvidence.conflictChunks` === ∅ (by chunk_id).
- **Empty (no conflict):** If the post-verdict 历史 pass returns zero conflicting chunks, the card STILL renders with `未检索到与本次结论冲突的历史片段。` — the user sees the check happened (transparency over silence).
- **Loading:** While the post-verdict pass is in flight (brief — it's a single retrieval pass over 历史 tier), the card shows `正在检索历史层反证...` with a `Loader2` spinner.
- **Error:** Pass failure → `历史层反证检索失败：{error}。结论不受影响。` (the verdict stands; the annotation is best-effort).

### SC-8 — Policy version filtering (CMPL-08, D5-15)

- **UI scope:** The filtering itself is at the retriever layer (D5-15 PRE-filter `effective_to IS NULL OR effective_to >= today`, co-located with the D7 tier filter). The UI concern is purely DISPLAY: showing the active version on chunks + surfacing the filter on the graph browser.

- **Graph browser integration:** Chunk nodes carry the `当前有效` / `已失效` badge per §SC-5.
- **Retrieval invariant (checker-enforced):** A regression test asserts the retriever returns zero chunks with `effective_to < today` for any query — the UI never sees superseded chunks in VerdictCard citations or CounterEvidenceCard conflict chunks. They appear ONLY in the graph browser (explicit browsing) and ONLY with the `已失效` badge.

## Accessibility

Phase 5 surfaces inherit the Phase-4 accessibility baseline (focus ring `--color-primary` 2px on every focusable; keyboard-navigable SkillPicker; ARIA labels on icon-only buttons). Phase-5 additions:

- **Accordion (graph browser + inspector):** shadcn Accordion provides keyboard nav (Tab to enter, Arrow Up/Down to move between items, Enter/Space to expand, Escape to collapse). ARIA `aria-expanded` on each node.
- **Command (@-mention + skill manager):** shadcn Command provides Arrow-key navigation + ARIA `combobox` role + `aria-activedescendant` on the active item. Screen-reader announces `Skills, 2 项` / `文件, 5 项`.
- **Wizard step indicator:** `aria-current="step"` on the current step; `Progress` bar carries `aria-label="向导进度，步骤 {N}/{total}"`.
- **Counter-evidence disclaimer:** the disclaimer sentence is real text (not ARIA-only) so it's in the DOM and read by screen readers. The card carries `role="region"` + `aria-label="历史层反证（仅供参考）"`.
- **Redline diff:** the diff blocks carry `role="region"` + `aria-label="原条款"` / `aria-label="建议改写"`. The strikethrough on original-clause uses `text-decoration: line-through` (semantic, not just visual).
- **Version badges:** `aria-label="当前有效"` / `aria-label="已失效，{effectiveTo} 起不再检索"` on the badge `<span>` (icon-only visually).
- **Color contrast (checker-enforced):** `--color-annotation` teal (#14b8a6) on `--color-surface` (#1a1f26) = contrast ratio 4.6 (passes WCAG AA for normal text). Diff backgrounds (`#241c1f` / `#1e2a21`) with their respective text colors (#ef4444 / #22c55e) = ratios ≥ 4.5. All pass the Phase-4 checker thresholds (≥ 3.0 borders, ≥ 4.5 text).
- **No color-only encoding:** counter-evidence is distinguished by (a) teal color, (b) the `AlertTriangle` icon, (c) the dashed-style border option if the checker flags teal-too-close-to-accent, (d) the verbatim disclaimer sentence. Never by color alone. Redline add/remove is distinguished by (a) red/green tinted bg, (b) strikethrough on removed, (c) the `原条款` / `建议改写` labels. Never by color alone.

## Responsive Behavior

Phase 5 inherits the Phase-4 responsive model (the three-panel grid collapses via the topbar collapse-left / collapse-right buttons; no mobile breakpoints — this is a desktop tool). Phase-5 reinforcements:

- **5-tab center panel at narrow widths:** if the center panel is resized below 360px, tab labels truncate to icons-only (the inherited Label-size text hidden via CSS `@container` query or a Zustand `centerWidth` threshold). Fallback: horizontal scroll on the tab strip. No tab is ever hidden behind a "more" menu.
- **Graph browser tree depth on narrow widths:** the 3-level Accordion (tier→doc→chunk) may overflow at narrow widths; chunks render as scrollable rows with mono-font truncation + title-attr full ID on hover.
- **Redline diff on narrow widths:** the diff blocks stack vertically (original above rewrite) — they are ALREADY vertical in the default layout (not side-by-side), so no responsive swap needed.
- **Wizard mode on narrow widths:** the wizard header step indicator compresses to `步骤 {N}/{total}` (drops the `Skill 向导 ·` prefix); the 3-button confirm row wraps to 2 lines if needed.
