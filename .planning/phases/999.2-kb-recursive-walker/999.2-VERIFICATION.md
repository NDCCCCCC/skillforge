## Issues Discovered and Resolved Mid-Execution

1. **First server restart didn't pick up graph.go change**: I ran `go build ./internal/knowledge/` (package build, no binary output) thinking it would refresh `skillforge-server-dev-new`. The binary still had old code; only the next `go build ./cmd/server` actually produced a new binary. Resolved by always running the full `go build ./cmd/server` before restart.

2. **`strings.Cut` direction bug**: Wrote `rest, _, ok := strings.Cut(source, "/")` thinking `rest` was the "after" portion. Actually `strings.Cut` returns `(before, after, found)`, so `rest` was the `before` (tier slug). After this bug, `filenameOf("sql-guides/汽车险/037_xxx.md")` returned `"sql-guides"`. Resolved by switching to `_, rest, ok := strings.Cut(...)` and adding the `TestFilenameOf_PreservesSubdirectory` regression test.

3. **One transient test failure**: After massive parallel operations (server start + indexer + multiple Python file moves + API queries), `go test ./internal/knowledge/` returned FAIL once. Subsequent 3 runs all PASS. Likely resource contention. Not a code bug.

## Notes for Future Phases

- Walker recursion is now the standard behavior. Future KB additions can use subdirs freely without coordination.
- The `TestFilenameOf_PreservesSubdirectory` test pins the Cut direction — any future "I want to switch back to LastIndex" change must update this test.
- Chunk IDs reset on each restart (17-256 in this run; not 1-240). The sort stability guarantees same walk order, so references within a session are stable. Cross-session chunk ID references (audit rows, citation labels) would need additional coordination if introduced.
