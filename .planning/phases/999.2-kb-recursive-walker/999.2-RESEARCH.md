## Codebase Findings

### F1: 当前 walker 是 `filepath.Glob("*.md")` 平层扫描

`internal/knowledge/walk.go:85-142` 是 `WalkRegisteredDirs` 函数，**只扫 knowledge/ 下的第一级子目录**，注册表命中后才返回 slug 名。具体的文件 Glob 在 `indexer.go:154-180`：

```go
// internal/knowledge/indexer.go:155-157
pattern := filepath.Join(tierAbs, "*.md")
matches, err := filepath.Glob(pattern)
```

`Glob` 不递归，**任何子目录下的 .md 都不被发现**。这是当前架构真实限制，sql-guides 240 个文件必须平铺在 `knowledge/sql-guides/` 下。

### F2: indexer 已经用 `filepath.Rel` 算 source path，会自动保留子目录

`internal/knowledge/indexer.go:179-181`：

```go
rel, err := filepath.Rel(knowledgeDir, path)
if err != nil { return fmt.Errorf("knowledge.Index: relative path for %s: %w", path, err) }
relSlash := filepath.ToSlash(rel)
```

如果 walker 把 `knowledge/sql-guides/汽车险/001_xxx.md` 传给 indexer，`rel` 会自动等于 `sql-guides/汽车险/001_xxx.md`，Milvus 里 chunk 的 `source` 字段就是这个完整相对路径。**indexer 不需要任何改动**。

### F3: `ResolveReads` 按 `<slug>` 或 `role:<r>` 展开，subpath 部分被忽略

`internal/kb/registry.go:228-230`：

```go
top := read
if i := strings.Index(read, "/"); i >= 0 {
    top = read[:i]  // 只取第一个 slash 之前的 slug 部分
}
```

所以 Skill 写 `authority/operations/**` 或 `authority/**`，**两者都解析为 slug=`authority`**。当前没有 subpath 区分能力。我们本次不实现这个——Skill 不必关心子目录。

### F8: 现有 walker 三状态决策表必须保留

`internal/knowledge/walk.go:31-36` 注释：

```go
//	dir ∈ registry, active     → returned (the caller indexes it)
//	dir ∈ registry, deactivated → WARN + skipped, NO audit row
//	dir ∉ registry             → WARN + skipped + audit
//	non-directory entries      → ignored
```

`WalkDir` 改造不能破坏这四类。第一级子目录的注册表检查仍然在 `WalkRegisteredDirs` 里做，**WalkDir 替换的是 indexer.go:155 的 Glob 调用，不是 walk.go 的 WalkRegisteredDirs**。

## Patterns (from existing code)

### P1: WalkDir 标准用法（Go 1.16+）

```go
import "io/fs"

var matches []string
filepath.WalkDir(tierAbs, func(path string, d fs.DirEntry, err error) error {
    if err != nil { return err }
    if d.IsDir() {
        if path != tierAbs && strings.HasPrefix(d.Name(), ".") {
            return filepath.SkipDir  // skip hidden dirs
        }
        return nil
    }
    if !strings.HasSuffix(d.Name(), ".md") { return nil }
    matches = append(matches, path)
    return nil
})
sort.Strings(matches)
```

替代 `Glob("*.md")` 等价于现有行为 + 递归 + 隐藏目录跳过。

### P2: 排序稳定性（保留 chunk ID 确定性）

`internal/knowledge/indexer.go:158` 已有 `sort.Strings(matches)`。WalkDir 收集后用同样的 sort 保证 chunk ID 跨重启稳定。

## Risk Analysis

### R1: 重启后 chunk ID 变化（low risk）

Walker 顺序从「平层 *.md 排序」变为「递归 walk + 排序」。如果 Milvus 集合里已有旧 chunk（按旧 ID），新 walker 分配新 ID 会导致引用旧 ID 的 audit / chunk 链接断裂。

**Mitigation**:
- 重启前确认 chunk ID 不是 critical reference（看 project 代码，没有持久引用 chunk ID 的场景）
- 重启后验证 /api/knowledge/graph 显示的 chunk ID 是新的稳定序列

### R2: 重组 sql-guides 文件后，旧 audit 引用（low risk）

如果 audit 表里记录了 `source_path = "sql-guides/004_雇主责任险附加险.md"`，文件移到 `sql-guides/操作手册/004_雇主责任险附加险.md` 后，audit 引用失效。

**Mitigation**:
- Audit 表是历史记录，不用于运行时跳转
- 接受这个回归（如果发生）

### R3: WalkDir 性能（negligible）

`filepath.WalkDir` 是 Go 1.16+ 引入的 fs.WalkDirFunc 优化版本，比 `filepath.Walk` 快 ~3x。对 240 文件规模无影响。
