<decisions>

## Implementation Decisions

### 走 multi-KB 而非 nested folders（已决定，2026-09-14 讨论）

未来需要新增内容类型时，建新的 KB slug（`policies`、`sql-guides`、`api-docs`、`runbooks`…），每个 slug 是独立目录 + 独立 role 字段。**不**走 subdirectory-based path filter（后者需要 ResolveReads subpath 支持 + retriever path filter + schema 改动 + D-09 信任注释更新，性价比低）。

### 单 KB 内可分子目录做视觉组织

每个 KB 目录（如 `knowledge/sql-guides/`）可以再有子目录（如 `汽车险/`、`财务/`）。OS、git、IDE、grep 全部支持。这只需要 walker 改 WalkDir。

### Chunk source path 自动保留子目录

`internal/knowledge/indexer.go` 已经用 `filepath.Rel(knowledgeDir, path)` 算 source path，递归后子目录自动出现在 source 里。**Milvus 里 chunk 的 `source` 字段会自动包含子目录路径**，不需要 schema 改动。

### 文件管理重组 sql-guides

按业务主题分子目录（具体映射在 PLAN.md 里）。每个 chunk 的 `source` 会变成 `sql-guides/汽车险/xxx.md` 而不是 `sql-guides/xxx.md`——Milvus 检索时这两个路径等价（Milvus 只看 tier 字段过滤，不看 source），不影响召回。

### Phase 范围是「最小修复」

| 改动 | 必要性 |
|---|---|
| walker Glob → WalkDir | 必需 |
| 新增 walker_test.go 回归测试 | 必需 |
| 文件重组 | 推荐（长期管理） |
| CONTRIBUTING.md / README 提示「KB 可分子目录」 | 推荐（可发现性） |

### 不做的事（explicit non-goals）

- ❌ 不改 ResolveReads 支持 subpath（Skill 不必关心子目录）
- ❌ 不改 retriever（Milvus tier filter 不变）
- ❌ 不改 KBM-03 词汇表
- ❌ 不加 path 列 / LIKE 子句（不必要）
- ❌ 不改 Skill reads 模式
- ❌ 不写 D-09 trust floor 注释更新（设计上未变更）

<specifics>

## Specific Ideas

### 重启后 chunk ID 稳定性

当前 walker 用 `sort.Strings(matches)` 保证确定性 walk order，indexer 分配 1-based chunk ID。改成 WalkDir 后必须保留等价的稳定排序：`filepath.WalkDir` 默认字典序，但需要先按相对路径字符串排序再返回（避免 `a/1.md` 和 `a1.md` 这种边界 case 顺序漂移）。

具体实现：在 WalkDir 回调里收集 paths，最后 `sort.Strings(paths)` 后返回。indexer 的 `for _, path := range matches` 循环不变。

### sql-guides 重组目录设计（初步，待 PLAN 确定）

按业务域分：
- `knowledge/sql-guides/汽车险/` — 车险相关（车商费用、车险报价、新能源车、三责车损等）
- `knowledge/sql-guides/财务/` — 财务对账（逐单未到期、政保入账、现金流、税款看板）
- `knowledge/sql-guides/操作手册/` — 通用操作（FineBI、FineReport、定时任务、视频录制、MongoDB 教程）
- `knowledge/sql-guides/系统表/` — 表/字段口径（数据提取字段解读、本地字段对照）
- `knowledge/sql-guides/其他/` — 兜底

具体 240 个文件的归类在 PLAN.md 的可执行步骤里。

### walker 隐藏目录处理

`WalkDir` 默认会进所有子目录。需要显式跳过：
- 隐藏目录（以 `.` 开头，如 `.git`）
- `node_modules`（虽然不太可能在 knowledge/ 下，但防御性跳过）

实现：在 WalkDir 回调里检查 `d.IsDir() && strings.HasPrefix(d.Name(), ".")` → skipDir。

<deferred>

## Deferred Ideas

### ResolveReads subpath 支持（如 `authority/operations/**`）

**不做**，原因：
- 当前 multi-KB 设计（新 KB slug 单独目录）已经覆盖"内容类型分组"诉求
- Skill 不必关心子目录，retriever 不需要 path filter
- 实现 subpath 支持需要改 ResolveReads 返回结构 + retriever schema + D-09 注释，性价比极低
- 如未来真的出现"同一 KB 内多 Skill 只读部分子目录"需求，再开 Phase 单独设计

### 新 KBM-03 role（如 `operational`）

**不做**，原因：
- 当前 sql-guides KB 用 `role: personal`（或未来 `role: authority` 配合 D-01 grounding）已经能跑
- 词汇表封闭是 KBM-03 设计哲学（trust moat），扩展需要单独 Phase + threat model

### Chunk-level 状态标记（如 `policy` / `reference` / `draft`）

**不做**，原因：
- 当前按目录(role)分类已经够用
- Chunk-level 元数据需要 schema 改动（新增字段）+ filter 改动
- 属于更大架构演进

</deferred>
