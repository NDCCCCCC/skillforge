## Spacing Scale

All values are multiples of 4. Tokens mirror `.planning/sketches/themes/default.css` with legacy `20px → 24px` and `40px → 48px` collapses (the checker rule "multiples of 4 only" is satisfied; 12 IS a multiple of 4 and is retained for chat density).

| Token | CSS var | Value | Usage (anchored to Phase 4 surfaces) |
|-------|---------|-------|--------------------------------------|
| xs | `--space-1` | 4px | Icon-to-text gap inside chips/badges; inline padding inside citation chip; reasoning preview left-border gap |
| sm | `--space-2` | 8px | Compact element spacing — message-meta gap, file-item icon gap, badge internal padding |
| md | `--space-3` | 12px | Default chat density — chat-header padding, chat-input padding, panel-left padding, message bubble padding (legacy sketch `--space-3`) |
| lg | `--space-4` | 16px | Section padding — verdict card padding-x, message bubble padding-y, preview-header gap, statusbar padding-x |
| xl | `--space-5` | 20px | Verdict card horizontal padding (legacy `--space-5`, retained as named exception below) |
| 2xl | `--space-6` | 24px | Verdict card top margin, center panel padding (`panel-center`), reasoning preview margin-top |
| 3xl | `--space-8` | 32px | Layout gaps between topbar/panels/statusbar, refusal-card vertical outer margin |
| 4xl | `--space-12` | 48px | Empty-state hero block spacing, major section break between verdict and citations list |

**Exceptions (declared, not violations):**
- `--space-5: 20px` retained ONLY for `VerdictCard` horizontal padding (matches sketch visual rhythm; 20 is a multiple of 4). All other surfaces use the canonical tokens above.
- `--topbar-height: 44px` and `--statusbar-height: 26px` are layout dimensions, not spacing tokens — both multiples of 2, not 4. Excluded from spacing scale; declared in §Layout Contract.
- Touch targets for icon-only buttons (collapse-left, collapse-right, skill-manager icon-btn): minimum 32×32 px hit area (the visible glyph is 16×16 inside 8px padding = 32×32). 32 is a multiple of 4.

## Typography

Locked at 4 sizes + 2 weights. All sizes derived from `.planning/sketches/themes/default.css`. Body line-height 1.5 per template default; headings 1.3 (slightly tighter than the 1.2 default because chat surfaces are dense).

| Role | Size | Weight | Line Height | Token | Phase 4 usage |
|------|------|--------|-------------|-------|---------------|
| Body | 14px (0.875rem) | regular 400 | 1.5 | `--text-base` | Chat message text, refusal reason body, SKILL.md preview prose, citation chunk verbatim text |
| Label | 12px (0.75rem) | semibold 600 | 1.4 | `--text-xs` | Tier badge `[权威]`, citation chip text, message-meta, status-color header label (合规 / 需补充 / 不合规), section titles (SESSIONS / FILES / SKILLS), verdict confidence %, sub-progress step label |
| Heading | 18px (1.125rem) | semibold 600 | 1.3 | `--text-lg` | Verdict card title, panel-empty-state heading, refusal card heading, center panel tab labels (active), chat-header skill selector label |
| Display | 24px (1.5rem) | semibold 600 | 1.2 | `--text-2xl` (down from sketch 1.75rem) | Empty-state hero ("开始一次合规审查"), topbar logo wordmark |

**Forbidden in Phase 4:**
- Weights other than 400 and 600 (no 300, 500, 700).
- Sizes other than the 4 above (no 13px / 16px / 22px / 28px / 36px from the sketch theme). The legacy tokens `--text-sm` (13px), `--text-md` (16px), `--text-xl` (22px), `--text-3xl` (36px) are DELETED from the Phase 4 token set.
- `text-transform: uppercase` is allowed ONLY on `.section-title` (SESSIONS / FILES / SKILLS labels) — letter-spacing 0.05em.

### Accent (`--color-primary` #4a9eff) reserved-for list — EXHAUSTIVE

Accent is reserved for these specific surfaces and NO others:

1. **Send button** background (primary CTA in chat input)
2. **Active session** left-border indicator + active session icon color
3. **Active variant-tab / preview-tab** underline or background tint (topbar variant tabs, center panel tabs when active)
4. **Citation chip tier badge** text color (the `[权威]`/`[历史]` text — but the chip background stays `--color-citation-bg`)
5. **Focus ring** on every focusable element (textarea, buttons, chips, dropdown items) — `outline: 2px solid var(--color-primary); outline-offset: 1px`
6. **Resize handle** hover/dragging color (the 1px line turns primary on hover)
7. **Reasoning preview** left-border 2px line + "推理" label color
8. **Mention dropdown skill-type badge** background tint + text (file-type badge uses `--color-info` instead, per sketch)
9. **Streaming indicator dot** when actively streaming (NOT the green statusbar dot — that uses `--color-success`)
10. **Skill selector** outline when the picker is open

NOT accent: verdict status colors, refusal card borders/icons, message bubble backgrounds, panel backgrounds, breadcrumb text, statusbar text, scrollbars. These all use surfaces, borders, text tokens, or status tokens.

### Status semantic group (separate from accent; D-06 verdict card + D-07 refusal card)

| Token | Hex | Semantic | Phase 4 surface |
|-------|-----|----------|-----------------|
| `--color-status-compliant` | `#22c55e` (green) | Verdict 合规 | Verdict card 3px left-border + status-label text color |
| `--color-status-needs-info` | `#f59e0b` (yellow/amber) | Verdict 需补充 AND `review_required` badge | Verdict card 3px left-border + status-label text + the corner "需人工复核" badge background |
| `--color-status-non-compliant` | `#ef4444` (red) | Verdict 不合规 | Verdict card 3px left-border + status-label text color |
| `--color-status-unanswered` | `#8b95a3` (gray) | Verdict unanswered (no verdict emitted) AND I-don't-know refusal | Verdict card 3px left-border + I-don't-know Refusal card 1.5px full-border + ❓ label |
| `--color-status-out-of-scope` | `#5b7a99` (blue-gray, **NEW — not in sketch theme**) | Out-of-scope refusal (D-07) | Out-of-scope Refusal card 1.5px full-border + 🚫 label text |

**Status color separation contract (checker-enforced):**
- The 4 verdict status colors (green/yellow/red/gray) are MUTUALLY EXCLUSIVE per verdict — one verdict card shows exactly one status color.
- The 2 refusal colors (blue-gray out-of-scope / gray I-don't-know) are MUTUALLY EXCLUSIVE per refusal and DISTINCT from the 4 verdict colors (a refusal is never drawn in green/yellow/red).
- `--color-status-out-of-scope` (#5b7a99) MUST be visually distinguishable from `--color-status-unanswered` (#8b95a3) at normal ambient light. Both share a blue-gray hue family but #5b7a99 has measurably higher saturation/blue content (HSL: 220° 26% 48% vs 215° 11% 59%) — verified by the checker via WCAG contrast against the `#1a1f26` surface: out-of-scope border contrast ratio ≥ 3.0, unanswered border contrast ratio ≥ 2.4.

### Tier badge color encoding (KNOW-05)

Tier badges render as inline mono-text `[权威]` / `[历史]` / `[个人]` / `[草稿]` inside citation chips and chunk-source preview. Color is the SAME for all tiers (tier is differentiated by TEXT, not color) — tier text color is `--color-primary` (#4a9eff). This matches sketch `.citation-chip .tier { color: var(--color-primary); font-weight: 600; }`. Phase 5 may introduce per-tier color encoding; Phase 4 does not.

## Component Contracts (FEUI-01..06 + supporting)

Interaction-level contracts the executor implements against. Each maps to one or more success criteria in ROADMAP §Phase 4.

### FEUI-01 — Streaming chat with typed message parts

- **Container:** `RightPanel > ChatMessages` (scrollable; auto-stick to bottom unless user scrolled up; "新消息" pill appears when not at bottom).
- **Stream binding:** `useChat({ transport })` from `@ai-sdk/react` v4 — owns message stream state (CONTEXT §Claude's Discretion). No Zustand slice for messages.
- **Message rendering:** Each `UIMessage.parts` is dispatched by `part.type` to one of the renderers below (VerdictCard, RefusalCard, ReasoningPreview, ToolCall, Citation cluster, TextBody). Unknown types silently dropped (existing App.tsx behavior — preserve).
- **User vs assistant:** User bubble uses `--color-user-bubble` (#1e3a5f) bg + bottom-right square corner; assistant uses `--color-assistant-bubble` (#1a1f26) bg + 1px border + bottom-left square corner. Per sketch.
- **Streaming indicator:** Pulsing 6px dot in `--color-primary` next to in-flight assistant message label; disappears on `finish-message`.

### FEUI-02 — Collapsible reasoning chain, visible by default

- **Component:** `ReasoningPreview` rendered ABOVE the answer text (D-08).
- **Default state:** Expanded, height-capped at 160px (10 lines @ 14px × 1.5 line-height ≈ 210px → cap rounded to 160px for visual rhythm). Overflow-y auto with a 12px fade gradient at the bottom edge using `--color-surface` mask.
- **Streaming behavior:** As `reasoning-delta` chunks arrive, text appends to the preview's tail and auto-scrolls to bottom (sticky-bottom) until the cap, then the user can scroll freely. Once `reasoning-end` arrives, the cap remains.
- **Expand toggle:** One-click button `展开全部` (Label size, semibold, `--color-primary` text) at the right edge of the preview header. Clicked → height auto, full reasoning visible, button label becomes `收起`. Toggle persists to Zustand `ui.reasoningExpanded` for the session.
- **Answer-visibility invariant:** The answer `TextBody` immediately follows the reasoning preview in normal flow. When reasoning is expanded-full, the user MUST be able to reach the answer with a single scroll gesture inside the message bubble — implemented as `overflow-y: auto` on the bubble (max-height 70vh). The bubble never grows taller than 70vh; if reasoning is huge, the bubble scrolls internally. This is the D-08 anti-burying invariant.
- **Background:** `--color-reasoning` (#2a313b) bg, 2px left border in `--color-primary`, `--space-2 --space-3` padding, `--radius-md` corner.
- **Label:** `推理` prefix (Label semibold, `--color-primary`), followed by status suffix `推理中...` or `生成中...` per copywriting contract.

### FEUI-03 — Clickable citations → center panel chunk-source

- **Citation cluster:** `source-url` and `source-document` parts render as `Citation` chips BELOW the answer text (not inline with the text). Inline footnote markers `[1]`, `[2]` link to the chip cluster via scroll-into-view.
- **Citation chip visual:** `--color-citation-bg` bg + `--color-citation-border` border + tier text `[权威]` in `--color-primary` semibold + chunk-id in mono + `[查看原文]` tooltip on hover.
- **Click action (D-01):** Clicking a chip calls Zustand `ui.setCenterView({ kind: 'chunk-source', chunkId, tier, version, effectiveDate })`. Center panel switches to the chunk-source tab; top of the chunk shows tier badge + version + effective date row; body shows chunk verbatim text in `<pre>` (mono font, no Markdown rendering — preserves raw source).
- **Citation metadata block (SC-2, KNOW-05):** Tier badge `[权威]` (or `[历史]`/`[个人]`/`[草稿]`) + `版本: {version}` + `生效日期: {effectiveDate}` rendered as Label-sized muted text in a horizontal row at the top of the chunk-source view. Version and effectiveDate absent in fixture → render `版本: 未知` / `生效日期: 未知` (never blank).
- **T-1-08 source-url safety (LOCKED):** For `source-url` parts, the renderer MUST call `sanitizeUrl(url)` returning `null` if the URL's protocol is not `https:` or `http:`, OR if the hostname is not in the allowlist `[localhost, 127.0.0.1, ::1, spike.local, skillforge.local]`. If `null`, render the error-state copy `引用 URL 未通过安全白名单，已拦截：{hostname}` in place of the chip and log to console. If allowed, render `<a href={sanitized} target="_blank" rel="noopener noreferrer">`. This is a hard contract — the spike stub sets href directly and MUST NOT survive into Phase 4.

### FEUI-04 — Skill picker

- **Component:** `ChatHeader > SkillSelector` (top of right panel).
- **Data source (Phase 4):** Fixture `/api/skills` returns `[{ id, name, description, reads: ["权威"] }]` (single compliance Skill by default; a second stub Skill to demonstrate the picker).
- **Visual:** Button styled as `--color-surface-2` bg + `--color-border` + Label-size text + chevron icon. Click opens `DropdownMenu` with `Command`-style fuzzy search input at top (keyboard-navigable).
- **Selection behavior:** Selecting a Skill writes to Zustand `app.currentSkillId`; the chat-header label updates; the next `useChat.sendMessage` includes `{ skillId }` in the transport body. Active Skill is reflected in the topbar breadcrumb.
- **Mock behavior:** The Mock Transport uses the selected `skillId` to pick the appropriate fixture set (e.g. `fixtures/compliance-verdict.json` vs `fixtures/general-qa-text.json`). The picker is fully functional against fixtures — not a stub visually, only data-mocked.

### FEUI-05 — Refusal UX with distinction

- **Component:** `RefusalCard` rendered in place of `VerdictCard` when the message carries a `data-refusal` part (or when `data-policy` verdict status is `unanswered` AND `can_user_rephrase` is absent).
- **Visual distinction (D-07):**
  - **Out-of-scope:** `--color-status-out-of-scope` (#5b7a99) 1.5px full-border + 🚫 glyph prefix + heading `超出本 Skill 范围` (Heading size, same color as border).
  - **I-don't-know:** `--color-status-unanswered` (#8b95a3) 1.5px full-border + ❓ glyph prefix + heading `范围内无依据` (Heading size, same color as border).
- **Structured body:** Always rendered below the heading in Body size, 1.5 line-height:
  - `reason` (string from wire contract) verbatim.

## Wire Contract (Frontend Layer)

Mirror of `internal/spike/uimsg.go` + `internal/spike/verdict.go` in TypeScript. The executor generates `web/src/types/wire.ts` from these contracts; unit tests assert field-shape parity with the Go types so wire-contract drift fails CI.

- **UIMessageChunk types (16 — kebab-case):** `text-start`, `text-delta`, `text-end`, `reasoning-start`, `reasoning-delta`, `reasoning-end`, `tool-input-start`, `tool-input-available`, `tool-output-available`, `tool-output-error`, `source-url`, `source-document`, `data-policy`, `data-refusal`, `data-step`, `finish-message`.
- **Field casing:** camelCase. snake_case silently dropped by the AI SDK v5 parser — fixtures MUST comply (verified by `web/src/__tests__/wire-casing.test.ts`).
- **`data-policy` payload:** `{ type: 'data-policy', policy: Verdict }` where `Verdict = { status: '合规' | '不合规' | '需补充' | 'unanswered', confidence: number /* 0–1 */, citations: Citation[], reviewRequired: boolean }`. (Note: wire is snake-friendly in Go but the AI SDK v5 parser delivers camelCase to the FE — `reviewRequired`, NOT `review_required`.)
- **`data-refusal` payload:** `{ type: 'data-refusal', refusal: { reason: string, canRephrase: boolean, suggestedAlternativeQuery?: string, kind: 'out-of-scope' | 'i-dont-know' } }`. `kind` discriminates RefusalCard visual (D-07).
