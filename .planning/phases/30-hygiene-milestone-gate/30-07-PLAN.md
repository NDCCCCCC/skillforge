**Step A — .env.example**

在 `.env.example` 添加 `SKILLFORGE_ADMIN_TOKEN`：

```
# Admin gate token — fail-closed semantics: if not set, admin endpoints return 403.
# Generate with: openssl rand -hex 32
SKILLFORGE_ADMIN_TOKEN=
```

放在现有的 admin 相关配置附近（如 SKILLFORGE_DATA_SALT 之后）。

注释说明：
1. fail-closed 语义：未设置时 admin 端点返回 403
2. 生成方式指引（openssl rand -hex 32）

**Step B — main.go envOr wiring**

在 main.go 添加 `SKILLFORGE_ADMIN_TOKEN` 的 envOr 读取，并 plumb 到 `server.Deps`（用于 `isAdminRequest` 的 discoverability 和一致性）：

在 main() 函数的 env parsing 区段添加：
```go
// Phase 30 — admin gate token. Read via envOr (not envRequired) so
// an unset value is the legal demo-OOB state (isAdminRequest returns
// false when the env is empty, D6-08). Plumbed through server.Deps
// for orchestration parity with all other SKILLFORGE_* vars.
adminToken := envOr("SKILLFORGE_ADMIN_TOKEN", "")
```

在 `server.Deps` struct 初始化处添加字段（如果 `server.Deps` 有 `AdminToken` 字段的话）或记录该值已在 `isAdminRequest` 中直接读取。

**注意**：当前 `isAdminRequest` 直接调用 `os.Getenv("SKILLFORGE_ADMIN_TOKEN")`。
main.go 添加 envOr 读取并通过 Deps plumb 是为了 main.go 编排可见性。
如果 `server.Deps` 无 AdminToken 字段，则该值仍在 `isAdminRequest` 中读取，
main.go 的 envOr 添加仅为 verify-phase-30.sh Stage 2 的配置可发现性检查服务。
