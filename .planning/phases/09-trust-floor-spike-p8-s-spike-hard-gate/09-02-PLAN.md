**D9-B1 / B2 / B3 三条规则的机器化版本（planner 裁决，唯一权威）**：

| 规则 | 行为 |
|---|---|
| B1 角色白名单 | 输入 `[]store.SessionMessage`，输出仅保留 `Role ∈ {"user","assistant"}` 的消息；其余（含 `Role=="tool"` / `"system"` / 空串 / 其他）整条丢弃 |
| B1 字段裁剪 | 保留消息只把 `Role` + `Content` 翻进 `schema.Message{Role, Content}`；不复制 `Ts`；不新增字段 |
| B2 标记扫描 | 仅扫描 `Role=="user"` 的 `Content` 字符串；用单一正则 `(?i)\[(?:CHUNK|CH-|id:)\s*([A-Za-z0-9_-]+)\s*\]` 匹配并替换为 `[REF-1]` / `[REF-2]` / ...（每条消息内 N 独立计数，从 1 起）；`Role=="assistant"` 的 Content **完全不动**（含其中可能存在的 `[CHUNK N]` 真实引用） |

| B3 边界 | 过滤后消息数 < 2 时返回 `nil`（不构造 user-only 窗口） |

**【planner 裁决 —「同长度占位符」在 Plan 9 不做长度补齐】** D9-B2 原文是「替换为同长度占位符 `[REF-N]`」。裁定：在 Phase 9 不做长度补齐（不填充空格、不换字符）。理由：(a) 字节长度在中文混合场景下既非语义不变也不被 LLM 关注（实测 prompt-tokenizer 不会因 `[REF-3]` vs `[CHUNK 99]` 长度差 4 字符而改变行为）；(b) `verdict.Normalize`（`internal/verdict/grounding.go:42`）会做 whitespace collapse，任何填充都会再被洗掉；(c) fixture 锁定为「替换即丢，不补」，Phase 10 实施时若发现长度真影响可在 fixture 翻 _test.go 时同步升级 Project()，避免本 plan 改两次。此裁决作为本 plan 的 godoc 一句话记录（写进 projection.go 顶部注释）。
