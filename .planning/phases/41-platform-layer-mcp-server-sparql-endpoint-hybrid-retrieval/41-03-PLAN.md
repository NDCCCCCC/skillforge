    ```go
    type HybridQuery struct {
        Query   string `json:"query"`             // natural language query string
        MaxHops int    `json:"max_hops"`          // 1 or 2, default 1
        Rerank  bool   `json:"rerank"`            // default true (SKILLFORGE_RETRIEVAL_RERANK)
    }
    ```

    **Response shape:**
    ```go
    type HybridKGNode struct {
        ID         string        `json:"id"`
        Label      string        `json:"label"`
        Kind       string        `json:"kind"`          // "note"|"table"|"skill"|"file"
        Tier       string        `json:"tier,omitempty"`
        Provenance *Provenance   `json:"provenance,omitempty"`
    }
    type HybridKGEdge struct {
        Source    string `json:"source"`
        Target    string `json:"target"`
        Predicate string `json:"predicate"`
    }
    type HybridMilvusHit struct {
        Score      float64 `json:"score"`
        Text       string  `json:"text"`
        SourcePath string  `json:"source_path,omitempty"`
        Section    string  `json:"section,omitempty"`
    }
    type HybridResponse struct {
        KGNodes    []HybridKGNode   `json:"kg_nodes"`
        KGEdges    []HybridKGEdge  `json:"kg_edges"`
        MilvusHits []HybridMilvusHit `json:"milvus_hits"`
    }
    ```

    **HybridSearchScoped(query HybridQuery, allowedTiers []string) HybridResponse:**

    **Step 1 — KG Expansion:**
    If `MaxHops` is 0, default to 1. If `MaxHops > 2`, cap at 2.
    Use `kg.Adjacent1/Adjacent2` to expand a subgraph starting from entities matched by a keyword search on the query string. The starting point: query the KG for entities whose label contains the query keywords (use `kg.QueryScoped("", "skf:description", "", allowedTiers)` and filter by case-insensitive substring match on the query string against the entity IRI).
    
    Actually — simpler approach per D-HYB-01: do a KG `QueryScoped` for all entities matching a simple label search. The exact expansion algorithm:
    1. Collect all ABox note/tbl entities visible to the caller skill (via `QueryScoped("", "rdf:type", "skf:NoteChunk", allowedTiers)` + `QueryScoped("", "rdf:type", "skf:TableSchema", allowedTiers)`).
    2. Build a KG subgraph by traversing `referencesTable` edges up to `MaxHops`.
    3. The subgraph nodes are the expanded entity set for Milvus search.

    **Simplified KG expansion (per the 005e spike pattern):**
    - Start with entities matched by the query string in their IRI or label
    - For `MaxHops=1`: collect all entities reachable via `skf:referencesTable` from matched entities
    - For `MaxHops=2`: do two hops
    - Collect all unique entity IRIs → these form the `KGNodes` output
    - Edges: all `referencesTable` edges between the expanded entities

    **Step 2 — Milvus Hybrid Search:**
    Use the existing Milvus retriever (from `internal/retriever/milvus`). The hybrid search in Milvus 2.5+ supports dense + sparse multi-vector. Query Milvus with the natural language query string. The reranker (BGE-reranker-base) will be applied in Step 3.

    **Step 3 — BGE-reranker:**
    If `Rerank=true` (default), apply BGE-reranker-base to re-rank the top-50 Milvus results. The reranker takes the query + top-50 text chunks and returns re-scored results. Take top-5.

    **Step 4 — Assemble response:**
    - KG nodes: entity IRIs + labels + kinds from KG
    - KG edges: `referencesTable` edges between expanded entities
    - Milvus hits: score + text snippet + source_path + section for each hit

    **Env vars (D-HYB-03, D-HYB-04):**
    - `SKILLFORGE_RETRIEVAL_RERANK=true|false` — default true, enables BGE-reranker
    - `SKILLFORGE_HYBRID_HOPS=1|2` — default 1, KG expansion depth

    **Tier filtering:** All KG operations use `QueryScoped` with `allowedTiers`. The Milvus search also uses tier-filtered queries (call Milvus with the tier-filtered entity set as a pre-filter).

    **Error handling:** Return error if Milvus search fails. The KG expansion should not fail — if it returns 0 nodes, return empty results.
