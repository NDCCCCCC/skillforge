  <action>
    In `internal/server/admin_platform.go`, add the shared SPARQL handler logic used by both the REST endpoint and the MCP skf_query tool.

    **Request body shape (D-SPARQL-01):**
    ```go
    type SparqlPattern struct {
        S      string `json:"s"`       // subject IRI or "": wildcard
        P      string `json:"p"`       // predicate IRI or "": wildcard
        O      string `json:"o"`       // object IRI or "": wildcard
        Limit  int    `json:"limit"`   // default 50, max 500 (D-MCP-05)
        Offset int    `json:"offset"`  // default 0
        Filter string `json:"filter"`  // optional: entity name substring match
    }
    ```

    **Response shape (D-SPARQL-01):**
    ```go
    type SparqlResult struct {
        S          string        `json:"s"`
        P          string        `json:"p"`
        O          string        `json:"o"`
        Provenance *Provenance   `json:"provenance,omitempty"`  // from store.Triple
    }
    type SparqlResponse struct {
        Results   []SparqlResult `json:"results"`
        Count     int            `json:"count"`
        Truncated bool           `json:"truncated"`
    }
    ```

    **SparqlQueryScoped(pattern SparqlPattern, allowedTiers []string) SparqlResponse** — the shared function:
    1. If `pattern.Filter` is non-empty, apply substring match on entity names after the query returns results (filter on S/P/O string values, case-insensitive substring).
    2. Call `kg.QueryScoped(pattern.S, pattern.P, pattern.O, allowedTiers)` to get filtered triples.
    3. Apply `Offset` and `Limit` pagination.
    4. Compute `Count` (total matches before pagination) and `Truncated` (count > limit).
    5. Build `SparqlResponse` with results.
    6. Default Limit to 50 if 0; cap Limit at 500 (D-MCP-05).

    **Error handling:** Returns error for invalid limit/offset (negative values → 400).

    This function is called by both the REST endpoint handler and the MCP skf_query tool.

    Add `adminPlatformSparqlHandler` to `internal/server/admin_platform.go`:

    **Handler: POST /api/sparql**

    1. **Parse body:** Read JSON body into `SparqlPattern`. On parse error → 400 with error detail.
    2. **Extract caller identity (D-SPARQL-03):** Read `X-Skill-Name` header. If absent → 401 with `{"error": "missing X-Skill-Name header"}`.
    3. **Resolve skill to tiers:** Look up the skill name in the KG to get its `hasReadAccess` tier list (via Adjacent1 on the skill IRI). If skill not found → 401. Empty reads list → 401 (no tier access is an invalid caller state).
    4. **Call SparqlQueryScoped:** Pass pattern and resolved tier list.
    5. **Return:** 200 with `SparqlResponse` JSON (no special envelope — direct JSON response, per D-SPARQL-01).

    **Route registration in server.go:** Look for the section where admin routes are registered (around `h.GET("/api/admin/governance/shacl", ...)`). Add:
    ```go
    h.POST("/api/sparql", deps.adminPlatformSparqlHandler)
    ```
    Note: This route is NOT under `/api/admin/` — it is the public SPARQL endpoint (the token is the X-Skill-Name header, not X-Admin-Token). Tier isolation is enforced server-side.

    **Do NOT use `requireAdmin`** — this endpoint uses X-Skill-Name header for tier isolation, not the admin token.
