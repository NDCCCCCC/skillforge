## Architectural Decisions

1. **Composite alias is QUOTED in SQL** — the period `2026-07` introduces a hyphen into the composite name (`loans__2026-07`), which DuckDB only accepts inside a `"..."` quoted identifier. The plan's brief substitution (`ds_{dataset}` → `ds_{composite}`) is implemented as `ds_{dataset}` → `"ds_{composite}"` to make the substitution actually runnable. The replacement value is ValidateDatasetID-locked (`^[A-Za-z0-9_-]{1,64}$`); the extra quotes cannot smuggle anything because no metacharacter escapes that lock.
2. **Atomic attach-then-query** — the EngineAdapter acquires the LRU mutex for the WHOLE query (not just the ATTACH), so a concurrent eviction cannot DETACH the alias between "attached" and "queried". This is the session-scoped catalog discipline — ATTACH/DETACH mutate the connection's catalog.
3. **Singleton-Registry as a D16-C4 trust anchor** — two calls from different Skill contexts share the same Registry (and therefore the same compiled SQL template, the same TableRefCount, the same PreserveColumns). The cross-Skill test asserts this by sharing `reg` across both calls and asserting byte-identical result rows + identical ASOf.Period + identical Signature on the audit rows.
4. **Mirror constant `kpi.KMinDefault == data.KMinDefault`** — the CGO boundary (internal/data transitively depends on go-duckdb) forces the kpi package to mirror the constant instead of importing it. The WSL test `TestNameLexiconParity` locks this equality; drift makes the test red.
5. **`KPINamePattern()` accessor** — exporting the canonical regex via a thin accessor (rather than the literal regex pattern) prevents the WSL test from silently diverging on grammar updates. Drift between the accessor and the loader's internal pattern is exactly what the test catches.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] removed `rows.Err()` call on driver.Rows interface**
- **Found during:** Task 3 kpi_engine.go initial compile
- **Issue:** driver.Rows has no `Err()` method (sql.Rows does). Initial implementation called `rows.Err()` for iteration errors; compile error.
- **Fix:** Removed the call. Any iteration error from `rows.Next(dest)` other than io.EOF breaks out of the loop; this matches the pattern used by `attach_lru_test.go` for direct driver.Rows iteration.
- **Files modified:** internal/duckdb/kpi_engine.go
- **Commit:** a4fe03c (folded into the engine adapter commit)

**2. [Rule 2 - Critical functionality] added `KPINamePattern()` accessor**
- **Found during:** Task 3 WSL test design
- **Issue:** The plan's `TestNameLexiconParity` asserts the kpi name grammar matches `duckdb.ValidateDatasetID`, but the kpi regex `kpiNamePattern` was unexported. Re-declaring the regex in the WSL test would silently diverge on grammar updates (RULE-2 critical: the lock must fail-closed on drift).
- **Fix:** Added `internal/kpi/lexicon.go` exposing the canonical regex via `KPINamePattern() *regexp.Regexp`. Returns the same instance the loader uses internally; drift surfaces immediately in the WSL test.
- **Files added:** internal/kpi/lexicon.go
- **Commit:** 829b191

### Documented Plan Notes

**Composite-alias substitution quotes the replacement value** — see Architectural Decision 1. The plan's literal "ds_{dataset} → ds_{composite}" wording omits the quotes; the implementation quotes because DuckDB's unquoted identifier grammar rejects hyphens. The ValidateDatasetID allowlist on the composite value is what keeps the quotes safe (no metacharacter escapes).
