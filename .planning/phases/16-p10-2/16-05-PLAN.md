  type SQLSerializer interface { SerializeSQL(ctx context.Context, statement string) (string, error) }（godoc：json_serialize_sql 的进程内抽象；生产实现是 internal/duckdb 适配器，测试实现读 probe fixture / 内联 JSON——CGO 边界纪律注释）。
  type sqlEnvelope struct { Error bool `json:"error"`; ErrorType string `json:"error_type"`; ErrorMsg string `json:"error_message"`; Statements []sqlStmt `json:"statements"` }；type sqlStmt struct { Node json.RawMessage `json:"node"` }——node 先保 RawMessage，按探针实测形态定义最小递归模型（含 type 字符串 + from_table/join 树/子查询位置；若 probe 显示表引用以 schema_name/catalog_name+table_name 拆分字段呈现，则按实测字段名建模——不按文档想象）。
  func ValidateSQLAST(ctx context.Context, ser SQLSerializer, statement, declaredDataset string) (tableRefRefs []string, err error)：调 ser.SerializeSQL → json.Unmarshal envelope → 四条 fail-closed 规则（每条错误经 fmtError("ValidateSQLAST", ...) 带 KPI 语境由调用方包）：
  规则 1 envelope.Error == true → 拒（错误带 ErrorMsg 与 ErrorType）——Pitfall 1：序列化「成功」返回的 error:true 必须显式检查；
  规则 2 len(envelope.Statements) != 1 → 拒（只允许单条语句）；
  规则 3 statements[0].node 的 type != "SELECT_NODE" → 拒（SELECT-only；INSERT/DELETE 无论实测走 error:true 还是其它 node.type，两条规则双保险都拒——A1 lock 的落点）；
  规则 4 递归走查收集全部 BASE_TABLE 表引用（from_table、join 树、select_list 与 FROM 子句中的子查询——递归深度以实测 AST 为准）：收集结果为空 → 拒（零表引用——SELECT 42 形态无数据集绑定）；任一引用不匹配「别名恰为 ds_{declaredDataset} 且表名恰为 data」→ 拒（错误列出非法引用全量 + 声明 dataset——未注册数据集与跨数据集 join 同一规则机械判定，D14-D1 应用层呼应）。返回值 = 合法引用列表（调用方记 TableRefCount，16-06 复合别名替换的计数校验消费）。
