## Design Rationale

**Why hardcode MaxIteration: 10 (P12-L2)?** Pitfall 8 — DeepAgent's default MaxIteration is 50 (or 20 per ChatModelAgent — RESEARCH Open Question #1). On GLM-5.2 + DeepAgent, 50 iterations = ~$5+ per query. Making this a config knob invites operator drift. Source-grep + reflection locks make the cap structural.

**Why fnv64a hash + 200-char truncation?** Naive loop detection hashes the full tool args; legitimate multi-hop retrieval (Phase 3 pattern: agent calls retrieve 2-3 times with refined queries) would falsely trigger. Truncation to first 200 chars moves the hash boundary between refined queries — Phase 3 multi-hop tests verify this pattern (Pitfall 5 mitigation). fnv64a is fast (deterministic, no crypto) and produces 8-byte hashes (fits in uint64).

**Why forced_stop on `data-decision` (not new chunk)?** D15 wire-type alarm — adding a new discriminator breaks the D15 lockstep with TS. Adding `forced_stop` as a new VALUE in the existing `Decision` enum (D16 overload pattern, extended from Phase 11) keeps the discriminator count stable. The FE real-chat-transport.ts parses the same data-decision chunk; the only addition is a new case in the decision switch.

**Why BudgetLayer as nullable column (vs separate table)?** Audit row count grows by ~3 rows per budget trigger (one per layer triggered); keeping it in the audit table makes timeline queries uniform (12-07 AuditTimelineTab shows budget events alongside approval events). Separate table would require a JOIN. Trade-off: nullable column vs JOIN — nullable column wins for query simplicity.

**Why 50000 token default?** Initial calibration — covers ~10 LLM calls with 5K context each. Phase 12 Open Question #5 records this as needing live calibration. 12-08 acceptance gate measures actual token usage on the 50-case golden set; if 50000 is too tight or too loose, the constant can be tuned.

## Reference Patterns

- **Phase 11 D11-C3** (audit_writer sync INSERT before StatefulInterrupt) — budget audit row INSERT happens in BeforeModel callback BEFORE the LLM call that would have been made; mirrors the fail-closed posture.
- **Phase 11 D11-A4** (shared ctx + SSE writer; <200ms cancel preserved) — budget middleware shares the same ctx; SSE emit via the per-Run emitter closure.
- **Phase 3 D16** (data-decision SSE chunk discriminator) — extended with `forced_stop` value (P12-L3 lock; no new discriminator).
- **Phase 8 D8-06** (SC-5 stub TestInterruptResumeRoundTrip) — preserved; budget middleware does NOT touch CheckPointStore (separate concern).
- **Phase 9 T-3-AUDIT** (INSERT-only audit pattern) — budget audit rows are INSERT-only; no UPDATE / DELETE.

## Pitfall Mitigations

- **Pitfall 8 (DeepAgent cost explosion):** 3-layer budget gate from day 1. MaxIteration: 10 hardcoded (P12-L2). Token accumulator + loop detector as second/third safety nets. forced_stop conservative (never run-to-exhaustion).
- **Pitfall 5 (Loop detection false positives):** fnv64a hash + first-200-chars truncation. TestBudgetLoopDetectionLegitimateMultiHop proves Phase 3 multi-hop pattern doesn't trigger.
- **Pitfall 1 (Sub-agent injection — deferred to Phase 13):** 12-01 factory sets WithoutGeneralSubAgent: true; budget gate applies to the entire DeepAgent run including any sub-agents (defense in depth).

<risk>
## Top 3 Risks

1. **Loop detector false positives on legitimate multi-hop with very similar args.** If the LLM refines the query slightly (e.g., adds a single character), the first 200 chars are still identical → false positive. **Mitigation:** TestBudgetLoopDetectionLegitimateMultiHop asserts refined-query pattern doesn't trigger; if acceptance gate measures >10% false-positive rate, widen the truncation to 100 chars or use Levenshtein distance (more expensive but fuzzier). Phase 12 Open Question #4 records this.

2. **Token budget too tight for complex queries (50000 cap = ~10 LLM calls).** A complex multi-hop compliance audit query might need 15+ LLM calls; budget gate would forced_stop mid-execution. **Mitigation:** TokenBudget is configurable per-run (env var or per-Skill override); 12-08 acceptance gate measures actual usage on the 50-case golden set; tune the default. Per-Skill override possible via SKILL.md `token_budget: <int>` extension (out of scope for 12-05; recorded for Phase 13+).

3. **forced_stop emit and audit INSERT are NOT atomic.** If SSE emit succeeds but audit INSERT fails, the user sees forced_stop but no audit row. **Mitigation:** The order is audit-INSERT-then-emit (mirrors D11-C3); if audit fails, the budget callback returns an error WITHOUT emitting the SSE chunk (forced_stop only fires if both succeed). TestBudgetAuditRowOnTrigger asserts the order.
</risk>
