## Design Rationale

**Why a new package (`internal/runtime`) instead of extending `internal/agent`?** Phase 11 already created `internal/agent/{callbacks,tools,hitl}` subdirectories. Adding `internal/runtime/` as a sibling (not child) preserves Phase 11's package boundary — `internal/agent` keeps ChatModelAgent construction (Phase 11) + HITL Tools (Phase 11) + callbacks (Phase 11 D11-A2). `internal/runtime` owns archetype dispatch + `ApplyTrustStage` exit. `internal/verdict` is downgraded to a library (D11-A2: trust floor + D2-01 grounding) consumed by `internal/runtime.ApplyTrustStage`. This is the canonical Architectural Responsibility Map from RESEARCH.md.

**Why hardcode MaxIteration: 10?** Pitfall 8 (DeepAgent default MaxIteration=50 cost explosion). The research confirms that making this a config knob invites operator drift — a config value of 50 is the natural "give me more reasoning" suggestion, but on GLM-5.2 + DeepAgent, that's ~$5+ per query. P12-L2 source-grep lock makes the cap structural — only an explicit code change can lower it.

**Why WithoutWriteTodos: true (Option C)?** The auto-injected write_todos middleware in `deep.New` is opaque — SkillForge cannot intercept the tool call to emit audit + SSE. Option C (custom write_todos Tool with audit + SSE hooks) trades the auto-injection convenience for full control. 12-02 ships the audited custom Tool.

**Why WithoutGeneralSubAgent: true?** Phase 13 (P8.4 sub-agent fan-out) builds the safe fan-out path with tier-inheritance + per-sub-agent grounding. Enabling sub-agents in P8.3 without that hardening is a security risk (T-13-1 sub-agent injection). Phase 12 ships with sub-agents disabled; Phase 13 enables them after the safe fan-out path lands.
