## Design Rationale

**Why Option C (custom write_todos Tool) instead of intercepting auto-injection?** Eino DeepAgent auto-injects write_todos via `buildTypedBuiltinAgentMiddlewares` (deep.go:209-217). The middleware is opaque — it calls `adk.AddSessionValue(ctx, SessionKeyTodos, input.Todos)` and SkillForge never sees the tool call to emit audit + SSE. Option C (set `WithoutWriteTodos: true` + register custom Tool) trades the auto-injection for full control. RESEARCH §Pattern 2 confirms this is the cleanest path.

**Why a separate `plan_todos` table instead of extending `audit.action`?** Trade-off: separate table = clean PLAN-05 replay query (`SELECT * FROM plan_todos WHERE run_id=? ORDER BY ts`); extended audit = uniform audit query (one table for everything). Replay is the hot path — every render of PlanReplayView (12-07) hits this query. Audit uniformity is nice for the operator but per-render latency matters more. P12-L5 lock.

**Why a new wire discriminator (`data-plan-trace`) instead of overloading `data-decision`?** D15 wire-type alarm + D10-B4 overload (4 history events already use `data-decision.Step=0`). Adding `plan_todo_*` to data-decision would explode the enum. New discriminator is cleaner + D15 lockstep with TS mirror in 12-06 (paired commit). P12-L6 lock.

**Why fail-closed on SSE emit failure (not just audit failure)?** The SSE channel is the LIVE trace — if audit succeeds but SSE fails, the user sees stale state (audit shows update, UI shows old todos). Both must succeed for the Tool to return success. Mirrors HITL-04 fail-closed posture. P12-L4.

## Reference Patterns

- **Phase 11 D11-A2** (HITL = Tool+StatefulInterrupt) — write_todos is NOT a HITL Tool; it's a regular Tool with audit + SSE. No StatefulInterrupt call.
- **Phase 11 D11-C3** (audit_writer sync INSERT before StatefulInterrupt) — write_todos audit INSERT happens BEFORE SSE emit (audit is the durable record; SSE is the live stream).
- **Phase 11 D8-06 SC-5 stub** (cross-process resume via CheckPointStore) — write_todos audit rows survive process restart (plan_todos is sqlite-persisted, same DSN).
- **Phase 3 T-3-AUDIT** (INSERT-only audit pattern) — plan_todos follows the same INSERT-only + ?-parameterized pattern; no Update/Delete methods.
- **Phase 4 D15** (wire-type compile-time alarm) — ValidTypes extension paired with TS mirror in 12-06.

## Pitfall Mitigations

- **Pitfall 3 (write_todos audit not persisted → replay broken):** Task 4 audit INSERT happens BEFORE SSE emit; if audit fails, Tool returns error (no partial state). Task 2 INSERT-only table guarantees replay consistency.
- **Pitfall 6 (data-plan-trace buffering in AI SDK v5):** Emitting via `data-plan-trace` discriminator is the safest path. 12-06 also adds synthetic `tool-input-*` + `tool-output-available` chunks for redundancy — the live-rendering surface is the tool-call lifecycle (AI SDK v5 native).
- **Pitfall 7 (D15 wire-type drift):** Task 1 ships Go half + locks the constant string "data-plan-trace". 12-06 ships TS mirror in paired commit.
