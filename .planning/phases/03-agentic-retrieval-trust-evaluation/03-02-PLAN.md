type AuditRow struct {
    ID              int64
    Timestamp       time.Time
    SessionID       string
    UserID          string
    SkillID         string
    Query           string
    PromptHash      string  // hex SHA-256
    ModelVersion    string
    VerdictJSON     string
    RefusalReason   string

    ContextPrecision  *float64
    AnswerRelevance   *float64
    ContextRecall     *float64
}

type SessionMessage struct {
    Role    string    // "user" | "assistant"
    Content string
    Ts      time.Time
}

type Store interface {
    PutAudit(ctx context.Context, row AuditRow) (int64, error)
    QueryAudit(ctx context.Context, filter AuditFilter) ([]AuditRow, error)
    GetSession(ctx context.Context, sessionID string) ([]SessionMessage, error)
    AppendTurn(ctx context.Context, sessionID string, user, assistant SessionMessage) error
    Health(ctx context.Context) error
    Close() error
}

| Boundary | Description |
|----------|-------------|
| Operator → audit query (GEVL-03 SQL filter) | Untrusted input crosses here — the operator's filter string (user, refusal_reason, etc.) MUST NOT be concat'd into SQL |
| Concurrent sessions → shared SQLite file | Two same-user sessions cross here — row-level `session_id` partitioning is the isolation enforcement |
| Eval sidecar (Plan 03-06) → audit table | Read-only consumption of audit rows for Ragas eval |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-3-SQLI | Tampering | `QueryAudit` SQL filter construction | mitigate | Task 2 + Task 3: every filter field uses `?` parameterized placeholders; `TestAuditRowSQLInjection` injects `'; DROP TABLE audit; --` into every filter and asserts the table survives. NO `fmt.Sprintf` in any query path. |
| T-3-AUDIT | Repudiation | `audit` table integrity | mitigate | Task 2: schema has INSERT + SELECT paths only — no UPDATE. SQLite file permissions are the operator's responsibility (documented in Plan 03-05 README). Deletion is Phase 6 retention policy. |
| T-3-HASH | Repudiation | `prompt_hash` collision resistance | mitigate | Task 2: `prompt_hash` is SHA-256 (collision-resistant to 2^128); hash input is `rendered system prompt + skill_id + model_version` so cross-skill reuse does not collide. |
| T-3-SESSION | Information Disclosure | `session_turn` cross-session leakage | mitigate | Task 2 + Task 3: `GetSession` query is `WHERE session_id = ?` (SQL-layer enforcement); `TestSessionIsolationConcurrent` under `-race` proves two same-user sessions with different `session_id` see only their own history. |
| T-3-SC | Tampering (supply chain) | `go get modernc.org/sqlite` | mitigate | Task 1: blocking `checkpoint:human-verify` BEFORE the install — human verifies pkg.go.dev listing, source repo, license (BSD-3-Clause compatible with Apache-2.0), and absence of postinstall scripts.
