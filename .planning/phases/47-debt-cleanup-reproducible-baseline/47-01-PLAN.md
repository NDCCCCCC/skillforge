<objective>
Eliminate the real root cause of the `TestDeriveEdgesDeterministic` flake — nondeterministic edge direction caused by Go map iteration order in `ComputeEdges` — and harden the test so the GRF-02 determinism contract is enforced at a strength that actually proves it.

Purpose: `ComputeEdges` publicly promises "same input → byte-identical output" and `EdgeGraph.Neighbors` performs directed traversal, so a flipped `From`/`To` changes the reachable node set. The measured flake (CONTEXT D-01: `-count=200` → 34 failures, ~17%; every failure on `From`/`To`/`EdgeType`, zero on `Weight`) is a real production nondeterminism, not a test artifact — and Phase 48's public CI gate cannot go green while it exists.

Output: a deterministic `ComputeEdges`; a loop-driven whole-struct test that fails loudly if determinism regresses.
</objective>

`Edge` (fields `From`, `To` string; `EdgeType`; `Weight float64`) — struct definition must not change.

Root-cause site: `graph_edges.go:206-248` — `sourceTokens map[string][]string` → `sources []srcInfo` converted by `for src, tokens := range sourceTokens` (random map order), then `for i < j` pairing emits `From: sources[i].chunkID, To: sources[j].chunkID`. Slice order therefore decides edge direction.

In-file precedent for sort-before-pair: `computeCitationEdges` at `graph_edges.go:550-574` (map → slice → `sort.Strings` → pair).

Directedness that makes this functional, not cosmetic: `EdgeGraph.Neighbors` at `graph_edges.go:364-374` walks `g.adj[current]` toward `edge.To`.

Current final comparator (`graph_edges.go:261-270`) sorts by `From`, then `To`, then `EdgeType` — three keys, `sort.Slice` (unstable), no `Weight` tie-break.
