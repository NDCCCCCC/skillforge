Rewrite the enumeration and rule placement inside `scan_trust_surface` only. Do not change P1–P7, P9, P10, or the P8/P11 call sites.

1. **Enumerate both extensions, still max-depth 1:**
   `find "$dir" -maxdepth 1 -type f \( -name '*.yml' -o -name '*.yaml' \) -print 2>/dev/null | sort > "$list"`.
   Keep the zero-file guard, and keep a subject guard: fail unless at least one enumerated basename is `ci.yml` OR `ci.yaml` (the phase's three-job matrix must exist under its known name; P2/P5/P9 reference it directly).

2. **Hoist the path-filter rule into the per-file loop.** Delete the `ci_src` read and the post-loop `paths:` block. Inside `for p in paths:` evaluate **comment-stripped** text (`nocomment = re.sub(r"(?m)#.*$", "", src)`): if `"paths:" in nocomment` or `"paths-ignore:" in nocomment`, fail with `trust-surface: %s contains %s — a path-filtered required check sits Pending (T-48-03)` naming the file.

3. **Hoist the secret rule into the same loop, with an explicit named allowlist.** Parse `re.findall(r"secrets\.([A-Za-z_][A-Za-z0-9_]*)", nocomment)` and compare each name against:
   - `GITHUB_TOKEN` — allowed in every workflow;
   - `GLM_API_KEY`, `BGE_M3_URL`, `MILVUS_ADDRESS` — allowed **only** when `os.path.basename(p) == "eval-gate.yml"`.
   Anything else fails with `trust-surface: %s references secrets.%s; only secrets.GITHUB_TOKEN is allowed outside eval-gate.yml (T-48-04)`. This replaces the "whatever is in ci.yml is fine" accident with a named exception.

4. **Case-insensitive publication tokens (IN-02).** Evaluate `lower = nocomment.lower()` and fail on any of: `ghcr.io`, `docker.io`, `quay.io`, `docker/login-action`, `registry:`, `dockerhub`, `docker push`, `packages: write`, `push: true`. `push: false` must NOT match `push: true`. Report the matched token and whether it matched case-insensitively.

5. **Replace the raw `"write" in src` scan (IN-02).** It currently false-fires on prose such as "this workflow writes the PR comment". Use comment-stripped, value-shaped detection: fail when a line matches `^\s*[A-Za-z0-9_-]+:\s*write(-all)?\s*$` or contains `packages: write`; keep the parsed permissions-map check as the authority.

6. **Accept and judge permissions string forms (IN-03) — without widening the ceiling D-29 records.** At workflow level and at job level, the string value `none` is accepted (it grants nothing, so it is inside D-29's enumeration); `write-all` is a violation; **`read-all` is a violation**; any other string is a violation. The defect being closed is the silent skip — today the job-level branch is `isinstance(job.get("permissions"), dict)`, so a job-level string is never judged at all.

   `read-all` stays rejected, and this deliberately departs from the review's own phrasing ("P8 rejects the valid `read-all` shorthand"). D-29 is locked and enumerates the permitted ceiling as exactly `{contents: read, pull-requests: read}` with zero write in the directory; `read-all` grants *every* read scope (`actions`, `checks`, `packages`, `id-token`, …), so accepting it would have the verifier enforce a ceiling wider than the decision records. Handling `none` and `write-all` closes the silent-skip half in full; accepting `read-all` is a D-29 **amendment** first and a code change second, and no such amendment is on this phase's surface.

7. **Evidence line:** print `TRUST-SURFACE-OK (%d workflow file(s), path filters and secret references checked per file)` so the printed claim and the computation cannot diverge.

Mutation probes (all three must make the **real** gate exit non-zero; every fixture is removed by a `trap` and must not remain tracked):
