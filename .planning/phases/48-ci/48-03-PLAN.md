## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fork PR → `eval-gate` live job | Fork-controlled trigger reaches a job whose `env:` carries `GLM_API_KEY` / `BGE_M3_URL` / `MILVUS_ADDRESS` |
| Dependabot → same job | A same-repo actor that nonetheless receives no secrets, so it would `log.Fatalf` in `cmd/eval` |
| Workflow trigger shape → token scope | Introducing `pull_request_target` would re-run fork code with base-repo secrets and a write token |
| `eval-gate.yml` → the published CI contract | Its `on:` block is what every contributor's PR is evaluated against; silently widening or deleting it is a silent scope change |

## Threat Register (this plan)

| ID | STRIDE | Threat | Severity | Disposition | Mitigation in this plan |
|----|--------|--------|----------|-------------|-------------------------|

Never gate a secret-bearing job by widening the trigger — gate it with a job-level `if:` |
| T-48-02 | Information Disclosure / Availability | A fork PR reaches `eval-gate`; GitHub substitutes empty strings for the three secrets, `cmd/eval`'s `envRequired("BGE_M3_URL")` calls `log.Fatalf`, and every external contributor sees a red required check | high | mitigate | Task 1's three-clause job-level `if:` (D-09); the three secret mappings are asserted still present so the gate cannot be "fixed" by deleting them |
