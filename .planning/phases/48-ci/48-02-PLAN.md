<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Untrusted PR → `docker` job | An untrusted fork PR triggers a multi-GB CGO image build (etcd/milvus-scale dependency trees) on public runner minutes |
| `ci.yml` → registry | Any path from the Docker job to a registry is an image-publication capability the project has explicitly refused |
| `web/package-lock.json` → runner | `npm ci` installs third-party packages from the lockfile; a lockfile edit is a supply-chain event |
| `ci.yml` → required-check semantics | A `paths:` filter or a skipped job turns "the gate ran" into an assumption |

## Threat Register (this plan)

| ID | STRIDE | Threat | Severity | Disposition | Mitigation in this plan |
|----|--------|--------|----------|-------------|-------------------------|
| T-48-09 | Tampering | `push: true` / `load: true` / a `tags:` key creeps into a build step and CI publishes an image | high | mitigate | P7 asserts exactly two `push: false` and zero `load: true` / `tags:` / login / registry tokens across `.github/workflows/` |
| T-48-10 | Tampering | A registry surface (`docker/login-action`, `registry:`, `packages: write`) introduced to make the build work | high | mitigate | P8 scans the entire workflow directory; zero hits is the pass condition and an empty file list is a failure, not a pass |
| T-48-03 | Spoofing | A `paths:` filter added for "speed" leaves the required check `Pending` forever, or a job-level skip reports `Success` without running | high | mitigate | P8 asserts zero `paths:` / `paths-ignore:` in `ci.yml`; D-24 records that per-line skipping must use job-level `if:` — and this phase needs none. **ID note:** this ID is canonically the `paths:`-filter threat. The distinct eval-gate skipped-job false-green threat that was briefly also numbered `T-48-03` in plan 48-03 was renumbered to `T-48-15` |
| T-48-04 | Information Disclosure | A `secrets.*` reference enters `ci.yml`, making a public fork PR either leak or fail on a missing secret | high | mitigate | P8 asserts `ci.yml` references nothing but `secrets.GITHUB_TOKEN`; the workflow-level `permissions: contents: read` stays the ceiling for `fe` and `docker` (they declare no job-level permissions at all) |
| T-48-12 | Denial of Service | Untrusted fork PRs trigger two full CGO/Node image builds; the docker job's runtime budget is the only bound | medium | mitigate | `timeout-minutes: 45` on the docker job, `15` on `fe`; no self-hosted runner, no cache-poisoning surface (`type=gha` scoped per image); documented expectation (D-27/D-28) that only dependency layers cache |

No `high`-severity threat is left `accept`ed in this plan.
