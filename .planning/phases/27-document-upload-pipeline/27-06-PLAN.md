
**Stage 2: No-on-disk invariant**
```bash
echo "=== Stage 2: No-on-disk invariant ==="
# 2a: streaming multipart (parseUploadForm pattern, mirrors parseImportForm)
STREAMING_PATTERN=$(grep -rE "BodyStream|multipart\.NewReader" --include="*.go" internal/server/upload.go 2>/dev/null | wc -l)
if [ "$STREAMING_PATTERN" -eq 0 ]; then
    echo "FAIL: upload.go does not use BodyStream/multipart.NewReader"
    exit 1
fi
# 2b: no disk writes in the upload pipeline
DISK_WRITE=$(grep -rE "os\.WriteFile|os\.Create|ioutil\.WriteFile" --include="*.go" internal/server/upload.go 2>/dev/null | grep -v "_test.go" | wc -l)
if [ "$DISK_WRITE" -gt 0 ]; then
    echo "FAIL: upload.go contains disk write patterns"
    exit 1
fi
# 2c: magic-byte verifier present (Content-Type allowlist enforcement)
VERIFY_FUNC=$(grep -rE "^func VerifyMagicBytes" --include="*.go" internal/server/upload.go 2>/dev/null | wc -l)
if [ "$VERIFY_FUNC" -eq 0 ]; then
    echo "FAIL: VerifyMagicBytes function not declared in upload.go"
    exit 1
fi
# 2d: VerifyMagicBytes body contains no disk write paths (defense in depth)
VERIFY_DISK=$(grep -A 20 "^func VerifyMagicBytes" --include="*.go" internal/server/upload.go 2>/dev/null | grep -E "os\.WriteFile|os\.Create|ioutil\.WriteFile" | wc -l)
if [ "$VERIFY_DISK" -gt 0 ]; then
    echo "FAIL: VerifyMagicBytes body contains disk write patterns"
    exit 1
fi
echo "PASS: upload.go uses streaming multipart, no disk writes, VerifyMagicBytes present and pure in-memory"
```

**Stage 3: Trust invariant smoke**
```bash
echo "=== Stage 3: Trust invariant ==="

VALIDATE_BEFORE_EMBED=$(grep -n "validateTiers" internal/knowledge/upload_index.go 2>/dev/null)

if [ "$CITABLE_IN_UPLOAD" -gt 0 ]; then
    echo "FAIL: kb.Citable found in upload_index.go (should only be at query time)"
    exit 1
fi
echo "PASS: trust invariant preserved (validateTiers at insert, kb.Citable at query)"
```

27-06-T2b: Create STRIDE-27.md (threat model for Phase 27):

**Trust Boundaries:**
| Boundary | Description |
|----------|-------------|
| client → upload endpoint | Untrusted file bytes cross here |
| upload handler → parser | Parsed content crosses here |
| parser → embedder | Trusted content |
| embedder → IndexerBackend | Trusted vectors |
| IndexerBackend → Milvus/Mongo | Trusted vectors + metadata |

**STRIDE Threat Register:**

| Threat ID | Category | Component | Disposition | Mitigation |
|-----------|----------|-----------|-------------|------------|
| T-27-01 | Tampering | upload endpoint | mitigate | Admin token gate (isAdminRequest); Content-Length guard; magic byte verification |
| T-27-02 | Information Disclosure | upload bytes | mitigate | No disk write; bytes.Buffer in memory; SHA-256 hash in audit |
| T-27-03 | Denial of Service | upload endpoint | mitigate | SKILLFORGE_UPLOAD_MAX_BYTES (100 MB default); per-slug concurrency limit |
| T-27-04 | Tampering | audit row | mitigate | INSERT-only pattern (PutAudit); frozen args carry immutable upload metadata |
| T-27-05 | Repudiation | upload action | mitigate | Admin token + audit row with ActorType=admin |
| T-27-06 | Elevation of Privilege | deactivated KB upload | mitigate | validateTiers checks ActiveSlugs() — fail-closed before Insert |
| T-27-SC | Supply Chain | eino-ext parser packages | mitigate | CGO check at plan-phase; pure-Go fallback documented |

**Mitigation summary:**
- T-27-01: Admin token required; unknown format → 400
- T-27-02: bytes.Buffer only; SHA-256 for audit; no os.WriteFile
- T-27-03: Configurable max bytes + per-slug mutex
- T-27-04/05: INSERT-only audit row; ActorType=admin
- T-27-06: validateTiers fail-closed before any I/O

## Phase 27 LIVE Acceptance Runbook

Perform these steps in order. Mark each PASS/FAIL.

**Prerequisites:**
- Server running with SKILLFORGE_ADMIN_TOKEN set
- At least one active KB slug in the registry
- A test .md file with content "Test upload 2026-09"

**Steps:**

1. **Upload a .md file via curl (bypassing FE):**
```bash
curl -X POST http://localhost:8888/api/admin/kb/authority/upload \
  -H "X-Admin-Token: $SKILLFORGE_ADMIN_TOKEN" \
  -F "file=@test.md;type=text/markdown"
```
Expected: HTTP 200, JSON `{"chunks":1,"id_range":[N,N]}`

2. **Verify audit row:**
Query the audit table: `SELECT action, frozen_args FROM audit WHERE action='action_doc_uploaded' ORDER BY id DESC LIMIT 1;`
Expected: action_doc_uploaded row with slug="authority", chunk_count=1

3. **Try upload without token:**
```bash
curl -X POST http://localhost:8888/api/admin/kb/authority/upload \
  -F "file=@test.md;type=text/markdown"
```
Expected: HTTP 403

4. **Try upload to deactivated slug:**
First deactivate a KB via POST /api/admin/kb/:slug/deactivate, then try to upload to it.
Expected: HTTP 404

5. **Try magic byte mismatch:**
Send a .md file but with Content-Type: application/pdf
Expected: HTTP 400 "content type does not match file signature"

6. **Upload via FE:**
Navigate to /admin → scroll to DocUpload panel → select KB → choose test.md → submit
Expected: green toast "1 个片段已入库"

7. **Verify chunks are searchable:**
Send a chat query that should match the uploaded document's content.
Expected: Citation appears from the uploaded document.

## Pitfalls to Avoid

**Stage 2 must catch disk writes.** The no-on-disk invariant is a hard requirement. The grep for `os.WriteFile|os.Create|ioutil.WriteFile` in upload.go (not _test.go) must be comprehensive.

**Stage 3 must verify kb.Citable is NOT called at insert time.** The trust floor lives at query time (retrieval/grounding), not insert time. Uploaded chunks go through the same kb.Citable gate at query time as boot-seed chunks. If the upload pipeline calls kb.Citable at insert time, it is redundant and could introduce a different code path.
</pitfalls>
