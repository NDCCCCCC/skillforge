UploadIndex signature:
```go
func UploadIndex(
    ctx context.Context,
    slug string,              // target knowledge base slug (from URL param)
    fileBytes []byte,          // full uploaded file content (in-memory, no disk)
    mimeType string,           // Content-Type (verified by handler via magic bytes)
    filename string,           // original filename (for Source field)
    emb embedder.Embedder,     // for vectorizing chunks
    reg kb.Registry,           // for validateTiers + ActiveSlugs
    uploadAuditHook func(action, detail string), // nil = no audit
) ([]retriever.Document, error)
```

Steps inside UploadIndex:
1. **Slug validation** — Call `validateSlug(slug, reg)`. If slug not in reg.ActiveSlugs() → return error. This is the fail-closed gate.
2. **Parse** — Call `parser.Parse(ctx, mimeType, bytes.NewReader(fileBytes), filename)`. If error → return wrapped error "parse failed: {err}".
3. **Frontmatter + body** — If ParseResult.Frontmatter != nil, call `splitFrontmatter(ParseResult.Content + "---\n" + ParseResult.Frontmatter)` to get the body without frontmatter. Otherwise use Content as body directly.
4. **Chunk** — If len(body) > maxDocBytes (4000), split using the recursive splitter. Each chunk ≤ 4000 chars with 200-char overlap. For ≤ maxDocBytes, one chunk.
5. **Effective window** — Call `parseEffectiveWindow(ParseResult.Frontmatter)`. Default (0, 0) if no frontmatter.
6. **validateTiers** — Call `validateTiers(docs, reg)` BEFORE embedder. If error → return it (fail-closed per KNOW-02).
7. **Embed** — For each chunk, call `emb.Embed(ctx, string(chunk))`. If embed fails → return error "embed failed: {err}". Never fall back to zero vector.
8. **nextID coordination** — Call `getUploadNextID(ctx, reg, slug)` to get the starting ID. Each doc gets the next ID sequentially.
9. **Return docs** — Return the []retriever.Document to the caller. Do NOT call Insert here — caller (upload handler) does the Insert and then fires the audit hook.

validateSlug helper:
```go
func validateSlug(slug string, reg kb.Registry) error {
    if slug == "" { return errors.New("slug is empty") }
    if _, ok := reg.Lookup(slug); !ok { return fmt.Errorf("kb %q is not registered", slug) }
    active := reg.ActiveSlugs()
    for _, s := range active { if s == slug { return nil } }
    return fmt.Errorf("kb %q is deactivated", slug) // fail-closed
}
```

uploadAuditHook signature (matches indexer.go indexAuditHook pattern):
```go
var uploadAuditHook func(action, detail string)
func SetUploadAuditHook(fn func(action, detail string)) { uploadAuditHook = fn }
```

The audit hook is set at boot in cmd/server/main.go, mirroring SetIndexAuditHook.

27-02-T2: Implement getUploadNextID in internal/knowledge/upload_index.go AND add GetMaxID to the retriever.Retriever interface.

The uploader needs to know the current max ID in the backend to avoid collisions with existing chunks. The indexer.go starts at 1 on a fresh collection — the upload path must not collide with boot-time IDs.

```go
// getUploadNextID queries the backend for the current max chunk ID for slug,
// then returns max+1 (or 1 if no chunks exist).
// The returned range [start, start+chunkCount-1] is recorded in the audit row.
func getUploadNextID(ctx context.Context, slug string, r retriever.Retriever) (int64, error) {
    maxID, err := r.GetMaxID(ctx, slug)
    if err != nil { return 0, fmt.Errorf("get max id for slug %q: %w", slug, err) }
    return maxID + 1, nil
}
```

Steps:
1. **Add GetMaxID to the retriever interface** in `internal/retriever/retriever.go`:
   ```go
   type Retriever interface {
       // ...existing methods...
       // GetMaxID returns the highest chunk ID currently stored for the given
       // tier (slug). Returns 0 (no error) when no chunks exist for the slug.
       // Implemented by MilvusClient and MongoClient (Plan 27-04).
       GetMaxID(ctx context.Context, tier string) (int64, error)
   }
   ```
2. **Stub the method** on any internal test doubles in the same commit so the
   build stays green (no backend impl in this plan — that's 27-04). Mock
   retriever used in 27-02-T3 tests returns a configurable max (default 0).
3. Plan 27-04 owns the real backend implementations on `*MilvusClient` and
   `*MongoClient` (the file `internal/retriever/milvus/client.go` is added
   to 27-04's files_modified).

**Important**: The indexer's boot-time Index() assigns IDs 1..N in walk order. The upload path uses GetMaxID to find the current ceiling. On a fresh collection with only boot-seed chunks, GetMaxID may return 0 (no rows) → start at 1. If 47 boot-seed chunks exist, GetMaxID returns 47 → upload starts at 48.

The nextID is NOT stored in the audit row directly — the audit row carries `id_range_start` and `id_range_end` so re-seed can recompute MAX from audit.

<pitfalls>
## Pitfalls to Avoid

**Do NOT call Insert inside UploadIndex.** UploadIndex returns []retriever.Document. The caller (upload handler, Plan 27-03) decides when to Insert and handles backend errors. This keeps UploadIndex testable without a real Milvus/Mongo.

**Do NOT start nextID at 1.** If boot has already indexed 47 chunks, and the uploader starts at 1, IDs collide. getUploadNextID must query the backend first.

**validateTiers MUST run before the embedder.** This is the KNOW-02 fail-closed gate. If validateTiers fails, no embedder call and no docs returned.

**Never fall back to a zero vector on embed failure.** The embedder is the production BGE-M3. A zero-vector fallback would silently corrupt the vector space.
</pitfalls>
