The narrow interface that the upload pipeline uses. Only Insert — no query, no search, no metadata.

```go
package retriever

import (
    "context"
)

// IndexerBackend is the narrow insert-only interface for the document upload pipeline.
// It is deliberately minimal: only Insert is needed to append new chunks.
// The query/search path goes through retriever.Retriever (a separate interface).
//
// Both Milvus and MongoDB retriever implementations satisfy this interface.
type IndexerBackend interface {
    // Insert appends docs to the backend store. The docs are already
    // validated (tier check, effective window check, embedding computed).
    // Errors are returned verbatim — the caller decides retry/log/abort.
    Insert(ctx context.Context, docs []Document) error
}

// IndexerBackendNotWiredError is the 503 body when Deps.IndexerBackend is nil.
const IndexerBackendNotWiredError = "indexer backend not wired (server started without a retriever backend)"
```

This is intentionally minimal. The interface lives in the retriever package (same package as Retriever) to keep Document type visibility clean.

    "context"
    "github.com/skillforge/skillforge/internal/retriever"

// MilvusIndexerBackend satisfies retriever.IndexerBackend.
type MilvusIndexerBackend struct {
    mc *MilvusClient
}

// Compile-time assertion.
var _ retriever.IndexerBackend = (*MilvusIndexerBackend)(nil)

// NewIndexerBackend wraps an existing MilvusClient as an IndexerBackend.
func NewIndexerBackend(mc *MilvusClient) *MilvusIndexerBackend {
    return &MilvusIndexerBackend{mc: mc}
}

// Insert delegates to MilvusClient.Insert.
func (b *MilvusIndexerBackend) Insert(ctx context.Context, docs []retriever.Document) error {
    return b.mc.Insert(ctx, docs)
}

<pitfalls>
## Pitfalls to Avoid

**IndexerBackend is narrow.** Only Insert. Do not add GetMaxID here — that lives on the retriever.Retriever interface. The upload pipeline's getUploadNextID calls the Retriever, not the IndexerBackend.

**Both backends must implement the same interface.** The upload handler is backend-agnostic. If the switch in main.go chooses Milvus, the upload pipeline uses MilvusIndexerBackend. If Mongo, the upload pipeline uses MongoIndexerBackend. The handler does not know which.

**IndexerBackend is NOT the Retriever.** Retriever has Search, Retrieve, GetChunk. IndexerBackend only has Insert. Do not conflate them.
</pitfalls>
