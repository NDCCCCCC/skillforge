Implement `QueryScoped(pattern string, allowedTiers []string) []Triple` in store.go, per D-TIER-01/03/06:

**Schema layer exemption** (D-TIER-03):
Schema layer = TBox declarations (owl:Class, owl:ObjectProperty, owl:DatatypeProperty, rdf:type declarations) + Skill/KBCategory/SubCategory/Tier/SkillAgent/RefusalPhrase/NoteChunk/TableSchema class individuals. These are identified by their predicate:
- `rdf:type` + O in {owl:Class, owl:ObjectProperty, owl:DatatypeProperty} → always visible
- O starts with ns + class names (Tier, KBCategory, SubCategory, Skill, SkillAgent, RefusalPhrase, NoteChunk, TableSchema) → always visible
- Predicates that are ontology metadata (rdfs:label, rdfs:comment, rdfs:domain, rdfs:range) → always visible

**Tier filtering algorithm** (D-TIER-06 entity-level):
1. Run the base Query with the pattern (same as Query)
2. Partition results into schema-layer (always pass) and ABox-data (need filtering)
3. For ABox-data triples: check if the SUBJECT entity has a `belongsToTier` triple where O is in allowedTiers
4. If the subject has no belongsToTier triple → fail-closed, exclude
5. If the subject has belongsToTier and at least one tier is in allowedTiers → include all triples for that subject
6. Collect all included subject entities and their edges (forward and reverse via Adjacent1/Adjacent1Reverse)

**AllowedTiers mapping** (D-TIER-05):
- passed in as `[]string` (tier names like ["sql-guides", "权威"])
- Empty/nil allowedTiers = no filtering (admin baseline = all visible)
- The allowedTiers list comes from SKILL.md reads field (parsed externally, passed in)

**Implementation**:
```go
// QueryScoped returns triples matching the pattern, filtered by tier.
// Schema-layer triples (TBox declarations, Skill/KBCategory/etc individuals)
// are never filtered. ABox data entities (note/tbl) are filtered to
// allowedTiers. An entity with no belongsToTier triple is invisible (fail-closed).
// Entity-level filtering: if a subject is visible, ALL its triples are included
// (both forward and reverse edges, D-TIER-06).
func (s *Store) QueryScoped(patternS, patternP, patternO string, allowedTiers []string) []Triple {
    // Handle empty tiers = no filter
    if len(allowedTiers) == 0 {
        return s.Query(patternS, patternP, patternO)
    }

    // Schema layer: never filter
    schemaTriples := s.querySchemaLayer(patternS, patternP, patternO)
    dataTriples := s.Query(patternS, patternP, patternO)

    // Collect visible ABox subjects
    visibleSubjects := s.visibleABoxSubjects(allowedTiers)

    // Filter data triples to visible subjects
    var filtered []Triple
    for _, t := range dataTriples {
        if isSchemaTriple(t) {
            continue // already in schemaTriples
        }
        if visibleSubjects[t.S] {
            filtered = append(filtered, t)
        }
    }

    // Add all edges for visible subjects (both directions)
    // ... collect Adjacent1 and Adjacent1Reverse for visible subjects ...
    return append(schemaTriples, filtered...)
}
```

**isSchemaTriple helper**:
A triple is schema-layer if:
- P == rdf:type AND O in {owl:Class, owl:ObjectProperty, owl:DatatypeProperty}
- OR O starts with NS + known schema class name (Tier, KBCategory, SubCategory, Skill, SkillAgent, RefusalPhrase, NoteChunk, TableSchema)
- OR P in {rdfs:label, rdfs:comment, rdfs:domain, rdfs:range, rdfs:subClassOf}

**visibleABoxSubjects**:
1. Query all triples with predicate = ns+"belongsToTier"
2. Collect subjects where O in allowedTiers
3. Return as map[string]bool for O(1) lookup

**Adjacency inclusion** (D-TIER-06):
Once visible subjects are identified, also include:
- All triples where S is a visible subject
- All triples where O is a visible subject (reverse edges — e.g., Skill hasReadAccess KBCategory)

This ensures the subgraph for visible entities is complete.
