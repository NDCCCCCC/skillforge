# Phase 39 — UI Design Contract

> Visual and interaction contract for Phase 39 `/admin/pipeline` — ECL Pipeline 实时状态（运行触发 / 进度 / 失败重试 + 死信列表）. This is a **consistency-locking** phase per the USER DIRECTIVE: the existing admin console design language is LOCKED; this phase extends it with one new tab (the 9th). Every token, class idiom, and pattern below is inherited from the implemented console (`web/src/components/admin/`), not redesigned. Generated by gsd-ui-researcher.

  stage: string;            // opaque BE string; see §Stage Mapping
  current_file: string;
  done: number;
  total: number;
  queue_len: number;
  failures: PipelineFailure[];

### 4. Polling hook (inside PipelineTab or `use-pipeline-status.ts` — planner's call)

- Pattern: `useEvalReports` — `fetchOnce` wrapped in `useCallback`, `window.setInterval` re-armed on cadence change, accepts an injected `fetchImpl`/interval for vitest (`vi.useFakeTimers`).
- Cadence (D-Prog-01, LOCKED): **2000ms while a run is active** (`stage ∉ {idle, done}`), **10000ms otherwise** (idle / done / error / 503 / 403). When a poll flips the running state, re-arm the interval so the new cadence applies immediately.
- No `document.visibilitychange` handling this phase (matches existing polling precedent; admin console is a manual monitoring surface).
- Run / retry POSTs do NOT go through the poller; on success they trigger an immediate `fetchOnce` (server truth, KnowledgeBaseList `loadBases` pattern).

### 5. Stage Mapping (FE display contract)

`stage` is an opaque BE string. FE maps via lookup; **unknown values render the raw string** (never blank, never a crash):

| BE stage | zh label | Badge treatment |
|----------|----------|-----------------|
| `idle` | 空闲 | neutral |
| `merge` | 切分合并 | amber + pulse |
| `extract` | 实体抽取 | amber + pulse |
| `kg-load` | KG 写入 | amber + pulse |
| `milvus-load` | Milvus 索引 | amber + pulse |
| `done` | 已完成 | green |

Sentinel names `idle` / `done` are part of the FE contract — the planner must keep them (or update the FE map in the same plan). `isRunning = stage !== 'idle' && stage !== 'done'` drives poll cadence, Run button state, and the pulse badge.

## Interaction Behaviors

### Run lifecycle

1. Click 「运行 ECL」 → `window.confirm('运行 ECL 管线？将重建 sql-guides 的切块、实体抽取与索引（幂等操作，可重复执行）。')` — KnowledgeBaseList deactivate precedent (mutating POST + cost-bearing: LLM calls + Milvus re-embed). Cancel = no-op.
2. Confirmed → POST `/api/admin/pipeline/run` with token header. Button enters 「运行中…」 only when the **server-confirmed** status flips to a running stage — no optimistic running state.
   - 202/200 → info toast 「ECL 管线已启动」; poller re-arms to 2s.
   - 409 (already running) → error toast 「管线正在运行中，请等待完成」; next poll re-syncs the button.
   - 403 / 503 / network → error toast with real reason (§Copywriting); button returns to its prior state. No auto-retry.
3. While running: progress bar + 当前文件 + queue_len update from polls only (server truth — never optimistic increments). The Run button stays disabled; **no cancel control exists this phase** (cancel API explicitly deferred in 39-CONTEXT §deferred — rendering one would be a fake capability).
4. On `stage === 'done'`: badge turns green, poller drops to 10s, button re-enables.

### Retry lifecycle (per dead note)

1. Click 重试 on a `dead` row → POST `/api/admin/pipeline/retry/:note_id`. Single click, **no confirm** (bounded single-note action; matches Phase 29 disposition precedent).
2. Success → success toast 「已重新入队 note {note_id}」 + immediate status re-fetch. The row's subsequent `pending → resolved/dead` transitions arrive via polling (server truth).
3. Failure → error toast 「重试失败：{真实原因}」; row unchanged, button re-enabled.
4. No batch-retry control: the only retry endpoint is per-note (D-Route-01); a 「全部重试」 button would 404 — forbidden as a fake capability.

### Polling

Per §Component 4. Errors during polling do not stop the loop; the inline error line renders only when a fetch fails, and clears on the next successful poll.

## Honesty & Trust-Semantics Rules (console red lines)

1. **No fake cancel.** No cancel button while a run is in flight (cancel API deferred by 39-CONTEXT §deferred). The Run button disabled state is the ONLY run-control feedback.
2. **Server truth only.** Progress, stage, queue_len, and failure states derive exclusively from poll responses; no optimistic counters, no assumed completion.
3. **dead ≠ deleted.** Dead-letter copy says 死信（可手动重试）; forbidden strings: 「已删除」「已丢弃」「已永久失败」. `resolved` says 已恢复, never 「已修复知识库」.
4. **Errors verbatim.** Server `error` bodies render as-is after the zh-CN prefix (启动失败：/ 重试失败：); network failures render 网络错误, never a fabricated status.
5. **No fake capabilities.** No batch-retry button, no per-stage manual skip, no schedule/auto-run toggle (boot auto-run is intentionally absent per D-Run-01 — the hint line states this).
6. **Idempotency stated, not oversold.** The hint line says 按 note 级替换，结果幂等 — it never claims 零风险 or 即时完成.
