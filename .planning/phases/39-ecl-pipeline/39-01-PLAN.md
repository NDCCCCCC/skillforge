Implement two exported primitives on *Store (per D-Boot-01 "或等价删除原语" — planner pins subject-scoped deletion because both note-level replace and orphaned-TableSchema cleanup need exactly this shape):

1. `func (s *Store) DeleteSubject(subject string) int` — removes ALL triples whose S equals subject, returns count removed. Implementation constraint: positions in byS/byP/byO point into s.all, so partial compaction corrupts the other two indices. Correct approach: filter s.all preserving order, then REBUILD byS/byP/byO from scratch in the same pass. Take s.mu.Lock. O(n) rebuild is fine at KG scale (<10k triples).

2. `func (s *Store) InsertUnique(t Triple) bool` — returns true and inserts only if no identical triple exists (use s.Query(t.S, t.P, t.O) wildcard lookup then exact S/P/O comparison, all under one lock acquisition to avoid TOCTOU; if Query's RLock makes that awkward, inline the candidate scan under the write lock). Returns false without mutating when the triple already exists. This is the dedupe guard for the boot TBox→KG merge (RESEARCH Pitfall 3: LoadSnapshot then re-loading TBox must not double-count).

Both get doc comments in the file's established voice (Insert's "caller deduplicates if needed" comment should be updated to point at InsertUnique). No signature changes to existing methods.
  </action>
