    **A. 新建 `internal/retriever/embedded/rank.go`（包内行类型 + 纯函数排序）**

    文件头沿用仓库 SPDX 头（`// Copyright 2026 SkillForge Authors`、Apache-2.0 正文、`// SPDX-License-Identifier: Apache-2.0`）。声明 `type row struct`，字段与 `retriever.Document` 的检索面一一对应：`ID int64`、`Tier string`、`Content string`、`Source string`、`Embedding []float32`、`EffectiveFrom int64`、`EffectiveTo int64`。不要加 bson tag（那是 mongo 的存储层细节；embedded 不序列化 row）。

    **B. 新建 `internal/retriever/embedded/cache.go`**

    `func cacheKey(model string, dim int, corpusHash, endpointHash string) string`：sha256 覆盖 `"v1\x00<model>\x00<dim>\x00<corpusHash>\x00<endpointHash>"`，返回 hex。`endpointHash` 是 `BGE_M3_URL` 的 sha256（调用方算好传入），**原始 URL 绝不进 key、绝不进文件名、绝不进缓存载荷**（Pitfall 9：URL 可能带 token）。空 model / 空 corpusHash / 空 endpointHash 各自拼进去，不 panic（空值仍产生确定性 key）。

    `func corpusHash(entries []knowledge.DocEntry, read func(rel string) ([]byte, error)) (string, error)`：按 `WalkDocs` 已排好的路径顺序（该函数保证按 slash 相对路径排序），对每个 entry 写入「相对路径 + `\x00` + 字节长度（十进制）+ `\x00` + 文件字节」；`read` 返回错误即 wrapped 返回。**不得使用 `entry.Bytes`（磁盘文件大小）之外的时间元数据、不得使用 mtime、不得使用文件计数**——`DocEntry.Bytes` 只作为长度前缀的交叉校验，真正进 hash 的是实际读到的字节（Pitfall 8：git clone / checkout 会重写 mtime）。

    `func readCache(path string, model string, dim int) ([]row, error)`：打开文件，逐项校验头部：magic `SFVC`（4 字节）、version uint32 == 1、modelLen uint16 + model 字节（必须等于 `model` 参数）、dim uint32（必须等于 `dim` 参数）、docCount uint32、payloadHash [32]byte。**任一不符 → 返回 `errCacheInvalid`（包内哨兵）并附具体原因串**（例如 `embedded: cache invalid: magic mismatch`），调用方据此重建，**绝不部分可用**。逐条读 `(id int64 | tier 长度前缀串 | source 长度前缀串 | effectiveFrom int64 | effectiveTo int64 | dim × float32 LE)`，读完后重算全部向量字节的 sha256 并与 `payloadHash` 比对，不符同样整份作废。文件不存在时返回原始 `os` 错误（调用方用 `os.IsNotExist` 区分「未命中」与「损坏」）。

    `func writeCache(path string, model string, dim int, rows []row) error`：先写 `path + ".tmp"`（`os.O_CREATE|os.O_WRONLY|os.O_TRUNC`，`0o600`），写完 `f.Sync()` 后 `os.Rename` 到正式路径（tmp+rename 保证不会产生半截文件被后续进程当成有效缓存）。头部 layout 与 `readCache` 严格互逆。

    `func acquireCacheLock(lockPath string, wait time.Duration, logf func(string, ...any)) (release func() error, err error)`：`os.OpenFile(lockPath, os.O_CREATE|os.O_EXCL|os.O_WRONLY, 0o600)`；成功则返回一个删除 lock 文件的 release 闭包；`os.IsExist(err)` 时以 200ms 间隔轮询（`time.NewTicker`）直到 `wait` 超时；超时返回带 `embedded: timed out waiting for the vector cache after %s; another process holds %s` 的错误，并说明「不会降级为假向量」。**循环必须有 deadline，不得无界 sleep。**

    **C. 把 Task 1 的 `Ensure` 换成缓存感知实现（保持幂等、不阻塞、不持锁）**

    关键约束：**`Ensure` 必须先于 `SeedFromKnowledgeDir` 调用（装配顺序见 Task 1 的 D 节），因此 `Ensure` 不能依赖「seed 已装载」才能算出缓存 key。** 语料 hash 只依赖语料字节、不依赖向量，所以 `Ensure` 自己算：

    1. `CacheDir == ""` → 只做内存侧准备并返回 nil（缓存可禁用，但禁用不等于假向量）。
    2. `c.corpusHash, err = corpusHash(entries, readFile)`——entries 来自 `knowledge.WalkRegisteredDirs(c.cfg.KnowledgeDir, reg, seedAuditHook)` + 逐 slug `WalkDocs`，`readFile` 是 `os.ReadFile`。**这一步零网络**（不调 `Embed`），因此可以在 seed 之前完成。`c.cfg.KnowledgeDir` 与 `c.cfg.Registry` 因此必须是 `Config` 字段（见下）；`WalkRegisteredDirs` 失败即返回错误。
    3. `c.endpointHash = sha256hex(c.cfg.EndpointURL)`；`c.cachePath = filepath.Join(c.cfg.CacheDir, "vectors.bin")`；`key := cacheKey(c.cfg.Model, c.cfg.Dimensions, c.corpusHash, c.endpointHash)`。
    4. `rows, err := readCache(c.cachePath, c.cfg.Model, c.cfg.Dimensions)`：
       - `err == nil` → 写锁装入 `docs` / `byID`，返回 nil（缓存命中，装配侧随后的 seed 会短路）；
       - `errors.Is(err, errCacheInvalid)` 或 `os.IsNotExist(err)` → **返回 nil**，但 `docs` 保持为空（未命中由 seed 负责装载与写缓存）；
       - 其他错误（权限、IO）→ 返回 wrapped 错误（不静默当作未命中）。
    5. **`Ensure` 不抢锁、不轮询、不写缓存**——锁与写缓存全部归 `SeedFromKnowledgeDir`（下一节）。这样 `Ensure` 无阻塞，重复调用幂等，且不会与 seed 的锁路径互相等待。

    `Config` 因此增加三个字段：`KnowledgeDir string`、`Registry kb.Registry`、`CacheWaitTimeout time.Duration`（零值 → 5 分钟）。`Client` 的私有字段相应增加 `corpusHash string`、`endpointHash string`、`cachePath string`、`cacheKey string`。

    **C2. `SeedFromKnowledgeDir` 的缓存集成（锁 + 写缓存 + 并发短路）**

    在 Task 2 的 A 节流程之上追加四条：
    1. **幂等短路（第一条语句）**：若 `len(c.docs) > 0`（`Ensure` 已从缓存装入）→ 直接 `return len(c.docs), nil`，不做任何网络调用。
    2. 若 `c.cachePath != ""`：`release, err := acquireCacheLock(c.cachePath+".lock", c.cfg.CacheWaitTimeout, c.cfg.Logf)`；`err != nil` 时——在返回前先尝试一次 `readCache`（可能是持锁进程刚刚写完）：成功则装入并 `return len(c.docs), nil`，失败则返回该超时错误（**不降级为假向量、不返回部分语料**）。抢到锁后 `defer release()`。
    3. 装载 + `validateDocs` 全部成功后，写锁提交 `docs` / `byID`，然后若 `c.cachePath != ""` 调 `writeCache(c.cachePath, c.cfg.Model, c.cfg.Dimensions, c.docs)`；写缓存失败 → 返回 wrapped 错误（缓存写不成是配置/权限问题，必须暴露，但 `docs` 已可用，错误串须说明「vectors are loaded in memory; only the on-disk cache failed」）。
    4. 持锁期间装载失败 → `defer release()` 删除锁文件，让下一个进程可以重试（不留死锁）。
