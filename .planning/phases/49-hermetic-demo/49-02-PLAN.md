<objective>
让 SkillForge 在完全没有 LLM API key 的情况下仍能跑完整条问答链，并让 stub 模式在三处被如实标注、绝不静默伪装成真模型。

本 plan 交付五件事：

1. **新增 `internal/server/stubchat/` 包**：实现 `model.BaseChatModel`（`Stream` + `Generate`），从 pipeline 已渲染进 user message 的 `[ref-N] tier=… source=…` 证据块里做**确定性抽取**，产出与真模型**字节形状一致**的 `verdict.Verdict` JSON（D-07）。
2. **插在 `Deps.PipelineChatModel` 上**：`internal/server/pipeline.go` 已有 `if s.PipelineChatModel != nil` 分支，stub 实现该接口后，pipeline 的 parse → `verdict.Validate` → `verdict.GroundingCheck` → `GroundingChecker` 降级链**全部原样跑过**，`pipeline.go` **零改动**（本 plan 的核心约束）。
3. **`verdict.Verdict` 新增 `Mode` 字段**（JSON tag `mode,omitempty`），只有 stub 写 `"stub"`，真模型不写 —— 保持 wire 向后兼容（D-08①）。
4. **启动装配**：`cmd/server/main.go` 把 `GLM_API_KEY` 从必填改为可选（`BGE_M3_URL` 保留必填，D-01/D-11），无 key 时自动挂 stub 并打印醒目 WARN（D-08②），有 key 走真模型；同时把 stub 模式下的 `Rewriter` / `RefusalClassifier` 置 nil —— 否则 stub 的 verdict JSON 会被 refusal classifier 误解析成分类输出 → 重试耗尽 → default-deny → **全量拒答**。
5. **README 写明**（D-08③）+ **前端类型扩展**：`web/src/types/verdict.ts` 加可选 `mode` 字段与 `isStubVerdict` 谓词，`isVerdict` 守卫保持不变（它只判 `status`，加 `mode` 不破坏它）。
