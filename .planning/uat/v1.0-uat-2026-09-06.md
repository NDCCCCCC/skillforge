## 二、缺陷清单（根因到行）

### B1（P1）/eval/audit 白屏 — 线形状不匹配 — **已修复（commit d2aa97c）**
- **现象:** `/eval/audit` 整页空白；console: `Uncaught TypeError: Cannot read properties of undefined (reading 'startsWith')` in `<AuditTable>`；React 提示无 error boundary。
- **根因:** `GET /api/audit` 返回 PascalCase Go 序列化（`ID/Timestamp/Query/VerdictJSON/...`），FE 的 AuditRow mapper 读的是另一套 key → 行字段 undefined → `AuditTable.tsx:39 isRedacted(value)` 对 undefined 调 `.startsWith('[REDACTED:')` 抛错。
- **回归来源:** 疑似 Phase 19/20 动 audit handler 序列化后未跑 FE transport 合同（Phase 6a 验收时该页是好的）。
- **修复方向:** BE 补 wire tags（对齐 FE 期望的 snake_case）或 FE mapper 兼容两种 casing；`isRedacted` 加 `typeof value === 'string'` 防御；给 /eval 子路由加 error boundary。

### B2（P1）Skill 切换被回弹 — useSkillAutoSwitch 依赖污染 — **已修复（commit 8208d30）**
- **现象:** 任何有历史恢复的会话中，用户在 SkillPicker 选另一 Skill：handleSelect 执行（菜单关闭）后 currentSkillId 立即回弹到会话绑定 skill。
- **根因:** `web/src/hooks/use-skill-auto-switch.ts:50` 依赖数组 `[skillId, skills, currentSkillId, setCurrentSkill]`——用户手动切换使 currentSkillId 改变 → effect 重跑 → `currentSkillId !== skillId（会话绑定值）` → `setCurrentSkill(skillId)` 强制改回。hook 无法区分"恢复期自动切换"与"用户显式覆盖"。
- **修复方向:** ref 记录已应用过的 skillId，只在 `skillId`（历史恢复载荷）变化时应用一次；依赖数组去掉 currentSkillId。

### B3（P2）会话 id 命名空间冲突 — duplicate key ×46 — **已修复（commit a615407）**
- **现象:** roster 中 session-2 渲染两行（server 行 + 本地行），React key 冲突警告 46 次；行属性错配导致重命名/删除的点击目标不可靠（本次 UAT 中一次误 PATCH 把 session-2 标题改成"会话 2"，已修复还原）。
- **根因:** `createSession()` 本地 id 生成走 `session-N` 命名空间，与库中遗留 `session-2` 撞车。
- **修复方向:** 本地会话 id 加前缀（如 `local-<uuid>`）；roster 合并渲染处按 id 去重。
